# Fallow analysis engine versus implemented OpenSIP design

## What Fallow concretely does better

### Takeaway
Fallow has a broader, more specialized JS/TS application-analysis catalogue. The strongest selected-design difference is framework recognition: OpenSIP selects nine recognizers, while Fallow ships many additional application, test, bundler and tooling plugins. Core clone and graph principles already overlap; they should not be sold as missing OpenSIP architecture.

### Inferences
- Framework recognition breadth is a real selected-product gap even under the assumption that OpenSIP is fully implemented: nine fully implemented recognizers do not equal Fallow's application coverage. Prioritize additional recognizers using repositories we actually target, with declaration provenance and negative fixtures.
- Specialized predicate/workflow gaps worth considering are frontend maintainability/style diagnostics, advisory public-signature coupling/API leakage, and security source/sink candidate workflows. The architecture can accommodate future fact/predicate families; that is different from currently selecting these features.
- Ordinary symbol trace/graph impact is NOT a safe blanket gap claim. OpenSIP already contracts graph neighbors/path/reach queries; review briefs can expose affected consumers. Its chapter 13 explicitly anticipates bounded impact-selected test recommendations. The specialization gap is a concrete ready-made answer such as type-signature coupling or test suggestion rollups, if no selected owning contract supplies it.

### Gaps
- Search of current product-v1 and architecture contracts found no explicit selected CSS style-drift, template-complexity, taint/sink-candidate or public-signature type-coupling predicates. Treat this as a scoped contract search, not proof that every historical pack/artifact lacks relevant syntax predicates.
- No executed comparison establishes performance, true-positive superiority, or corpus-wide recall. README speed claim is an old Fallow 2.100.0 measurement and cannot support today's cross-product speed claim.

## Where OpenSIP's completed design is stronger

### Takeaway
OpenSIP has stronger evidence semantics and broader language-native scope. It requires declared compiler/input provenance, exact retained identities and explicit uncertainty, where Fallow chooses pragmatic syntactic defaults and a semantic best-effort gate fallback.

### Cited Findings
- OpenSIP supports TypeScript, JavaScript and Rust native cells, plus syntax-only modes; checked types and resolved imports/references/calls are distinct predicate-specific rungs. Rust proc macros/build scripts have disclosed limits or admitted inert prepared inputs. — [Capability table](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:584)
- OpenSIP separates exhaustive examination from actual edge resolution, and records dynamic forms as unresolved edges rather than interpreting absence as a resolved negative. Unknown origins mean incomplete reachability. — [Completeness law](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:1876), [Limitations](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:605)
- OpenSIP evaluates exists/none/count against admitted complete populations; absent required evidence yields indeterminate, and strong Kleene Boolean logic preserves unknown. It retains the entire deterministic predicate tree and admitted evidence references. — [Evaluator law](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/identity-and-evidence.md:1526)
- Fallow's default analyzer is syntactic; optional semantic refinement primarily asks exact-symbol questions for exports already considered unused by its normal module graph. Retained-unresolved and retained-abstained outcomes keep the syntactic finding. Its default semantic requirement is best-effort; complete can be requested. — [Type-aware contract](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/docs/type-aware-analysis.md)
- When base/head semantic identities cannot compare, Fallow audit falls back to pre-refinement syntactic keys, warns, and demotes semantic-only introductions so they cannot fail the new-only gate. This is explicitly implemented, not merely prose. — [Audit ledger source](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/api/src/audit_keys.rs#L92-L108), [Type-aware audit contract](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/docs/type-aware-analysis.md)
- OpenSIP's incorporated Fallow rules prohibit syntactic substitution for missing required semantic evidence and exclude model/external judgment from Control. Static/runtime/test/history facts are not globally ranked or averaged into confidence. — [Architecture boundary](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/architecture/13-evidence-workflows-and-product-contracts.md:16), [Non-borrows](/Users/sb/code/opensip-ai/opensip_arch/docs/coop/FALLOW-BORROW-REGISTER.md:114)
- OpenSIP imports require exact snapshot correspondence or admitted per-file VCS mappings with matching source digests; a commit/build name alone cannot admit evidence to predicates. — [Source correspondence](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:2713)
- OpenSIP already specifies exact/normalized/structural clone facts, near candidates and TS/JS-erasure cross-language candidates; no mode proves behavioral equivalence. It includes Rust and nested closure/block/impl bodies. — [Clone modes](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:2562)

### Inferences
- OpenSIP offers a stronger basis for enforcing architectural and policy constraints when evidence is incomplete or modes change. The key advantage is honest indeterminate policy behavior and exact source/provenance binding, not a claim that its analyses find more bugs.
- Rust is an important substantive scope advantage; Fallow focuses its semantic engine on JS/TS application ecosystems.
- We should borrow Fallow's specialized user-facing questions and qualification corpora, while retaining OpenSIP's evidence/Control model.

### Gaps
- Fully implemented design does not prove qualified runtime performance or successful independent conformance. Keep user assumption separate from measured evidence.

## Fallow limitations and measurement nuance

### Takeaway
Fallow is candid about the distinction between candidates and proof, and already has meaningful correctness machinery. It should not be dismissed as merely regex or depicted as unsafely auto-fixing every syntactic candidate.

### Cited Findings
- Type-aware fix reruns analysis and guards declarations by hashes, requires complete negative semantic decisions, and withholds class-member removals with reachability caveats. It abstains on decorators/dynamic imports/computed members and incomplete projects. — [Safety contract](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/docs/type-aware-analysis.md#fail-closed-behavior)
- Svelte virtual-module named exports can make a semantic project unavailable; framework-aware virtual file integration remains deferred. LSP is one root, Programs are per process/session with no disk Program cache; checker requests lack in-flight cancellation. — [Limitations](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/docs/type-aware-analysis.md#deferred-scope)
- Symbol-impact exact direct consumers are followed by a reverse-module closure whose resolver admits relative local paths and limited extensions. Nonliteral dynamic imports are recorded as a limitation. Test suggestion coverage should not be read as compiler-complete transitive behavioral impact. — [Impact source](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/tools/type-aware-sidecar/src/symbol-impact.mjs)
- Corpus summary reports 559 candidates, precision 1 on adjudicated confirmation, safe confirmation yield 30.95%, combined safe-resolution yield 37.57%, independently adjudicated truth coverage 37.92%, abstention 19.86%, and three repositories with confirmed value. It explicitly disclaims corpus-wide recall; indeterminate candidates are excluded from accuracy. — [Corpus summary](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/benchmarks/type-aware-corpus-summary.md)
- Clone implementation uses SA-IS suffix arrays for exact token clone discovery, MinHash/LSH with verified Jaccard for bounded near clones, explicit skip counts and complete-link similarity tests. This is real engineering maturity; OpenSIP's design is already comparable in near-clone principle but not these exact performance choices. — [Suffix array](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/engine/src/duplication_detector/detect/suffix_array.rs), [Near implementation](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/engine/src/duplication_detector/near.rs)
- Model-based similar-code runs through a verified local Candle/Jina companion with bounded I/O and source-digest/model provenance. It does not run in audit, SARIF, LSP, VS Code or auto-fix. Nested callbacks/constructors/accessors/computed methods are outside v1 with omissions reported. External verdict joins reject stale/duplicate identities; model similarity still proves no behavioral equivalence. — [Similar-code contract](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/docs/similar-code-analysis.md), [Verdict validation source](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/api/src/runtime/similar_code.rs)
- Boundary checks apply to every analyzed module, including unreachable modules, because unsupported task-runner origins may still execute them. — [Boundary source](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/core/src/analyze/boundary.rs)

### Inferences
- Useful borrow: transparent confirmation yield/abstention and concrete feature-bucket evidence, not headline 100% accuracy.
- Avoid suggesting OpenSIP needs near clones, offline models, explicit omission accounting, or generic graph queries from scratch; existing design already addresses the principles or intentionally separates authority.

### Gaps
- Old September Fallow commit is not in the shallow clone, so source diff failed. Do not date every feature as newly added since September without independent Git history evidence.
