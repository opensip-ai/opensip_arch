# Fallow developer workflows and operational safety

Source inspection at Fallow `1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c` (Oct 5 Pacific; main contains unreleased changes). No build, runtime correctness validation, or benchmark performed. Compare with fully implemented current consolidated OpenSIP product design, not preview delivery. The previous local borrow register pinned `23bb9a7` (Sep 5, 3.22.0), and already adopted broad evidence/review/policy/baseline ideas. Current design supersedes chapter 13 prose in relevant areas.

## What does Fallow do better or specify more concretely?

### Takeaway
Fallow has a more concrete editor feedback experience and actionable advisory maintenance prioritization. These are product-surface/heuristic specification gaps, not evidence-authority gaps in OpenSIP.

### Cited Findings
- **Editor feedback loop:** real LSP capabilities include quick fixes, code lenses, hovers, UTF-16 positions and conditional pull diagnostics. Code lenses include export usage, complexity, and React component intelligence. The VSCode extension supplies dead-code/duplicate/health/security/coverage trees, clickable audit status, baseline commands, and opt-in run-on-save audit. [LSP capabilities](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/lsp/src/server_capabilities.rs#L8-L29), [lenses](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/lsp/src/code_lens.rs#L50-L62), [VSCode](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/editors/vscode/src/extension.ts#L872-L962).
- **Important editor correctness detail:** analysis is disk-based. Per-document versions and exact disk/buffer comparisons prevent stale diagnostics on unsaved edits. Scheduling coalesces events (200ms quiet or max 2s delay) and allows only one consecutive cancelled run so autosave cannot starve every publish. These are useful concrete contracts to add if selecting an OpenSIP editor client. [buffer state](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/lsp/src/document_state.rs#L1-L45), [scheduler](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/lsp/src/schedule.rs#L1-L37). Our machine projections and safe HTML editor links are designed; no LSP client/buffer lifecycle was found in the inspected current consolidated workflow prose. [selected surfaces](../../docs/v2/architecture/10-mvp-and-future-scope.md#L37-L47), [safe editor links](../../docs/v2/architecture/prototype-report-inventory.md#L147-L149).
- **Maintenance queue:** Fallow refactoring targets combine complexity density, churn hotspot, dead-code ratio and dependency fan-in/out; normalize distribution-dependent thresholds; retain contributing factors/evidence; sort by priority/estimated effort to expose quick wins. The exact chosen weights are heuristics, not measured ROI. [target algorithm](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/engine/src/health/targets.rs#L41-L153). OpenSIP admits history as advisory priority input and supplies candidate/inspect/review brief, but its closed candidate kinds are clone-candidate, low-confidence-unused, runtime-unhit and history-stale; current inspected contract does not specify a maintenance-cost/effort queue. [history](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L520-L525), [candidate contract](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L675-L699).
- **Speed-work queue:** Fallow distinguishes change importance from optimization target. Cost proxy is invocation count times peak-block-executions/calls when V8 block data exists, otherwise invocation count times cognitive complexity (minimum 1); it labels cost basis explicitly. This is not elapsed time, CPU time or a performance bottleneck proof. [formula](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/cli/src/health/optimization_target.rs#L320-L359). OpenSIP runtime observation and source mapping are designed, but concrete optimization-target ranking was not found in inspected contracts. [runtime interpretation](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L520-L525).
- **MCP agent ergonomics:** Fallow supplies typed tools, a shared in-process parsed-module warm store, and bounded JavaScript Code Mode to combine/filter read-only tools before returning data. Limits include 20KB snippets, 32MiB memory, 8 host calls, 30s max deadline and 4MiB max output; allowed tool enum excludes fix apply. [warm store](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/mcp/src/warm_session.rs#L1-L33), [Code Mode bounds](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/mcp/src/tools/code_mode.rs#L19-L47), [tool allowlist](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/mcp/src/tools/code_mode_tools.rs#L41-L65). OpenSIP has machine/agent projections and `agent serve`; do not call generic agent support missing. Protocol packaging and programmable filtering can be an optional ergonomic follow-up, not an architectural replacement. [agent command inventory](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L1097-L1101).

### Inferences
- Highest value small design addition is an editor projection contract with stale-view refusal, source-version binding, cancellation/progress and safe edit handoff to existing repair authority. No need to change Control semantics.
- A named advisory maintenance queue could compose churn, ownership, complexity, coupling, coverage, clone and effort evidence with visible contributing factors and bounded assumptions. Keep metric priority separate from evidence sufficiency and never promote a ranking to verdict or repair permission.
- Optimization ranking is a lower-priority differentiator unless OpenSIP wants performance remediation. Borrow the separation of risk and cost, not the exact proxy weights.

### Gaps
- No benchmark or measured productivity proof establishes Fallow faster or more useful in practice.
- No Fallow TUI implementation was found among crates. The supported comparison is VSCode/LSP and CLI walkthrough interaction, not terminal UI superiority.
- Absence statements are bounded to inspected consolidated contracts, current architecture scope and targeted keyword searches, not a proof that no older design anywhere mentioned those ideas.

## Which apparent gaps are already designed or deliberate scope choices?

### Takeaway
Most headline workflow features are already covered by the prior Fallow borrowing and now have stronger consolidated contracts. Third-party plugin ecosystem and TUI are explicit exclusions, rather than forgotten requirements.

### Cited Findings
- Baselines, audit/new-only gates, zero-config recommendations, evidence imports, deterministic output, candidate inspection, bounded review and policy testing were explicitly adopted/preserved under FW-01 through FW-15. [prior borrow register](../../docs/coop/FALLOW-BORROW-REGISTER.md#L44-L72).
- OpenSIP portable baseline embeds identities, policy/scope/waiver descriptors and admitted detector closure; `baseline show`, adopt/export/upgrade and audit are designed. [baseline contract](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L257-L323).
- Candidate discovery, inspection, suppression until changed evidence/date and producer-labelled bounded review briefs are concrete current design. Fallow review/walkthrough's source anchors, graph snapshot pin, owner grouping and consequential decision ordering do not introduce a wholly missing review concept. [OpenSIP review](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L675-L699), [Fallow review data](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/cli/src/audit.rs#L54-L97).
- Declarative rule authoring/testing is already designed with strict data-only schemas, effective policy digests and refusal semantics. Fallow also exposes local external JSON/JSONC/TOML framework plugins with conditional dependency/file detection, entry roles, glob roots and manifests. This makes private framework conventions convenient, but does not add arbitrary code execution or semantic plugin authority. [Fallow declarative plugins](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/config/src/external_plugin.rs#L87-L194), [OpenSIP policy authoring](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L591-L673).
- OpenSIP deliberately selects one signed first-party registry and excludes public marketplace, third-party publishers, untrusted executable/WASM contributions and TUI. Call local declarative framework customization a potential product choice, not an accidental architectural hole; Fallow's local configuration support is not proof of a public marketplace. [scope](../../docs/v2/architecture/10-mvp-and-future-scope.md#L37-L47), [registry/admission boundaries](../../docs/v2/contracts/product-v1/admission-and-qualification.md#L339-L349).

### Inferences
- If users commonly have private framework conventions, compare the convenience of Fallow's external declarative recognizers against OpenSIP's signed profile admission. Safe local data-only root/discovery overrides could be valuable, but only after checking existing Config2 technical-recognition fields; do not reopen arbitrary plugin execution by default.

### Gaps
- The inspected local OpenSIP workflow contract does not fully enumerate which custom framework recognition overrides Config2 already permits; do not confidently assert those are unavailable.

## What does fully implemented OpenSIP do better?

### Takeaway
OpenSIP is designed to make comparison, evidence reuse and edits auditable and safely attributable across source/policy/detector changes. Fallow has useful safety checks, but still uses weaker gate attribution and file-by-file commit mechanics in these paths.

### Cited Findings
- **Repair atomicity/recovery:** Fallow stages all writes into same-directory temp files, fsyncs them, checks root confinement and expected content/resolved paths before promotion, preserves file mode/BOM/line ending, rejects mixed CRLF/LF. This is substantive safety. But its final loop independently persists each file and accumulates written/failed sets; no compensating batch rollback appears in this commit path. If a later promotion fails, earlier changes can remain. [Fallow commit](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/cli/src/fix/plan.rs#L221-L275), [staging/revalidation](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/cli/src/fix/plan.rs#L288-L406), [encoding](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/cli/src/fix/io.rs#L1-L67).
- OpenSIP repair uses hash-addressed exact preview plan, current trusted recipe and authorization bound to plan/project/base snapshot, durable PREPARING→STAGED→APPLYING→APPLIED→COMMITTED journal, compensating restore of already-renamed targets on failure, blocking on unrecognized target state, separately authorized crash recovery, and fresh snapshot verification. [OpenSIP preview](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L707-L717), [OpenSIP apply/recover/verify](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L1008-L1040).
- **Preview/apply agent handoff:** Fallow MCP fix preview invokes dry-run CLI; fix apply independently invokes `fix --yes` with same root/config/options. Parameters shown do not carry an immutable preview plan identity. OpenSIP apply names the exact preview plan identity and authorization, so approval cannot silently select a newly recomputed different edit plan. [MCP fix](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/mcp/src/tools/fix.rs#L1-L66), [OpenSIP authorization](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L1008-L1016).
- **Honest comparison:** Fallow's shared audit ledger explicitly demotes semantic-only introduced findings to inherited/advisory when base/head semantic identities cannot be compared and attribution falls back to syntactic keys. It is documented deliberate behavior, not conjecture. [Fallow demotion](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/api/src/audit_keys.rs#L108-L133). OpenSIP cannot recast missing comparison evidence as inherited: required prior-detector pivots and tri-valued presence produce typed INDETERMINATE; known net-new findings still gate. [OpenSIP multi-axis law](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L330-L418).
- **Distinguish fixes from moved goalposts:** OpenSIP separately attributes code, detector, policy, scope, waiver and evidence changes, keeps subsequent deltas, uses union of removed/added detectors and gates known net-new code even when hidden by policy/scope/waiver changes. That is stronger than a single new/inherited membership gate. [comparison](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L330-L467), [Fallow membership](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/api/src/audit_keys.rs#L11-L40).
- **Evidence freshness and limited inference:** OpenSIP import binds exact schemas/payload/provenance/build/source mapping, treats stale/wrong-build/unverifiable input as unusable for predicates, distinguishes observable-unhit from unobservable/unmapped, and forbids runtime observations alone from proving universal non-use or improving native destructive-repair closed-world eligibility. [imports](../../docs/v2/contracts/product-v1/workflows-and-surfaces.md#L473-L568). Fallow's useful ranking/reporting machinery does not supply this full OpenSIP custody/admission law.

### Inferences
- Strongest concise differentiation: Fallow answers what to clean up next more concretely; fully implemented OpenSIP answers why a gate is trustworthy and whether an edit/reused observation is authorized and reproducible more rigorously.
- Retain Fallow's real safeguards in fair comparison; do not call all its fixes unsafe merely because full transaction recovery is absent in this path.

### Gaps
- No concurrency/fault execution was performed. Failure conclusions derive from inspected code control flow, not a reproduced crash.
- This scope does not evaluate all Fallow source custody paths or third-party integrations; avoid an unbounded claim that Fallow has no evidence provenance anywhere.
