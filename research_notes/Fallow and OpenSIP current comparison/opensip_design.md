# Current OpenSIP design against current Fallow

## What does Fallow do better than the fully implemented intended OpenSIP product?

### Takeaway
Fallow has materially broader framework/front-end analysis and developer integration. OpenSIP's full design already adopts many of the previous comparison's workflow ideas; the remaining differences are concrete capability depth and deliberate product scope limits, not implementation lag.

### Cited Findings
- Comparison basis: OpenSIP HEAD65a185c39d6b912500115cbe452b0005dcfff362, current full product D-372. The contract README expressly says Fallow-inspired zero-config, stable output, invocations, retained evidence, changed-code gates and advisory boundaries belong to the current full design even when implemented later. [Current authority](/Users/sb/code/opensip-ai/opensip_arch/README.md:5), [full contract scope](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/README.md:42).
- Fallow HEAD1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c has built-in plugin construction for Next, Nuxt, Remix, Astro, Angular, SvelteKit, Expo, React Native, NestJS, many build/test/content tools. Its engine registry tests assert >100 plugin names; the count includes tool integrations, not100 equally deep semantic framework analyzers. OpenSIP has exactly nine recognizers: node-package, typescript-config, npm-workspaces, pnpm-workspace, cargo-package, cargo-workspace, nextjs, vite, vitest-jest. Unknown frameworks remain disclosed with incomplete reachability, not inferred closed world. [Fallow source](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/core/src/plugins/registry/builtin.rs#L5), [engine registry check](https://github.com/fallow-rs/fallow/blob/1b1b9dd6d5015f77cf911887c2e9a1d0f4256e5c/crates/engine/src/plugins.rs#L102), [OpenSIP exact recognizers](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:2750).

### Inferences
- Framework breadth and component/style parsing are the strongest practical gaps for JS/TS users: compiler accuracy cannot recover application entry points or template/style relationships absent from the selected input model.
- Editor diagnostics could reuse the typed Run/query model, while unsaved-buffer analysis needs a separate advisory overlay contract. Preserve that distinction when borrowing LSP UX.
- Prefer individual explainable complexity metrics and contributions over copying an aggregate0–100 health score.

### Gaps
- I did not build/run Fallow; claims here concern selected source behavior, not performance or precision validation.
- Fallow model similarity is broader than OpenSIP's explicit near-clone shingle algorithm, but it was already examined in FW-02. It remains an optional advisory capability choice, not a novel missed safety feature. [Prior borrow disposition](/Users/sb/code/opensip-ai/opensip_arch/docs/coop/FALLOW-BORROW-REGISTER.md:54), [current concrete clone modes](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:2562).

Cargo workspace members fold into one workspace program unit. Co-located Rust and TS roots remain separate language units. - Baselines, runtime imports, explain/inspect/review, repair preview/apply/verify, zero-config provenance, policy tests, generated inventories and weakening attribution were already adopted into full contracts. ## What does fully implemented OpenSIP do better?

### Takeaway
OpenSIP offers stronger source/evidence/authority semantics, replay, semantic negative reasoning, multi-axis regression attribution and mutation safety; Rust native semantics is also a distinct capability absent from Fallow's JS/TS analyzer scope.

### Cited Findings
- Native TS compiler-bound identities plus Rust compiler-native universes with sealed source/dependency/toolchain/prepared inputs. Rust procedural macros/build scripts remain inert prepared data or explicit unavailable edges; ordinary analyzer execution never silently runs them. [native matrix](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:584), [Rust universe](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:1255), [dependencies](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:1646), [preparation](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:2497).
- Distinguishes exhaustive examined population from complete reference/import/call resolution. Unknown exports, nonliteral loading, dynamic dispatch and unknown external consumers propagate uncertainty; private:true alone cannot establish a closed world. Universal negatives and destructive repair demand sufficient evidence. [two completeness claims](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:1878), [closed-world ingredients](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/native-evidence.md:2208).
- Pure evaluator retains complete predicate tree with strong Kleene truth and unknowns; all branch deficiencies stay visible, even when a known hit determines failure. Independent replay uses retained admitted inputs, not producer PASS flags or emitted findings as the oracle. [evaluation/proof](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/identity-and-evidence.md:1489).
- Immutable exact source snapshot, semantic Plan, facts/Coverage/import evidence and versioned identities support independent source-bound replay and authoritative durable Runs. Default durable commit verifies proof before immutable object publication and atomic ledger receipt. Explicit ephemeral execution has no authoritative Run/repair/baseline authority. [durable commit](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/identity-and-evidence.md:1631).
- Baseline carries embedded policy/scope/waivers, rule absence knowledge and runnable detector closure. Fresh CI can run old detector over current source; attribution separates code, detection, policy, scope, waiver and evidence differences. Disabling a rule while introducing a bug cannot silently classify it fixed. Missing/revoked old closure produces typed uncertainty. [portable pivot baseline](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/workflows-and-surfaces.md:257), [multi-axis comparison](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/workflows-and-surfaces.md:331).
- Repair binds exact source snapshot/evidence/recipe trust and file pre/postimage bytes; destructive actions require native closed-world prerequisites. Preview, apply, recovery and fresh verification have distinct authorization and evidence semantics. Model review dispositions cannot mint verdicts or authorize repair. [candidate/review](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/workflows-and-surfaces.md:675), [repair](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/workflows-and-surfaces.md:701), [apply grant](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/security-and-lifecycle.md:1161).
- Host authority owns policy, persistence, output and termination; providers produce only facts/Coverage. No implicit config execution, downloads, ambient evidence, hooks or telemetry in ordinary analysis. Signed first-party closures/offline inventory/lifecycle/revocation are explicit. [host architecture](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/README.md:9), [selected boundary](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/admission-and-qualification.md:337).
- Output parity ties human/JSON/SARIF/HTML/agent projections to same findings, verdict, required Coverage, deficiencies, termination and retention disclosure; renderer omission cannot turn missing analysis into empty findings. [current renderers](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/workflows-and-surfaces.md:1108).
- Qualification gates construct expected cell/fixture sets independently, compare normalized observations to independent pinned oracle, compute correctness/performance rather than trusting reported PASS, and require every platform/profile lane. Warm and cold/evidence workloads separate. [independent report oracle](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/contracts/product-v1/admission-and-qualification.md:225).
- Warm incremental snapshot content capture is already designed via stat-cache/Merkle/lazy CAS with racy-timestamp protection, bound invalidation/retry and explicit validation assurance. Do not call incremental architecture missing; measure achieved latency before claiming faster. [snapshot cost model](/Users/sb/code/opensip-ai/opensip_arch/docs/coop/architecture/03-execution-model.md:33).

### Inferences
- Strongest differentiated product pitch is evidence consumers can inspect/replay and mutations they can authorize against exact source, rather than simply more detectors.
- Native compiler semantics improve binding identity but do not make dynamic JS, public APIs or all Rust dispatch complete. OpenSIP's explicit uncertainty is a strength and must remain visible.
- Fallow's much lighter Oxc/static runtime model is likely simpler to distribute than full compiler/toolchain/storage closure, but that is an inference; no comparable measured closure costs were obtained. OpenSIP's aggregate closure size/startup/memory costs are already qualification obligations. [closure budgets](/Users/sb/code/opensip-ai/opensip_arch/docs/v2/architecture/02-distribution-and-components.md:35).

### Gaps
- Scope precision: no claim that Fallow lacks all source guards, determinism, uncertainty metadata, baselines or repair safeguards. Parent researcher should contrast actual Fallow implementation against these specific stronger contracts.
- Assumption of full implementation does not supply empirical precision, speed, memory or false-positive evidence.
