# Pre-Run interruption envelope correction

Unreviewed root proposal, conditional on the report04 envelope5 candidate. No design lock, architecture owner or product files are changed. RP-OBL-C01 exposed a public shape gap: envelope3 required errors, metadata successor4 permits errors=[] only for REQUEST.UNKNOWN_OPTION with a diagnostic, and envelope5 retains that restriction. Therefore an interrupted invocation with no committed Run and no prior error detail cannot use the failure form, even though the existing D9 class/signals/exit130 are owned. Using an unrelated error detail would misstate the event.

Proposed envelope6 adds one alternative to the existing empty-errors condition: kind=failure, errors=[], exitCode130 and an exact termination object {class:interrupted, signal:SIGINT|SIGTERM|SIGHUP}. It creates no code, detail, kind, identity or cancellation rule. Metadata UNKNOWN_OPTION diagnostics remain byte-for-byte the other alternative. The new form has no Run/result/findings/query/mutation/doctor/invocation/metadata/retention/diagnostics/agent-hint payload; it permits existing request/project correlation fields. Only this new empty-errors form is constrained this way. Historical nonempty-errors forms and their semantic owners are preserved; this change does not erase previously recorded step failures.

The host selects this form only after the owned before-settle cancellation decision and only when it has no committed Run to name. It cannot substitute it for an operational fault, policy verdict, indeterminate result or request rejection. A previously committed Run still follows the existing Run-bearing interruption carrier and keeps its exact identity. Cancellation after settlement does not reclassify the settled outcome. Existing RequestId and optional clientCorrelationId are retained. Failure to deliver the interruption envelope still follows existing delivery rules; this schema does not implement signal handling or decide a cancellation/delivery race. Original step outcomes remain in the operational invocation ledger, irrespective of the final aggregate. No dummy Run or invented error record is permitted.

The successor record gives the exact parent bytes and one JSON-pointer change, plus the required major/id/title/description changes. Restoring those yields the full envelope5 object exactly. The new major is explicit: no major5 consumer silently accepts6. Final report projection, inventory mapping, generated source registry/closure, metadata/CLI tests and real host delivery must all be rebound after actual root/Claude acceptance. This is not immediate source promotion or full report design approval.

The standalone checker verifies34 copied source pins before loading the copied canonical reference, uses an offline explicit registry with the reviewed exact-number validator, reproduces refusal of all three owned signals in envelope5, and admits the corrected forms in6. It checks missing fields/signals, invalid signals, wrong classes/exits, false/float numbers, spurious details/Run/result fields and wrong majors. All43 existing metadata fixtures keep the same shape outcome under major5 versus6; this is shape compatibility, not rerun compiled-catalog semantic admission. Run with /tmp/opensip-implementation/metadata-reference-env/bin/python -I -B check.py. The trusted reference environment uses jsonschema4.25.1; no production signal/delivery/browser/runtime qualification follows.
