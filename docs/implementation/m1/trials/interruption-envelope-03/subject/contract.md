## Owner decision: preserve optional committed Runs

The cancellation prose says a Run committed by an earlier step is retained, without restricting that step to required. Optionality governs gating, not whether an authoritative Run exists. This revision selects the last completed analysis/verify Run in step order, including optional steps. `model-successor.json` changes exactly the cancellation branch's iteration from required results to all results. Required steps still alone determine whether settlement happened and the normal D9 aggregate; no exit/class/code/detail, Run identity recipe or step outcome is changed. `passage-overrides.json` contains exact before/after spans for both the cancellation paragraph and the failure-envelope paragraph. ## Named host joins

After planning, J-INTERRUPTION-LEDGER consumes the host's admitted finalized invocation record and an independently shape-admitted envelope. It checks RequestId/project/correlation, exact step/result order, cancellation phase, and every step/result kind. Analysis and verify use AnalysisResult; a query cannot carry one. Cancelled steps have no result and carry the observed interrupted signal, and every subsequent step is cancelled. Non-cancelled steps cannot carry interrupted terminations. Malformed reference arguments produce a named JoinRefusal rather than leaking KeyError/TypeError. This is not a replacement for full schema/DAG/attempt/Run admission or custody, which remain host implementation duties; the three previously missing prerequisites from F-B are now explicit executed checks.

On before-settle interruption, the envelope's aggregate must equal the derived class/signal/last-commit tuple. A run carrier has the exact original AnalysisResult; an invocation carrier holds the exact finalized record. Mixed result carriers refuse. With no committed Run, the selected output is the new empty failure or exact invocation carrier. A cancelled query/doctor result or unrelated current error detail is not fabricated. Earlier actual faults remain in their original step ledger entries. Existing nonempty-error shapes are not removed from envelope6, and other outcome classes keep their existing detail composition. This successor's interruption projection chooses the honest detail-free aggregate rather than treating the schema's permissive unrelated-error combinations as legitimate output. It does not alter previously recorded errors.

Before planning, no InvocationRecord exists (its schema requires at least one step). J-INTERRUPTION-PREPLANNING therefore uses a separate private trusted host observation {stage:before-planning,requestId,signal,projectId?,clientCorrelationId?}; it is not serialized user authority and is supplied from the already-reserved RequestContext plus the actual signal. It admits only the matching new empty failure. The host must not create that context after an invocation was admitted or after a commit. Actual lifecycle/capability custody is not implemented by a Python dictionary. This preplanning path creates no dummy step, attempt, Plan or Run.

A report's in-progress projected ledger is a different carrier from the finalized host InvocationRecord. It may have unrecorded children and cannot stand in for it here. When cancellation aborts a required report render, no completed report document is delivered; after the remaining cancelled outcomes are recorded, the host emits the interruption envelope through the owned delivery path. Failure to record or deliver keeps its own existing operational fault law. No successful partial HTML result is inferred from a reference cancellation case.
