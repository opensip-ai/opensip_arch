## Named host joins

It checks RequestId/project/correlation, exact step/result order, cancellation phase, and every step/result kind. Analysis and verify use AnalysisResult; a query cannot carry one. Cancelled steps have no result and carry the observed interrupted signal, and every subsequent step is cancelled. Non-cancelled steps cannot carry interrupted terminations. Malformed reference arguments produce a named JoinRefusal rather than leaking KeyError/TypeError. This is not a replacement for full schema/DAG/attempt/Run admission or custody, which remain host implementation duties; the three previously missing prerequisites from F-B are now explicit executed checks.

On before-settle interruption, the envelope's aggregate must equal the derived class/signal/last-commit tuple. A run carrier has the exact original AnalysisResult, retaining its analysis or verify kind; an invocation carrier holds the exact finalized record. Mixed result carriers refuse. With no committed Run, the selected output is a failure or exact invocation carrier; findings and advisoryReport are forbidden; invocation-scoped availability follows the retained selection rule below. Every interrupted carrier (failure/run/invocation) projects the complete in-step-order recorded domainDetails on earlier request-rejected/operational-failed steps. Include optional-step failures; exclude skipped and cancelled steps. A nonempty list is always carried in `errors`, exactly. When the list is empty, failure carries `errors:[]` while run/invocation omit the field, matching the existing shape constraint. There is no host choice between these forms. Changed remedies, duplicates, omissions, missing nonempty arrays and unrelated details refuse. The host persists the actual composed route detail when every such step is recorded, even when no interruption occurs. This is a host ledger-admission duty; the join cannot detect a detail that was never recorded. A cancelled query/doctor completion is not fabricated. Other outcome classes keep their existing detail composition. Frozen03 and04's error policies were never accepted and are superseded by this deterministic rule, aligned with report06's interrupted-failure policy. A report's in-progress projected ledger is a different carrier from the finalized host InvocationRecord. It may have unrecorded children and cannot stand in for it here. ## Availability is owned by the invocation

Review05 R1 is resolved by preserving the existing workflows-and-surfaces lines 1302–1329 law. A selected release-availability account does not require a committed Run. A retry contributes the single selection retained for that step, never all attempted selections. No fresh selection occurs during interruption rendering.

The mandatory complete delivery entry points are `validate_interruption_delivery` and `validate_preplanning_delivery`. The narrower `validate_interruption_join` and `validate_preplanning_interruption` remain component helpers for regression checks; invoking them alone does not satisfy final delivery admission.
