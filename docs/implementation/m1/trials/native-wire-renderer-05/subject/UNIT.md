# Native inert carrier renderer trial

This staged developer trial renders the proposed native IDL into Rust and TypeScript. The native owner is independently being corrected; this trial does not approve its semantics or install product files. Input copies and their exact origins are in input-pins.json. The externally selected common-control subject supplies unchanged extern types and contracts dependencies.

The generic renderer covers 17 scalar aliases, 50 records (45 structs, four tagged records, one external alias), 23 distinct external types and two protocol frame families. u64/bigint preserves unsigned integers. ByteString owns its data; deserialize_any preserves bytes versus text/array, without routing tagged records through Serde Content buffering. Four tagged records use generated map readers with exact text keys, duplicate and unknown-key refusal, and exact primitive scalar kinds. They accept a discriminator in any map position. Complex variant member types refuse during generation; these readers do not claim arbitrary record support. Rust nullable required members use explicit presence deserialization; optional members use FieldPresence to preserve absence versus empty/null. TypeScript optional properties require exactOptionalPropertyTypes. Generated auxiliaries reject name collisions. The frame and payload Rust types deliberately have no generic Serialize/Deserialize implementation: M3 must decode by actual frame tag and admitted host selector. TypeScript correlates frame tag/direction/payload in unions; host selector semantics still require admission.

Scalar bounds, numeric constants, NFC, path grammar, order, joins, commitments and frame state are handwritten admission duties, not established by these inert types. Serde is not a CBOR encoder or bounded parser here; serialization via a JSON serializer can produce arrays, so these traits do not establish wire output. M3's dedicated codec must enforce the format, length-before-allocation and canonical output. No generic serde value is authority. No host resource bounds or provider/runtime behavior are qualified.

Run Python -B test_render.py; pinned reference Python can validate inputs/wire-carriers.v1.json against inputs/wire-carriers.meta.schema.json. Run cargo test --locked --offline and strict TypeScript with tsconfig.json. Nine Rust tests cover actual representation boundaries; two compile-fail doc tests ensure frames cannot bypass host selection via generic serde. TypeScript probes contain positive and expected-negative assignments. Fourteen Python groups cover repeated generation, namespaces and refusal of ambiguous/unknown constructs. An initial test exposed deserialize_byte_buf accepting JSON strings; the renderer now uses deserialize_any. An initial test incorrectly named an absent ordinal alias; it was corrected to exercise an actual generated record. These are test-development corrections, not historical owner changes.

This file set can be copied and compiled independently with cached pinned Cargo dependencies and the separately pinned TS6 compiler. render.py writes fragments directly without formatting; final product integration must route them through the accepted prettyplease/TS-printer recipe and bind a closed validated IDL input profile, source selection, full generator closure and same eight outputs. No product integration, source-owner acceptance, M1 completion, wire codec/admission, performance, platform or release qualification follows.

Review01 found that Serde tagged buffering accepted an empty map for null, a byte string for text, and non-text map keys. Trial02 replaces that path with generated readers using deserialize_any and exact scalar visitors. New Rust probes cover all 18 required-null member positions, text/tag/key coercions and genuine byte strings with the tag last. The TypeScript direction-negative probe now shares a complete valid payload with its positive control, so direction widening is observable. Layout validation binds envelope headers to frame tables, confines frame-payload to its envelope position, refuses scalar const/enum conflicts and out-of-domain uint64 literals, rejects discriminator redeclaration and ambiguous generated names, and escapes Rust keywords. These are inert representation and generator grammar checks, not semantic admission. Flat Serde-derived records still rely on the eventual codec honoring type hints; a production CBOR codec must be independently qualified.

Review02 confirmed both review01 fixes. Trial03 applies scalar/layout validation to frame payloads and every selector alternative, and tests all four tagged-record duplicate guards with identical repeated member/tag values in raw JSON including tag-last order. It also refuses empty text enums, nonboolean bool constants, repeated memberOrder entries, single-variant tagged records and a changed envelope sequence type. Both TS direction families now have complete positive/negative controls. For the future dedicated CBOR codec, unsigned major0 must dispatch visit_u64 and null must dispatch visit_unit: visit_i64/visit_none are deliberately not interchangeable in this exact-kind bridge. Readers allocate a maximum of seven scalar slots but their bytes/text are unbounded until the dedicated length-before-allocation codec is implemented; no allocation-budget qualification follows.

Review03 confirmed all twelve mutation probes catch their target regression. Trial04 closes selection payload shape: exactly select/alternatives, one of the two selected mechanisms, exact two known alternative keys and ordinary type alternatives. Empty, missing, unknown, extra, nested or mixed type/selection shapes refuse; no declared frame may silently disappear because its alternatives map is empty. The earlier frame-payload negative tests used a misspelled selector key; those fixtures now use the actual valid select envelope before changing their alternative type. Independent malformed-selection tests include a positive two-variant render control. Full closed IDL profile and external reference/name validation remain required final integration duties; this renderer trial alone is not untrusted-schema admission or code-injection confinement.

Review04 found that positional alternative variants changed meaning when JSON object keys were reordered. Trial05 iterates the two mechanisms in explicit fixed owner-key order and records each key-to-variant/type mapping in render-result.json and generated Rust documentation. Equivalent alternative object order now produces identical renderer bodies and mappings. Identical alternative declarations or emitted Rust/TS type pairs refuse; no universal underlying alias-equivalence claim is made. TypeScript frame alternatives describe actual payload representation, not admitted host state. The positive FactBatch check now isolates the Ts2FrameV2 union and counts both rows, and non-object payload cases exercise the explicit refusal. Root and Claude do not claim the full closed IDL input profile, alias-cycle/extern resolution or source selection have been integrated by this algorithm trial.
