# Report asset integrity and safe-handle trial

This is staged implementation of the pure reporting asset verifier and a Unix platform handle adapter. It implements the selected report-asset binding algorithm over labelled fixture inputs. It does not install product files, select a real report bundle, introduce a public pin API, or qualify HTML, a signed release, lifecycle trust or D9 integration. source-pins.json binds exact design and identity inputs; Cargo.lock pins the two external packages, sha2-const-stable0.1.0 and libc0.2.189, already used in prior foundation trials. No new network provisioning was required.

The manifest is checked against raw byte length and SHA-256 before parsing or reading members. Exact JSON admission rejects duplicate keys and lossy numbers. Closed root/member fields, nonempty ordered unique digests and paths, exact supported projection digest, file roles, byte bounds and the one exact manifest exclusion are checked. Byte reads consume at most expected+1 bytes, retry Interrupted, grow allocation from actual data rather than claimed lengths and return no partial bundle. VerifiedBundle keeps the manifest digest/root/path with privately held owned asset bytes; completeness cannot be checked against a different supplied pin. Completeness requires an independently complete regular-file enumeration from build assembly and detects extra, missing and duplicate paths. It does not generate that enumeration.

The separate platform crate starts from a retained host-selected directory File. openat walks one component at a time with O_NOFOLLOW and O_DIRECTORY for parents, O_CLOEXEC and O_NONBLOCK, checks the opened endpoint is regular, and returns that same File. Descriptor ownership is explicit at the two unsafe operations. It neither discovers an installation root nor authenticates who selected it. Same-process host adapters are trusted under TCB-SCOPE-01. Reporting itself uses only identity and standard Rust; the platform dependency is test-only here. In product, the host implements the reporting-owned source trait using platform handles without a forbidden reporting-to-platform dependency. No caller path or pin may enter the final rendering API.

Limits requiring final integration: FixturePin is intentionally a public trial-only input; product must replace it with the private host-embedded constant in assets.rs and sole BUILD_CHANNEL, selected together with the real generated report schema and actual offline bundle. Manifest parsing currently uses the reviewed identity JSON profile (4 MiB/32 containers), while the private design permits larger manifests; this trial refuses above that profile before opening. Final assembly must establish that the exact selected manifest fits, or select a reviewed private profile. Asset lengths use the exact private schema maximum9007199254740990; actual bundle sizing and host resource budgets remain to be established. The fixture verifier consumes all listed members; a future subset needs explicit checked selection. It neither asserts runtime completeness nor ignores missing selected assets. Hardlink count is not refused by this owner; digest checks bind opened bytes, and returned bytes do not change if the source subsequently changes. An untrusted manifest cannot choose paths because its raw bytes must first match the trusted pin. Whole-host/root substitution is the existing trust boundary.

Seven unit groups cover raw anchor ordering, exact closed/lexical shape, schema compatibility, path/order/self-list rules, roles/zero-byte notice, mutable source independence, member corruption, completeness and actual stream read caps. Three real-filesystem groups on macOS-aarch64 cover a bundle, same-length corruption, symlink parents/leaves, directories, sockets, FIFO refusal without blocking, traversal and retained handles under root/leaf replacement. These are deterministic handle tests, not exhaustive concurrent filesystem-race or Linux qualification. The test-only FIFO helper is /usr/bin/mkfifo. Initial tests used an incorrect literal byte length22 instead of23 in two negative fixtures; the new non-vacuity assertion exposed it, and those fixtures now actually change their valid control.

Run /opt/homebrew/bin/cargo test --locked --offline, cargo clippy --locked --offline --all-targets -- -D warnings and cargo fmt --all --check. Real UI assets and compiled pin assembly, source/closure/inventory selection, nonasset startup isolation and required/optional D9 delivery integration remain necessary. No release, platform-wide, M1 or complete-project readiness follows. Actual independent Claude review is pending.

Review01 independently found no code defects and required permanent tests for twelve uncovered guards. Trial02 adopts eight reviewer regression groups (including the 73-case exact-error/open-order matrix) and a platform descriptor-flag test; the ignored performance probe remains historical evidence rather than a routine test. Test provenance is explicit in test-origins.json. The verified bundle now also retains and exposes the exact checked projection digest, addressing PI projection binding for this algorithm. Final rendering still must join it to the compiled selected projection. O_NONBLOCK intentionally remains set on regular-file descriptors. Device leaves can run an open routine before fstat refuses them; the installation root remains trusted. The default root test command does not run identity's own tests or the platform crate's integration tests: run the explicit platform test command too. No identity requalification or exhaustive race claim is made. Final assembly still needs a real nonregular-refusing enumerator, portable case/normalization collision checks, real private compiled pin/channel, actual bundle size/total budgets, D9 joins and Linux qualification.
