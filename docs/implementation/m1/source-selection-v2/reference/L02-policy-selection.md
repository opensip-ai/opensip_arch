# L02 required output policy — root selection for source integration

Codex selects the complete-output-or-explicit-operational-failure policy described
by required-output01/contract.md and the exact joint10 D9v1.15 proposed successor.
Actual Grok joint10 review explicitly finds this acceptable as an alternative;
Codex reproduced its independent interruption/write-failure/after-commit probes.
The exact review bytes are pinned in L02-policy-selection.json. This records an
owner decision within the user's authorized implementation scope. It does not
claim the final source bridge, production delivery or M1 is complete.

The old stronger criterion—reject before retained selection or provide a complete
larger bounded profile—was not met. This decision replaces it explicitly. Both
that criterion and its unsatisfied evidence remain in inherited-joint10-obligations.json
and originalClosureCriterion. No retrospective pass is recorded.

The normal CommandEnvelope remains4MiB/depth32. Before normal emission, the host
admits the exact complete projection and its private invocation/source joins and
uses the bounded codec. It cannot discard required fields, substitute a Run,
truncate a notice or allocate unboundedly before checking size. A capacity or
serialization failure emits no normal envelope and yields the existing
OUTPUT.SERIALIZATION_FAILED operational failure, exit4. Prior committed work and
its invocation aggregate remain intact. The user can therefore receive an output
failure after useful work committed; this is an explicit product behavior.

On successful required serialization/write/flush, the process termination equals
the aggregate, including interrupted/130. A later required output failure owns
process exit4 even when the preserved aggregate is interrupted. Required renderer
failures remain their existing step/delivery faults; a failure emitting their
failure envelope is a later output fault. Finalization has one commit and exit site.
No observer or optional delivery after that commit reclassifies the process.

Stream failure may expose a prefix or all bytes before flush failure. Never append
a second fallback envelope or promise atomic stdout. Best-effort fixed diagnostics
contain no caller text or exception data. File delivery uses its selected durable
publication contract and cannot falsely claim no visibility after publication.

The report's larger profile remains distinct from the envelope and embedded owner
profiles. This decision selects no larger InvocationRecord materialization and
closes no L01 retention issue. Source binding must carry the D9 parity clarification
and original golden derivations together. Actual bounded encoder, private source
custody, live signals, pipe/file failures and platform recovery remain product tests.

The policy decision is made; RP-OBL-L02 remains a final-integration blocker until
its reviewed source binding is complete. The implementation criteria are retained
for the relevant product milestones, not passed by a reference review.
