## Precondition challenge
Root says the join runs after complete invocation/step/DAG/Run and D9 admission, over trusted custody. That is honest, but under-specified.

**What the join re-derives:**
- correlation fields
- step and result membership
- settledness and phase
- the exact aggregate with the last *required* runId
- run-carrier equality
- invocation equality (committed branch only)
- after-settle non-reclassification

**What it assumes, with no pinned owner implementing it:**
- cancelled ⇔ interrupted, with the same signal
- the cancellation-suffix law
- result kind bound to step kind
- attempt consistency
- record custody

The pinned model has a generator and `validate_dag`, but **no invocation-record admission**. report04's `J-LEDGER-CANCELLATION` covers part of this, but only for report documents, and it is unaccepted.

## Remaining findings
- **F-A (medium, blocks prose selection).** The override says the form applies when there is "no earlier committed Run". It also adopts the D9 ledger rule, which (model :376–382 and the join) considers only **required** steps. Owner text :226 says "a Run committed by an earlier step" without that qualification. D5 shows a durably committed optional-step Run left unnamed. The owner must decide, then align the prose or the rule and join, and add a golden.
- **F-B (medium, blocks host-duty selection).** Name the prerequisite joins as host duties, or fold them into `J-INTERRUPTION-LEDGER`: per-step cancellation signal, the cancellation suffix, and result/step kind. Refusals must be typed. The erasure and substitution guarantees depend on these.
- **F-C (low-medium).** The no-commit branch doesn't police the carrier, so "no invented detail" and "no fabricated query completion" are unenforced. An interrupted aggregate has no route detail for native §10 composition to supply, so no existing owner check is identified. Restrict the before-settle no-commit carriers, or name the owner check. Apply invocation-record equality in both branches.
- **F-D (low-medium).** A signal before plan or record admission has no record to join (`orderedSteps` minItems 1), yet the prose makes the join mandatory. The owner must state the pre-record case. Also reconcile report04's "unrecorded render" ledger with `J-INTERRUPTION-STEPS`.
- **F5 (low).** Conditional provenance, as above.
