## 2. Owner decisions

- **Identity.** `$id urn:opensip:product-v1:workflows:evaluator3:report-projection:1`, `schemaFamily opensip.product.report-projection`, `schemaMajor 1`. The family string follows the existing `opensip.product.*` spelling rather than the P-5 sketch's `opensip.report-projection`.
- **Parity.** `envelope` is the complete `command-envelope:4` value and the **only** parity source. Its closed schema is untouched: check.py asserts `additionalProperties:false` and that no exploration member exists. The embedded value equals what the json renderer emits, with two differences only: `agentHints` is always absent, and `projectRoot` appears only under `pathDisclosure.mode=local-editor-links`. Neither is a parity field. Renderers read parity only at inventory4 `parityPaths` or fixed selectors. A panel never restates or overrides a parity value, so join keys are non-parity identities (`coverageId`, `comparisonResultId`, `planId`, owner `resolvedView.runId`).
- **Deltas from the P-5 sketch, all routine design choices:**
  - Every *applicable* panel is **required** as a state, and every non-applicable panel is forbidden. Absence therefore cannot be silent.
  - A history row is `{runId, run: AnalysisResult, findings, findingsProjection}`, not a nested CommandEnvelope. Nesting an envelope would force an invented historical `requestId`, termination and exit code.
  - Graph data is `{request, response}` pairs, so query context (endpoint, relation, direction, depth, view digests) is never lost.
  - Repair-preview recipe display reads the envelope directly and needs no catalog panel.
- **Asset binding.** The raw SHA-256 of the exact schema bytes is the `ReportAssetManifestV1.projectionSchemaSha256s` member. `check.py` prints it; any edit changes it.

## 5. Panel states and the three limit layers

A panel is `{state:"present", data}` or `PanelNotPresentV1`:

| State | Reasons | Meaning |
|---|---|---|
| `omitted` | `not-selected`, `exploration-budget-exceeded` | The host did not project it. |
| `unavailable` | `no-admitted-result`, `no-run-identity`, `evidence-expired`, `evidence-purged`, `evidence-missing`, `source-refused` (requires `detail`) | The source could not supply it. |
| `corrupt` | `retained-bytes-corrupt` | Retained bytes exist but cannot be admitted. |
| `incompatible` | `retained-schema-major-unsupported` | Retained data uses an unsupported schema major. |

Catalog `rules` and `capabilities` sections use the same wrapper. Whole-document shape or compatibility failure in the browser is a `report-data.ts` display error, never a degraded panel.

The three limit layers never merge:

1. **Source analysis.** Owner fields stay inside the exact owner records: graph `context.traversalCoverage`, `countBasis`, `truncated`, `totalItems` and `evidence` (coverageIds, scopeIds, deficiencyCitations, resolutionLimitations), plus native `coverage`, `resolutionCompleteness`, `closedWorld` and `deficiency`.
2. **Host projection.** `ItemProjectionV1 {total, omitted, omissionCause}` for prefix-limited lists, `GraphSlotV1.hostProjection.continuation`, and panel `omitted` states.
3. **Browser limits.** `budgetProfile.browserLimits`. Applying one is `view-state.ts` presentation state with a visible disclosure. It never alters data, counts or completeness.

A blank coupling cell, a missing path or an empty table is shown with its layer disclosures, never as a global absence proof.

## 7. Catalog translation and provenance

The catalog is a new private host display projection.

- **Rules** are exact `policy-document:2 Rule` records from the Run Plan's effective policy, with `source {kind:"run-plan-effective-policy", planId, policyDigest}` and `gateSeverityAtLeast`.
- **Capabilities** are the exact `ReleaseCapabilityRegistryV1`, with a report-local `registrySha256`.
- **Descriptions.** There is no free-text description field: no admitted description owner exists, and the component-manifest `displayName` schemas are `CANDIDATE-NOT-APPLIED`. Views show ids, severity, gate, enablement, subject enumeration selectors, message codes and language modes.
- **No permission.** A row confers no execution, grant or selection permission, and the browser offers no action on it.
- **Recipes.** Repair-preview recipe rows are the envelope's `RecipeRef` and `recipeTrust`. No recipe description or parameter catalogue owner exists.
- **Statistics.** Historical run statistics have no owner and are not shown.

## 8. Budget profile (UQ-1): development limits, not measured performance

| Constant | Value | Derivation |
|---|---|---|
| explorationMaxCanonicalBytes | 4194304 | Accepted exact codec `MAX_BYTES` (canonical.py and trial `exact-json.ts`). |
| maxGraphItemsPerSlot | 1000 | graph-query:3 `Bounds.maxPageSize`. |
| maxGraphSlots | 6 | floor(4194304 / (1000 × 635)), using a 635-byte constructed GraphNeighborRow. |
| maxEvidenceEntries | 3956 | floor(4194304 / 1060), using the 1060-byte CoverageResultV3 witness. |
| maxHistoryRuns | 1 | The only selected history source (audit baseline source Run). |
| maxHistoryFindingsPerRun | 5526 | floor(4194304 / 759), using a 759-byte constructed realistic FindingSurface. |
| maxCatalogRules / maxCapabilityDeclarations | 512 / 128 | Owner maxItems. |
| envelopeMaxCanonicalBytes | 83886080 | 100000 envelope4 findings × 759 B, rounded up to a 16 MiB multiple. |
| documentMaxCanonicalBytes | 88145920 | Envelope ceiling + exploration ceiling + 65536 root allowance. |
| maxJsonDepth | 38 | Accepted depth 32 + the largest embedding gain (6: graph request/response, capability registry). |
| budgetOmissionOrder | history, graph, evidence, catalog, comparison | Whole-panel omission when exploration bytes exceed. |
| browserLimits | nodes 2000, edges 4000, table rows 500 | Development presentation defaults. |

check.py recomputes every derived value from the pinned owners and the validated construction samples, and fails on drift. The prototype's 8 MiB graph cap, 2 MiB impact cap and 20-run/20-session windows are **not** inherited; they are measurement cases only.

**Why the report profile exceeds the accepted 4 MiB / 32 codec.**

- **Bytes.** Envelope4 admits 100000 findings, while only 5526 realistic findings fit in 4 MiB. check.py builds an 8000-finding envelope (5440794 bytes) that the accepted codec refuses (`BYTE_LIMIT`) and the report profile accepts. Truncating required parity to fit is forbidden, so the envelope needs its own ceiling.
- **Depth.** An owner record admitted at depth 32 in its own document sits deeper when embedded. check.py admits a PolicyDocumentV2 whose rule has a 27-level `not` chain under depth 32; the same rule in a report is refused by the depth-32 codec and accepted at 38.
- **Scope of the change.** The accepted codec is unchanged for its callers. The report profile is a separate parameterisation, and its owner is registered under RP-OBL-3.

**Exceeding a limit:**

- **Required parity.** Never truncated. An envelope above `envelopeMaxCanonicalBytes`, a missing required panel state, a shape-invalid document or a projection exception is a required-delivery failure: `operational-failed`, exit 4, `faultCause=delivery-required`, `DELIVERY.REQUIRED_FAILED`. The detail is `DELIVERY.RENDERER_FAILED_AFTER_COMMIT` with the committed RunId, or otherwise `DELIVERY.REQUIRED_PROJECTION_FAILED` with no RunId. JSON output limits are unaffected.
- **Exploration.**
  - Item limits prefix-truncate only evidence entries and history findings, with `ItemProjectionV1` counts.
  - A graph page is embedded whole: the request's `page.size` bounds it, and a following cursor is `not-embedded`.
  - Slots beyond 6 are never projected.
  - If canonical panels still exceed 4194304, the host replaces whole panels with `omitted/exploration-budget-exceeded` in `budgetOmissionOrder` until they fit.
  - History selection is never widened and latest is never substituted.

**Measurement plan (RP-OBL-2, M4 report integration lane).** Measure the actual built single-file report, with network blocked, on the selected machine platforms and a pinned browser.

- **Scale points:** envelopes of 0, 1k, 5.5k, 25k and 100k findings; graph panels of 1×100, 6×1000 neighbor rows and a 64-hop path; evidence of 100 and 3956 entries; the prototype 8 MiB graph / 2 MiB impact / 20-run cases, used as comparison cases only.
- **Metrics:** HTML bytes; parse + exact-codec + generated shape-validation time; first meaningful render; peak memory; graph layout time at `browserLimits`; keyboard and focus responsiveness.
- **Outcome:** a reviewed qualification record confirms or replaces each constant, as a new `profileId` and schema major if any shape constant changes. Until then no constant is a performance claim.

The reference Python validator took about 16 s on the 8000-finding case. That is a reference-tool cost of `uniqueItems` in jsonschema, not a product measurement.
