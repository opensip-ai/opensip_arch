# Planning evidence

`baseline.json` pins the actual architecture/product state inspected during drafting. It includes all selected contract records and key product schema copies. It grants no standing and must be refreshed in a new review subject if selected parents change.

`capacity_shape_spike.py` reads the native capability matrix and serializes synthetic request-field projections. Run from the architecture repository root:

```sh
python3 -I -B docs/implementation/fallow-expansion/evidence/capacity_shape_spike.py
```

`capacity-shapes.json` is its observed output. It uses canonical JSON settings with ASCII paths and eleven `ts-tsconfig` capabilities. It does not construct a complete schema-valid analysis-spec, execute OpenSIP, measure memory/time, derive framework qualification, or establish the final supported envelope. The record byte ceiling, maximum individual path length and capability cardinality are separate axes.

At the baseline, the inspected product identity schema has the inherited 1,024-row request limit, 128 distinct native contexts and 256 Plan imports. The selected contract record inventory contains no passage overrides for native lines 4276/4278/4280. RUST3-LIM's selected reference transport means the inherited Rust inline subject limit must not be reported as a current negotiated-provider file ceiling. Read selected successor semantics when deriving each transport bound.

A fresh-reader check of the planning package found baseline drift, unconditional branches and wording that could imply owner assent. Those drafting defects were corrected. Reader comprehension is not independent normative design acceptance.
