## Required contents of each reviewable design subject

- Exact selected parent paths, bytes, SHA-256 and selectors, including bound successors affecting the same fields.
- Complete replacement schema/reference files where required, exact before/after passage overrides elsewhere, and declared scope/supersession.
- Total algorithms and closed field/capability vocabularies; no unspecified fallback or reviewer discretion.
- Positive cases, hard negative lookalikes, missing/incomplete cases, exact-bound/+1 controls, identity-change cases and independent expected answers.
- Historical replay and baseline behavior; explicit public/protocol/closure version assessment and migration or negotiation rules where needed.
- Qualification additions: rule×language×mode strata, answerability and recall, explanations, resource workloads and exploratory separation.
- A machine-readable subject manifest and checks; an actual independent reviewer verdict bound to that manifest; the authorized lead's assent.
- Code ownership/inventory delta and dependency plan identifying accepted, in-flight and not-started consumers.

Use the existing contract-successor and inventory machinery. Fresh-reader checks on these planning documents do not grant `ACCEPT-DESIGN-UNIT`. Bind only accepted exact bytes after the real verification tool passes with actual review/assent records.
