# C2PM-1: signed component closure-major declaration

Proposed successor, not existing law or owner assent. This unit resolves the component-manifest source of `closure2.protocolMajor` left open by CR-1 and M3-C item 7. It changes no core-inventory projection, identity hash recipe, command authority, compiler/resource association, launch gate, historical admitted bytes or standing. Full C2a and M3 remain incomplete.

## Declaration and validation boundary

The signed component-manifest body may carry exactly the top-level member `closureProtocolMajor`, a positive signed-64 integer in `1..9223372036854775807`. It is not a field in `compatibility`, the envelope, catalog metadata, a caller descriptor, environment or file path. The successor completion adds exactly that optional root property to CR-1's selected complete manifest schema; root required fields, closedness, role branches and all other schema values remain equal. No manifest-schema version bump or historical-reader dispatch is selected.

Absence remains lawful for ordinary M2 manifest/body validation, including `validate` and `validate_inventory`. Presence is mandatory for **every newly admitted M3-C2a component closure projection**. Shape/body validity, `InventoryBody`, and signature verification alone do not confer native closure admission. The one authenticated signed path remains required: verified body/envelope/catalog, selected platform and retained tree, existing names, capabilities, permissions, field-use and identity joins. No caller flag can choose historical admission or bypass a current projection requirement.

Present values must pass the existing raw metadata integer parser before shape validation. Decimal or exponent spellings such as `1.0`, `1e0`, and `10e-1`, booleans, null, strings, zero, negatives and signed-64 overflow refuse under their existing parse/shape ownership. A mathematical JSON Schema engine alone does not prove the lexical integer duty. Identity's wider `protocolMajor` type remains unchanged; this signed input is a narrower source domain.

For role `analyzer`, when present, `closureProtocolMajor` must equal the same authenticated body's `compatibility.providerProtocol`. This is a new explicit cross-field consistency rule, applied in the shared semantic owner to **both** full host validation and inventory-body validation. It compares declarations, not compatibility windows. Absence does not trigger it. This successor extends DR-103 RJ-6 by the scoped semantic subcode **`CLOSURE_PROTOCOL_MISMATCH`** under `REFUSE_MALFORMED_MANIFEST`, solely for this present analyzer inequality; it is distinct from structural `MISSING_REQUIRED_FIELD`. Preserve a distinct private predicate discriminator `ClosureProtocolMismatch` for this failure within compatibility validation. Existing `Error::Compatibility` failures for hostCore constraints and manifest-version consistency keep their current meanings and routes; translating every Compatibility error to the new key is forbidden. No new public error code is added. Where the host translates this authenticated release-declaration failure into a termination, it uses the origin-sensitive registry below. Body-only validators return their validation failure and do not manufacture a workflow termination.

The C2a projection independently rechecks authenticated presence and analyzer equality. It copies that exact integer into descriptor `protocolMajor`; no normalization, inference, default, provider-major copy for absence, conversion, compatibility epoch or role switch changes the source. `manifestDigest` remains SHA-256 of the authenticated body bytes, envelope excluded. Republishing the field changes signed bytes, digest, catalog/signature associations and derived closure identity; it does not rewrite a retained historical object.

## Role interface meanings and supported resource declarations

The following four role interfaces and supported major `1` for each are **new explicit selections in this proposed successor**, never claims about existing artifacts. They are independent role-keyed interfaces, not a shared ABI or compatibility epoch. Publishers declare their actual interface in authenticated release metadata; a host never adds a declaration to old signed bytes. The host owns the interpretation contract and support selection. Any incompatible change to the interpretation contract requires a separately reviewed successor selecting another major and its support/migration rules; a publisher cannot make an unsupported major supported by declaring it.

| Role | Meaning of the declared resource interface | Initially supported major for new C2a projection |
| --- | --- | --- |
| `toolchain` | Interpretation and admission of the retained compiler/tool bundle under existing executable-member inventory, compiler identity and closure-shipped data duties, including published `baseCfg` ownership. | `1` |
| `stdlib` | Interpretation and admission of the complete retained declaration-resource inventory and the published `libSelection`-to-component joins. | `1` |
| `rust-dev-llvm` | Interpretation and admission of retained compiler-development/LLVM resources and their existing association with the selected compiler/toolchain. | `1` |
| `grammar` | Interpretation of the retained grammar bundle by the core syntax owner under its declared syntax classification duties. The grammar remains closure-only and produces no facts or worker session. | `1` |

These definitions create no new member list, compiler/LLVM matching algorithm, adapter, parser, resource format or executable entrypoint. Existing resource/identity joins are required separately. If those owning definitions are missing, a major declaration does not fill them or admit a resource. Two resources of the same major may be incompatible under those joins. Artifact/release-byte changes may preserve an interface major while changing closure identity.

Analyzer majors are supported only under the already selected named analyzer role subprotocol and its existing provider/native compatibility rules. This successor adds no analyzer protocol, window or numeric support union: in particular it does not treat provider/control/state numbers, TypeScript and Rust wire versions, or equal numbers from different roles as interchangeable. An analyzer lacking an applicable selected subprotocol cannot obtain new native admission from this field.

## Refusal predicates, origins and real public carriers

`closure-protocol-routes.json` is the reviewed additive extension to native-evidence §10's closed `x-opensip-public-route-registry`: add its four keys; preserve every existing key/mapping and closed public D9/common vocabulary. The existing schema registry and this extension together are the selected registry for these guards. Product materialization must merge the four exact rows, reject an unexpected conflicting row, and preserve all other schema values and accepted overlays. The four keys are **internal diagnostic keys**, not public detail codes. This successor adds exactly one public `DomainDetailCode` member, `native.closure-protocol-invalid`, through its exact successor public-detail registry and common-schema copies. No D9 error-code/class/fault vocabulary changes. Existing `HOST.INVARIANT_VIOLATED` is reused only for actual host bugs.

| Internal key | Predicate at the new closure projection/admission boundary |
| --- | --- |
| `native.closure-protocol-declaration-missing` | The authenticated component body has no top-level declaration. M2 body validation may still succeed; no new C2a closure is minted. |
| `native.closure-protocol-analyzer-mismatch` | A present analyzer declaration differs from the authenticated body's provider-protocol declaration. This includes the shared body-semantic check described above. |
| `native.closure-protocol-unsupported` | A shape-valid declaration is unsupported for that role under the selected resource table or applicable already-selected analyzer subprotocol. |
| `native.closure-protocol-descriptor-mismatch` | An input or recomputed descriptor's `protocolMajor` differs from the declaration of the authenticated body it purports to project. |

Existing parse, shape, trust, body-semantic, tree/platform/role and field-use prerequisites keep their owning refusal order and must succeed before this new projection guard set. Its deterministic order is **missing declaration, analyzer inequality, descriptor mismatch, unsupported major**; select the first failing predicate and mint nothing. Shape-invalid present values never become missing/unsupported errors. A descriptor that mismatches a declaration which is also unsupported yields descriptor-mismatch. Analyzer inequality is already rejected by shared body validation; the projection recheck preserves the same specific predicate if an inconsistent layer reaches that boundary. No precedence for unrelated owning checks is silently replaced.

The host carries actual provenance, never a caller-provided origin label. Missing, inconsistent or unsupported **authenticated release declarations**, and retained/supplied descriptors of **known external origin**, reject with class `request-rejected`, error code `REQUEST.PRECONDITION_FAILED`, exit `2`. A host **bug** minting its own invalid internal descriptor/declaration layer uses class `operational-failed`, error code `SYSTEM.OUTCOME.ILLEGAL_STATE`, `faultCause: host-invariant`, exit `4`. Calling a projection function on externally supplied signed bytes does not turn an invalid release declaration into a host bug. Conversely, a mismatch the host introduced while copying its own descriptor is not laundered into an external precondition failure. An unknown or impossible origin is refused by the derivation rather than guessed.

Each route derives a real workflow `StepTermination`; its `domainDetail` is absent, not null or a new string. The internal key remains in the operational diagnostic record. The existing envelope-errors composition stays in force: the pre-Plan **failure CommandEnvelope** carries its allocated request id, termination, derived exit, and exactly one `errors` DomainDetail. Its public code is `native.closure-protocol-invalid` for the two known-external origins and `HOST.INVARIANT_VIOLATED` for a host bug. Its subject is the bounded internal decision key under the existing native subjectBoundLaw, never a raw manifest/body preview. `public-detail-extension.json` and the complete registry/common candidates publish the new member. The exact code-keyed remedy for the external code is: “Select a component release with a signed role-supported closure protocol declaration consistent with its required joins; for a retained descriptor mismatch, supply the descriptor projected from that signed body. Never patch retained signed bytes.” This remains a true next step for all four predicates; no per-key remedy table is introduced. Host-invariant keeps its existing remedy: “the host produced an invalid internal record; report the defect with the retained diagnostic”. Declarative registry `domainDetail:null` means OMIT termination.domainDetail; `envelopeDetail` is a PUBLIC code, not a diagnostic key. Do not fabricate a Run envelope, or suppress the required errors array because the termination carries no detail. No `runId`, `plan2`, `run3`, worker spawn or native identity is minted by a failing new pre-Plan admission. These rules do not replace provider handshake faults, context/resource joins, Run-closure duties or the routing of faults at other owning boundaries. Historical Run/closure inspection remains under its authenticated applicable admission contract, not a public switch into this new minting path.

## Migration, materialization and remaining gates

New readers can validate old absent-field bodies. Old closed-schema readers reject new-field bodies; reverse compatibility is not claimed. Publishers must target a host/reader that supports this successor and make ordinary signed publication associations. Existing captured manifest shape/semantic oracle bytes and verdicts remain unchanged for absent-field cases. No historical patch, relabel, rehash, automatic backfill, unsigned descriptor, fixture-only trust path or unverified reconstruction is permitted.

`materialization-map.json` replaces CR-1's schema selection prospectively for this field and records current exact product source pins. It preserves CR-1's role, command, entrypoint, naming and trust duties. C2a updates the private security schema input/pin/generated shape, shared semantic validation, authenticated projection and the four native route-registry rows, the one public-detail registry extension, exact common-schema enum additions and the code-keyed remedy/envelope mapper together with required controls. Updating the native registry owes its ordinary source/admission-map repins and generated table reproduction; updating the private security input alone does not. No global registry repin is invented for the private manifest input.

Law acceptance and a separate design-lock bind do not implement C2a, put L into effect, satisfy native publication/launch gates, admit artifact bytes, freeze a T1 lane or qualify the product. Full C2a still owes exact signed-path, retention, platform/tree/role/field support, deterministic projection, fixture/release-boundary controls and its accepted dependencies. The reference audit in this unit tests schema preservation, exact one-member public-registry/common extensions, real public termination AND complete failure-envelope compatibility, required errors and code-keyed remedies; it is not authenticated product execution.
