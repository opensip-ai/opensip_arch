## Proposed package key

For Rust native records, propose `pkg1-` followed by lower-case raw SHA-256 of C([name,version,sourceId]), using exact admitted Cargo.lock values and the existing null-source/path rule sourceId="". Retain the full canonical tuple with the key. Native PackageKey is this bounded 69-byte opaque spelling, never an ambient Cargo package-id string, path, display label or delimiter concatenation. Recompute from the retained tuple before every semantic join. Equal keys with unequal tuples are a contradiction, not deduplication. Different sourceIds distinguish equal name/version packages.

The host retains a total activated-package table connecting each bundled Cargo observation to its admitted lock tuple, its selected source, and its admitted source file-manifest. Cargo's id is an acquisition/observation join only; path-bearing id text never enters PackageKey or another content identity. No tuple is reconstructed by splitting a package-id display string. Publish the pinned adapter's exact output fields and matching rules before implementation; this packet is not that missing producer contract. Null/missing/conflicting sources cannot be silently normalized except the already named path sourceId="" rule. One observed package must match exactly one admitted tuple. Duplicate or ambiguous path-package name/version tuples cannot be disambiguated by host path; the final successor must choose a representability refusal or explicitly extend the descriptor under review.

## Proposed native owner key

Retain the source and full package-key witness and verify both hash recipes. This does not redefine unrelated security test-runner or workflow owner vocabularies. Do not choose a source by lexical priority or equal bytes.

## Dependency mount collision

Keep the published .opensip/deps/v1/<name>-<version>/... mount for representable sets. Require every constructed stem to satisfy the existing single-segment LogicalPath and length rules before materialization; slash, dot/dot-dot, NUL, backslash, overlong or otherwise nonrepresentable names never form a mount. Do not percent-decode, normalize or sanitize them into another stem. Then check the exact constructed mount stems for uniqueness across different admitted package tuples, including spelling collisions from name/version concatenation. This check is over the actual activated admitted set before its worker materialization. It does not prune candidates before Cargo decides activation. If two distinct tuples produce one stem, refuse the requested native dependency materialization; do not choose one source, overwrite bytes, merge equal files or silently change the mount. This is a proposed explicit restriction, and the complete successor must assess the supported population/capacity effects and publish a provenance-aware failure composition. Alternatively changing the mount to include PackageKey would require an explicit native passage successor and updated worker/replay interfaces. This packet recommends refusal as the smaller worker semantic change but claims no existing authority for it. The full successor must separately publish how all route-admitted acquisition candidates are materialized whole before activation, retaining source distinction in adapter scratch and in the explicit acquisition namespace. A final worker collision policy cannot stand in for that missing preactivation mapping; inactive candidates are not silently skipped and acquisition counters/order remain unchanged.
