# Proposed complete Cargo projection key records

Lead preparation, 2026-10-10. UNREVIEWED and UNBOUND. Proposed full-profile content only. It changes no accepted schema, source, identity preimage, member admission, exception list or public route. Existing carrier limits remain 64 honored keys, 64 stripped keys, and 256 Unicode scalar values per key record as the current JSON Schema maxLength specifies; the independently selected canonical-byte bound remains separate. No new byte cap is selected here.

## Proposed representation

Represent a real parsed key path by its actual case-sensitive segments. A nonempty segment composed entirely of pinned Cargo/TOML bare-key characters A-Z/a-z/0-9/underscore/hyphen appears unchanged. Every other segment, including the empty string, is a canonical JSON STRING literal with the existing first-party canonical string quoting/escaping rule; join successive named segments with one dot. Do not use JSON canonicalization on the projected TOML file; NCP1 selects its different artifact.

Where a named key is inside a list's table value, include each actual zero-based list position as `[n]` between path segments, using decimal integer text without leading zeros. A scalar list element is a value, not a new named configuration key. Traverse nested lists to find any real named descendants. No wildcard, ellipsis, range or broad subtree placeholder is manufactured. A literal `*` key is quoted and stays literal.

This preserves ordinary records such as `build.rustflags`, `resolver.incompatible-rust-versions` and `source.crates-io.directory`, while distinguishing a literal dotted name (`"dot.key"`) from a nested table path (`dot.key`), an empty name (`""`) from absence, and literal index-looking names from actual list positions. Quotes, backslashes, controls, Unicode and empty strings receive one exact representation; there is no Unicode normalization, case folding or environment-name transformation.

The existing Cargo diagnostic escape_key_part function is interpretation evidence, not the proposed public artifact: its all-characters bare check treats an empty name as vacuously bare, and its generic TOML Value display is not an independently selected public key notation. Do not merely copy a human diagnostic spelling and claim complete key identity.

## Proposed population and classification

Enumerate every real named key in the effective fully converted/merged original configuration before semantic projection, including actual table-container keys and all named descendants. This is the effective merge population; it does not inspect keys in an unused current-spelling file or silently load files outside selected original discovery. Non-mergeable lists retain their pinned effective values rather than resurrecting replaced values. Definitions and original bytes remain separately associated, not encoded into these public key strings.

Because NCP1 strips each original include before merge, additionally enumerate the actual named key paths of every include value removed from a selected original document before merging. These paths refer to those stripped original directives; list indices within them are their own original directive positions. Their unique path union is disclosed as stripped. Repeated path occurrences across selected documents appear once, as the existing uniqueItems carrier requires; this does not claim one value occurrence or interchangeable document provenance. This exception supplies no include read or effective merged include value.

For semantic projection, a value leaf is honored only when the separately selected exact member/value/path/flag rule retains that key and its value after the selected transformation. Individual rustflag operands remain governed and disclosed through RustflagsProjection; they are not invented as additional configuration keys. Otherwise its actual key and all actual named descendants are stripped. A table-container key is honored structurally only if its retained projected subtree contains an honored descendant; a wholly removed container is stripped. A mixed retained container appears in honoredKeys while its removed real children appear in strippedKeys, not as the same path in both. Empty unhonored containers remain actual stripped keys. Exact whole-member rules for resolver/source/registry/target/rustflags remain their own authorities; this draft admits none by name or shape.

After complete classification, require that the two path sets are disjoint and each path has exactly one classification. Sort each complete unique encoded path set by Rust str Ord to produce its sequence. Every actual encoded key must satisfy the unchanged carrier length bound, and both complete populations must satisfy their existing count bounds. Do not discard late keys, crop an overlong name, drop an empty segment, coalesce literal dots, replace a subtree by a wildcard, treat a empty policy catalog as permission to drop every value or continue with partial output. Failure keeps its original association and awaits the complete origin-sensitive public projection; this draft selects no default code.

## Required independent controls

Before native use, compare exact reference strings for ordinary names, literal dots versus nested paths, empty segments, quotes/backslashes/controls/Unicode, literal wildcard/index-looking names, actual indexed table descendants and nested lists. Test deterministic sequences under every relevant insertion permutation, repeated key paths from distinct documents without provenance collapse, mixed honored/stripped containers, non-mergeable replaced list entries, include keys captured before suppression, and unused current-spelling configs never parsed. Test exact64/one-over65 populations, exact256/one-over257 Unicode-scalar key lengths after encoding, distinct UTF8-byte versus scalar counts and canonical record capacity. Every refusal must occur without a truncated key population or fabricated successful record.
