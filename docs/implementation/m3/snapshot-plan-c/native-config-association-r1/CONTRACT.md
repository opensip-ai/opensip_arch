# Proposed original snapshot configuration discovery and definition association

Lead preparation, 2026-10-10. UNREVIEWED and UNBOUND. This is proposed full-profile content, not an existing capability or an implemented discovery/read owner. It grants no live project, original host ancestor/home, source carrier, signed Tool or owner admission. Earlier accepted fixture observations and supporting constructors remain closed.

## Two exact populations

The original input is the complete admitted retained snapshot sourceInventory for the actual native attempt, its owning immutable blob-read capability, and the actual admitted invocation working-directory association within that snapshot. A pathname, bytes, digest or caller-provided Definition alone is insufficient. The complete profile must join this association to the selected workspace/manifest/request, rather than accept an arbitrary cwd selected by the child. This proposal supplies no fallback cwd or new invocation argument.

For effective config merging, walk the admitted original logical cwd and each original logical parent through the admitted snapshot root inclusively, nearest first. At each directory select its retained `.cargo/config` if present; otherwise its retained `.cargo/config.toml` if present. When both exist, legacy wins even when malformed; no retry or fallback to the current spelling. This selection uses the sealed complete inventory, not reads of current live original paths, scratch ancestors, ambient process cwd or sorted global filenames. Read each selected retained blob only through its actual owning capability with the same admitted digest/length/observation checks. Original input parse/merge order is the selected directory walk order.

No original host Cargo-home config joins this population. The selected native home is the invocation's fresh private empty home under CC2/CENV1, which has no original configuration file to merge. Do not inspect the caller's Cargo home or HOME to discover an additional original file. Empty home is an actual owned construction fact, not a magic path string. CC1's actual checks on every scratch-root ancestor remain separately mandatory before invocation, including ancestors above the snapshot materialization: bounded original discovery is not a claim that stock Cargo has a switch disabling ancestor reads.

For CC5 replacement, use EVERY retained snapshot regular file whose final two segments are `.cargo/config` or `.cargo/config.toml`, in the actual complete inventory order. Include both spellings when both are retained and locations not visited by the effective walk. This population is distinct from the selected merge documents. Each replacement receives the exact same projected artifact bytes. No discovered winner count, ignored loser, package subtree, filename coalescing, content deduplication or list truncation substitutes for the full replacement census. The existing 4096/location and logical-path bounds remain unchanged; an unrepresentable complete population cannot become partial admitted input.

Only actual retained eligible snapshot bytes exist for this native association. Files absent from the admitted complete retained inventory do not become live reads or borrowed source authority. Excluded/symlink/special/pruned/outside entries cannot be added by discovery. Whether an absent independently required manifest/source makes the attempt incomplete remains its separate owning rule; optional absence of an original config is not proof of a required source absence. An incomplete, corrupt or foreign snapshot cannot assert trustworthy absence.

## Definitions and relative interpretations

Assign each completely parsed selected document its own original logical file association and preserve it for every scalar, table and individual list element under pinned Cargo conversion/merge behavior. Equal Definition kind or equal config bytes do not equate origins. The original root for a `.cargo/config(.toml)` file is the logical directory containing `.cargo`, as pinned Definition::root specifies; it is not the projected file directory or the compiler process cwd.

The compatible initializer must map each original logical association to that same attempt's actual retained snapshot view at the point a path is interpreted. This is an owned association operation, not string substitution in semantic projected bytes. Resolve a relative directory only through its real original root, then validate the resulting source/target/read population under the separately owning selected rule. Do not add read authority because a path is absolute, normalize raw URLs/lock tuples, move one equal-byte file between attempts or infer source admission from the logical root. Operational scratch paths remain outside existing identity preimages.

Bound NCP-1's include suppression removes each document's include value after complete conversion and before merge; it cannot extend this read population. NRC1/CRA1 and the remaining exact honor/strip rules retain their own member/path/value checks. A complete resource-bounded parser, truthful all-key accounting, deterministic projected bytes, actual once-only initialized context, source/input/Tool correspondence and the full origin-sensitive public failure map remain required. This draft does not select a default public code for parse, merge, custody, population overflow or owner-association failure.

## Evidence required for full implementation

Actual controls must prove all of the following through the owning retained snapshot/read implementation, not supplied PathBufs or labels: legacy precedence and no malformed-legacy fallback; malformed unused current spelling not parsed; nearest scalar versus ancestor-prepended repeated list with original per-element roots; root-inclusive stop and denial of ambient outer/home inputs; complete both-spelling/unvisited replacement census; independently absent optional config versus missing required source; excluded/unretained paths never read; immutable same-observation digest/length checks; equal-byte foreign snapshot/config substitution refusal; two operational scratch roots yield identical semantic bytes and identities; late list/key/location overflow never truncates; and actual initialized producer consumes the complete construction once with subsequent disk/include reload forbidden before IO.

The previously accepted eight discovery fixture controls establish only stock behavior under private fixture roots. They do not supply these owned controls. This draft reuses that evidence by reference without reopening it. The actual production snapshot/cwd/read capability and complete native source/profile/owner/Tool/worker/publication/qualification gates remain open.
