## Exact algorithm

The serializer consumes the complete already semantically projected Cargo ConfigValue TABLE. It does not discover/read/parse original files, decide honor versus strip, validate source paths or select tools. A non-table document root refuses before serialization.

Recursively convert ConfigValue into toml::Value. Integer, string and Boolean preserve their exact typed value. Convert every list item in the existing effective order, retaining repeats and nested values. For every table independently, sort its complete actual key strings by Rust str Ord, insert them into the preserve_order TOML map in that order, and convert each corresponding value. No locale comparison, Unicode normalization, case folding, deduplication, wildcard key, path rewrite or additional sort of lists occurs.

Call this pinned toml::to_string exactly once on the converted table. The projected file is the exact UTF-8 bytes returned by that call: no prettifier, additional newline, trim, byte-order mark, line-ending rewrite, escape substitution or postprocessing. This artifact determines actual quoting, escaping, integer/Boolean text, Unicode spelling, table/array syntax and newline behavior. The empty table's exact bytes are an empty file; it is not absence of the required projected artifact. The raw artifact digest is SHA-256 of those exact file bytes under the existing rule, while the complete CargoConfigProjectionV2 record retains its distinct H identity. Do not relabel a semantic round-trip as an exact-byte digest proof.

Table sorting is deterministic construction before the chosen serializer, because the pinned Cargo TOML dependency enables preserve_order and Cargo ConfigValue tables use HashMap. Passing HashMap iteration order directly to serialization would not be this artifact. JSON canonicalization is not used for the TOML file.

## Definitions, resources and failures

Original definitions stay in the host-owned association and the exact compatible initializer. They are not stringified into projected bytes or replaced with the projected file's physical pathname. The file alone cannot reconstruct original relative-path roots. Equal file bytes under two original roots do not admit interchangeable inputs or owners; the actual owning producer must consume the full correct definition association once. This proposal chooses neither that owned path mapping nor the public key-record representation/order.

Full original parsing/conversion and semantic projection precede this serializer. No invalid original value becomes acceptable through coercion or serialization. An actual serializer failure retains its owned phase and original association; no new public code or generic input-incomplete route is selected. No partial bytes become admitted output. Actual write/retention/cancellation/IO faults remain separate owners.

The source ConfigValue tree, converted TOML tree, serializer buffers, output bytes and projected replacement copies all have real simultaneous storage lifetimes. This algorithm alone does not bound them or price allocation/write work. The unchanged D5 working/materialization envelope, charge-before-write requirements and compatible parser/merge/serializer resource publication must cover actual use. No per-file or total new numeric cap, free control-storage allowance, output-fd1/input bound substitution or root-copy discount is inferred. A complete native profile remains unpublished until those obligations and the origin-sensitive refusal map are selected and implemented.
