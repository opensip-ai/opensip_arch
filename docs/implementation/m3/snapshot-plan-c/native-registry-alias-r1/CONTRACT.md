## Exact honored family

For new-M3 native Cargo configuration, `registries.<name>.index` is honored as a static manifest-registry-name to original index association, conditional on the actual host-owned, admitted configuration/current workspace observation. All other `registries` keys remain stripped and disclosed under existing CC-5; the entire `registry` table remains stripped. Tokens, credential providers and aliases, protocol/default selection and authentication/execution/network controls are not admitted by this exception. The existing honored keys, rustflags allowlist, executableSelected=false and CC-1/CC-2/C-ENV1/CC-3/CC-4/CC-5 obligations remain unchanged. No ambient configuration or environment lookup is authorized.

The association uses exact Cargo 1.95 commit f2d3ce0bd7f24a49f8f72d9000448f8838c4e850 semantics, not a new regex or arbitrary URL parser: `RegistryName::new` calls `restricted_names::validate_registry_name`; `GlobalContext::get_registry_index` looks up that name's index and `resolve_registry_index` parses it with its actual configuration definition root and rejects a password; `SourceId::for_alt_registry` interprets the resulting original registry/sparse source. Registry names include the pinned Unicode XID rules, not an ASCII approximation. This is a name association, not a registry authentication claim.

The compatible profile must supply the actual admitted configuration definition/root association, with the same selection and URL interpretation Cargo would use over those admitted inputs, before using this key. Copying raw relative `file:` URL bytes into a differently located projected file does not prove that association. An absolute temporary mount path must not enter the raw lock/pkg1/own2 or existing configuration semantic identity merely to make the association work. This narrow unit selects no relative-URL rewrite, new allowed protocol, configuration merge/precedence algorithm, per-workspace projection, default protocol policy or first-party GlobalContext override. Those exact complete profile choices and their failures remain publication prerequisites; unsupported/unproved association cannot silently fall back to a guessed URL, a discarded dependency or an ambient source.

The special `crates-io` branch and Cargo's default/protocol selection remain separately governed, not inferred from alternative-registry behavior or this exception.

Source replacements, overlays, workspace preload, patches and old/new source loads must pass the same gate. An index URL, alias, replacement directory, valid lock tuple or successful metadata process supplies no fetch/cache/Git/network authority or custody/authentication proof. CSJ-1 source equality/precise comparison, original raw lock source/pkg1, NSK-1 original-family/acquisition sourceKind and DS1/DS2/DS3 provenance remain unchanged.
