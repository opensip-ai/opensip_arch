# Collector prefix storage and copy proof r1

## Scope and hypotheses

This is a proposed conditional source argument for payload storage, no-growth and logical copy streams, including refusal cleanup. It does not establish the52F local or8E callback metadata allowance, node-storage/layout, scalar operand sizes, hardware/RSS/allocator internals, actual ABI or a complete M bound. Exact product/std/plan inputs are closed in INPUTS.json. Compiler/std source correspondence remains a trusted compilation assumption; no Rust was invoked. All references below name those captured files.

Consider the actual private Collector instantiated in component_admission.rs346–366. Its expected length L is the checked conversion of the same candidate Blob's u64 length. The candidate is immutably borrowed through the call. The vector starts empty with capacity at least L if construction returns. Execution is safe, single-threaded private mutable access; there are no callbacks that expose/mutate this Vec. The proof assumes standard successful Vec construction/extension semantics, excludes process abort/OOM and arbitrary UB, and counts source-level allocation requests rather than machine allocator events. Capacity overflow/panicking allocation is not a successful admitted result or a proved operational refusal; this argument does not newly qualify such paths. Successful funding occurs before these vector constructors.

## P1: Collector invariant and sticky failure

At entry to each callback, 0<=len<=L<=capacity. Construction establishes len=0. begin and finish never modify the vector. fail only fills a previously empty fault. Once fault exists, begin/chunk/finish return before any copy; into_verified returns that fault. A later callback cannot clear it.

In chunk, the fault branch returns. If !begun or finished, fail records Chunk and performs no copy. Otherwise the length check reads L-len, which cannot underflow by induction. If incoming k exceeds L-len, fail records Length and performs no copy. Otherwise k<=L-len<=capacity-len; extend_from_slice appends k bytes, resulting len'=len+k<=L. This proves the invariant for arbitrary callback order and arbitrary chunk sizes, including empty chunks and calls after finish. It does not rely on callbacks respecting a fixed read size or on digest correctness.

into_verified consumes self. It yields the sole Vec only when fault=None, begun, finished and len=L. Otherwise its owned vector is dropped with self; no borrowed byte slice or partial success is returned. finish(false) sets fault before marking finished. A wrong begin length/digest or repeated begin is sticky. Successful begin's32 digest iterations are real work but remain outside this storage/copy argument. Their metadata price is not inferred from P1.

## P2: No payload reallocation on any returned-prefix path

Selected std source: vec/mod.rs3499 calls spec_extend(other.iter()); spec_extend.rs selects the TrivialClone slice-iterator specialization for u8, obtains the slice and calls append_elements. append_elements at2877 invokes reserve(k), then performs copy_nonoverlapping for k>0 and increments len by k. RawVec reserve checks needs_to_grow, whose source predicate is additional>capacity-len (wrapping_sub, which equals subtraction under P1). Since k<=L-len<=capacity-len, the grow branch is unreachable for every accepted append. The argument includes wrong digest/finish or later transfer failure: prefix accepted appends have the same invariant and never grow.

There is at most one initial source allocation request per L>0 payload Vec; L=0 is nonallocating in RawVecInner::try_allocate_in because the layout size is zero. This is an upper bound on selected source request sites, not a measurement of underlying allocator requests/size rounding. No zero-length special price reduction is selected: the proposed F allocation allowance dominates.

## P3: Logical payload-copy streams and header-vector storage

For each collector, every append increases len by k and no operation removes or rewrites accepted bytes. Hence total copied bytes before extraction/drop is final len<=L. copy_nonoverlapping contributes one logical read stream and one logical write stream of k bytes, so the proposed2L allowance dominates both streams for every prefix. Callback argument construction/metadata are separate; hashing/CI's shared read buffer and kernel reads remain their respective owners. This is not a claim about machine loads/cache traffic or arbitrary memcpy implementations.

The outer payloads Vec starts with_capacity(F), and only the descriptor's F candidate Blobs can push one extracted Vec each. At any next push j<F, len=j<F<=capacity, so push's grow branch cannot execute. A transfer/collector failure pushes no new element and returns immediately. Thus there is at most one initial nonzero index allocation request, of F Vec headers, with at most F successful header placements. Conditional on the already-selected24byte Vec ABI,48F prices both logical streams of those payload-header placements. It does not price all transient header/collector moves; those remain metadata proof obligations and no copy-elision assumption is used to claim they are free.

## P4: Actual transfer delivery envelope

retained_tree.rs470–550 issues at most one begin and one finish per transfer invocation. A latched call issues only finish(false); a new failure issues finish(false), with no subsequent success finish. In this admission loop a failure exits before any later Blob. transfer_inner calls begin only after association, file type/mode/length checks. installation.rs565 read_verified loops with made checked against attempts before reading, increments once per attempt, and invokes the sink at most once for each positive read that survives the total-length and digest-update guards. Therefore chunks<=attempts and total delivered bytes<=L for a representable successful prefix, or Collector P1 itself independently bounds copied bytes if delivery is malformed.

The source's attempts=2*ceil(length/65536)+2 saturates in u64. For an actual candidate that reaches transfers, fund_representation has already checked the equivalent chunk and per-Blob envelope arithmetic in usize, checked its aggregate E, and successfully charged the full bound. On the selected LP64 target such checked arithmetic gives an exactly representable u64 result and therefore no saturation in the matching mathematical envelope. The captured open_retained_tree association loop at retained_tree.rs345–361 finds each candidate path in the retained immutable tree and rejects unless the selected File length and lowercase digest equal that Blob. transfer_inner selects the same path in that retained tree/order and reads the retained File length; safe private fields do not mutate between these uses. This step relies on the existing charged_find/component-ordered-index owner contract; it does not independently re-prove that lookup implementation. Under that existing owner contract the two envelope lengths match. Without that owner contract, P4 remains conditional; P1–P3 still bound each collector by its own expected L. No underpriced callback allowance is established here: the E chunk bound still leaves begin/finish and all metadata to a separate disjoint local/callback map.

## P5: Prefix ownership and cleanup

At most one current collector owns a payload outside the payloads vector. Each prior successful collector moves its sole Vec into payloads; it does not clone bytes. into_verified consumes self and cannot expose a second owned Vec. The map later borrows candidate paths and payload slices, and is dropped before payloads on normal success; refusal at K unwinds locals in reverse construction order. Transfer errors are mapped and propagated before into_verified, preserving the actual transfer cause and dropping the current collector then previous payloads. A collector-completion refusal also drops the consuming self and then prior payloads. No cleanup invokes a new work charge, append, payload clone or allocator growth through this production code.

Vec::drop drops initialized elements, then RawVec::drop releases its nonzero allocation. Dropping u8 has no user code; dropping the outer Vec drops each initialized payload Vec. Borrowed map keys/values do not own payloads. This establishes the ownership shape under ordinary safe Rust destruction, not measured release counts, panic-safety qualification, bounded destructor metadata cost or allocator internals. Existing retained CI capability/pin release remains its owner's rule and needs actual controls.

## Supporting finite model and remaining work

check_prefix.py is a dictionary state-transition model, not actual Rust. It explores arbitrary short callback schedules, including malformed begin/chunk/finish sequences, and independently challenges three intentional defects: append without remaining-length guard, copy after sticky fault, and extraction before completed state. The begin-good/bad event abstracts the full digest/length checks and does not execute their arithmetic. Extract events observe the completion predicate without consuming the model state; affine ownership follows from the captured Rust signature, not that model. A fourth reservation predicate control exposes a too-small capacity. It can find small counterexamples but cannot establish all-input source correctness, native allocation/layout, complete work price or unit acceptance. Review must inspect the correspondence and may reject the argument even if model controls pass.

No production/queued file, formula, cap, accepted authority, plan or qualification is changed. Next substantive work remains the exact disjoint operation/operand source map within52F and8E and the map operation table; queued ABI/allocator/native checks are separate evidence gates.
