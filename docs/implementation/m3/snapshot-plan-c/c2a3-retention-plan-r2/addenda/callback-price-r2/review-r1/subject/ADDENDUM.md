This draft funds an explicit source-stage inventory and is not a demonstrated native undercharge of the old value. No published or product bytes change in this proposal. The original complete M bound remains unestablished; plan/source acceptance does not establish it.

The proposed formula is M_edges=128+F*(237+23H)+16E; scalar_edges=M_edges-q, q=11FH. All object, allocation,2B payload-copy,48F header,2Pq comparison and10368F array-bulk terms remain unchanged. Fixed128 and prepaid scan12F stay unchanged; scan still consumes the same local64F, leaving52F. begin/finish metadata remains in that local reserve and is not funded twice by the chunk row. No blanket allocator/hardware price or profile-cap change is selected.

If accepted as a plan addendum, a later independently source-reviewed implementation delta changes the callback coefficient8 to16 in fund_representation and the independent category-table test oracle, then re-freezes source and native inputs as required. Current queued old-image compiler/storage jobs stay immutable and remain valid only for their old exact scopes. Existing tests need their actual charge assertions/mutations reviewed against the new exact formula; no old native result can qualify a new delta. Product/unit acceptance still requires full source/operand bound, meaningful runtime controls, source guard, native ABI/allocation/debit/lifetime/cleanup, feature/privacy/export and aggregate census/fit gates.

## Concrete source-stage inventory and limits

STAGES.json proposes16 disjoint stages for the successful chunk path, following Collector::chunk -> Vec::extend_from_slice -> slice::iter -> the u8 TrivialClone spec_extend -> Iter::as_slice/make_slice -> append_elements -> Vec/RawVec/RawVecInner reserve fast path -> copy -> len update. Rows explicitly include receiver/iterator/pointer/length/call argument streams; copy payload data itself stays2k. LP64 active-field widths are conditional. Compiler-created frame/register/cache copies and hidden allocator internals are not the logical source operation model. Source-level carrier/receiver/iterator transport may not be silently omitted: if review identifies extra such operands or stages, revise the ledger and price before claiming fit.

These are candidate operand totals, not established byte bounds. A reviewer must inspect helper bodies, including the slice iterator macro's make_slice/len path and reserve forwarding, and challenge whether each row captures every logical source operand and can be bounded64bytes. Builtin pointer arithmetic, reference/slice formation and copy intrinsics have their existing safe Rust semantic contracts as trusted inputs; no compiler/std binary correspondence or native layout is newly qualified. No new arbitrary primitive may conceal a variable loop or additional byte stream. The stage partition is deliberately explicit so its defects remain reviewable.

Collector prefix invariant len<=expected<=capacity and k<=expected-len selects only the reserve non-growth path. No allocator grow_amortized or error allocation is selected for accepted chunks. Existing conditional prefix proof supports this branch restriction, not the new metadata price. For sticky-fault callbacks, no data is copied. Invalid begun/finished or overrun branches call fail: its None-test and private fault assignment must be counted; candidate worst-case refusal metadata fits within the same16-visit allowance (even counting both as separate visits). No finish(false) cost is hidden in this chunk row. If conditional source stages do not support16, return findings, correct the draft, and preserve the prior subject. No fee can be integrated on the strength of an unchecked arithmetic report alone.
