## Recommendation

Recommend one source-aware adapter directory root per exact admitted original lock source identity, and one verified NKC-1 pkg1 child within that root per admitted package. A candidate spelling is src1- plus rawSHA256(C(sourceId)) for the source root; that is a NEW proposed operational locator codec, not accepted law or a semantic owner identity. Retain/recompute the full exact source text before locator joins; a digest is not source admission. No input origin shares a replacement root merely because name/version/content/directory bytes agree. Distinct original sources with equal name/version therefore stay in different DirectorySource tables. A package's observed manifest locator must join back to the exact admitted materialized package tree; source/id string agreement alone is insufficient. Preserve all acquired candidates' admission/rejection and all admitted candidates' whole materialization before activation.

Raw lock source distinctions can still project to the same Cargo source slot through its pinned URL/source semantics. The full selection must detect those actual slot ambiguities and publish an explicit disposition; separate hash strings cannot license duplicate Cargo declarations or choose a winner. Publish the exact lockv4 encoded-versus-metadata unencoded Git source serialization bridge recorded in evidence/pinned-source/SOURCE-ASSESSMENT.md, including precise revision and actual original source/manifest/activation witnesses. Do not normalize the semantic sourceId tuple, split Cargo ids, deduplicate packages, skip inactive candidates, or change raw/domain file-manifest recipes.

Keep snapshot path-package layout intact through the owning sealed materialization, with no import/fallback outside the snapshot. Cargo's directory-source requirement for a direct-child Cargo.toml and checksum file is a separate representation obligation. A complete source tree whose actual package manifest is nested cannot be silently cropped, hoisted, symlinked, rewritten or skipped to fit this layout. Any Cargo-compatible manifest/checksum view must be explicitly published with all exact original/derived bytes, identity/provenance/owner sensitivity and failure duties. An imported Git tree or an authenticated registry tarball is not automatically a ready directory-source carrier. This packet selects no fabricated checksum authenticity, Cargo vendor child, populated Cargo-home cache, HOME fallback, manifest projection or Git source restriction.
