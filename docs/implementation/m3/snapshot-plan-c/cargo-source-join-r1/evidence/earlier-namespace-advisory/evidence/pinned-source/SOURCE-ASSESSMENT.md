## Emitted fields and joins

cargo_output_metadata.rs emits version 1, packages, workspace_members and a resolve graph for the whole workspace. It starts graph traversal from every workspace member, not only default members or resolve.root. With --filter-platform it selects requested/host dependencies according to bundled target data. The package array is restricted to nodes present in that graph; this is not authority to prune acquired candidates before admission/materialization. MetadataResolveNode has id, dependencies, deps and features; dep.pkg refers to the same normalized PackageIdSpec spelling as package.id. The source explicitly normalizes resolver IDs to package IDs because caller comparisons are opaque string equality. A reader must not split/reconstruct the id spelling or use it as a semantic identity.

package.rs::SerializedPackage emits name, version, id, source, manifest_path, targets, features and other metadata. serialized uses the actual PackageId name/version/to_spec, summary.source_id, actual manifest_path and resolved edition. source_id.rs::Serialize emits null only for path sources, otherwise as_url(). manifest_path is an observation locator to join through an actually owned materialization map; it is not a semantic absolute path. Neither current source evidence nor a caller-supplied map establishes that map's custody.

## Source serialization hazard and prospective bridge

encode.rs::encodable_source_id omits path sources in Cargo.lock. For lockfile version4 it uses as_encoded_url(); earlier versions use as_url(). Metadata uses as_url() for nonpath sources. source_kind.rs::PrettyRef writes branch/tag/rev values via url::form_urlencoded::byte_serialize only when url_encoded is true. Thus e.g. branch topic/foo+bar appears as topic%2Ffoo%2Bbar in lockv4, but topic/foo+bar in metadata. Direct raw metadata.source==lock.source is not a total lawful join. PackageKey must nevertheless retain/hash the exact admitted lock source text as selected by the codec candidate; substituting metadata source text would silently change its recipe.

A proposed bridge is to derive the expected nonpath metadata source with the same selected bundled Cargo SourceId::from_url(lockSource).as_url() serialization, then compare its exact emitted text, including precise revision, against the actual observation selected by the admitted manifest map. Path sources require actual path source/materialization witness, metadata.source null, and the lock's absent source represented by the already selected empty semantic string. This is a prospective algorithm, not yet a bound adapter/output/helper selection. The full source serializer/URL/query dependencies and whole source-field matching/refusal controls must be published and authenticated before product use. Cargo SourceId equality alone is not a substitute for an exact source text/revision join. Unknown/ambiguous/zero joins cannot choose a winner or drop a package. Multiple distinct exact lock tuples that project to one observation remain ambiguity; matching source display text alone cannot admit either.

The pinned from_url code parses git query pairs through GitReference::from_query, keeps precise fragment, removes query/fragment from base URL and recreates the SourceId. GitReference chooses the last recognized branch/ref/rev/tag, ignoring unrecognized pairs; URL/query decoding belongs to that pinned producer algorithm. A first-party reimplementation cannot guess generic percent-decoding, split the opaque package id, use a different URL library's defaults, trim strings or normalize semantic lock values. Actual manifest/source/activation and provenance verification remain separate from this serialization projection.
