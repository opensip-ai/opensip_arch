# CSJ-1: exact Cargo source comparison kernel

Prospective narrow native design selection. Bound R3-MR1/C-ENV1/NKC-1 remain closed. This selects a source-comparison kernel only. Complete source/producer/profile, manifest/activation/custody mapping, namespace/failure rules, actual adapter/library/product and complete R3 remain open. Earlier advisory namespace/source serializer text stays historical advice, not a selected codec or a historical record to rewrite.

## Inputs and selected algorithm

For a new-M3 Rust package join, preserve the exact admitted Cargo.lock name, version and sourceId. NKC-1 pkg1 still hashes that exact raw tuple. Metadata source spelling is an observation, never a replacement for the raw semantic sourceId. Metadata id is an opaque same-observation join, never split or used as the native key. The actual package name/version and admitted manifest/tree mapping must match separately; this kernel does not establish those joins.

For a nonpath original source, parse the exact admitted nonempty lock source text and the actual observed non-null metadata source string through the selected Cargo1.95 SourceId::from_url interpretation. The exact upstream Cargo commit is f2d3ce0bd7f24a49f8f72d9000448f8838c4e850, source_id.rs, canonical_url.rs and cargo-util-schemas source_kind.rs are pinned below, with the full Cargo.lock (URL2.5.8 selection). The future implementation must conform to that exact interpretation and the selected bundled interpreter/runtime data, not a guessed generic URL parser or a moving Cargo release. Profile/runtime/component/CRC1 authentication remains a mandatory owning gate: these source bytes or this machine's binary are not a signed bundled closure. A different interpreter is admitted only through a separately reviewed compatible/successor profile; no silent selection by currently installed Cargo.

Let L and M be those parsed SourceId values. The selected nonpath comparison is L == M AND L.has_same_precise_as(M). Cargo SourceId equality compares the source kind (including GitReference) and CanonicalUrl, and ignores precise. The additional precise comparison is therefore mandatory. For Git, both precise_git_fragment() values must also be present and nonempty; comparison is exact under the parsed precise representation, no invented hex pattern, length, case fold or revision normalization. This kernel admits no fetch, revision lookup, checkout or change to raw lock bytes. A different/missing revision never matches through source equality alone. Parse failure is a refusal, not a match, default source or a dropped record. A nonpath invocation yielding a parsed path source refuses; path matching uses the separate path case below.

The original source kind and Git reference/URL equivalence follow those exact pinned functions. This includes their query decoding, recognized-query selection, CanonicalUrl rules and runtime case behavior. These are comparison rules only; a canonicalized URL must not be serialized as a new sourceId, package tuple, source-root identity, owner key or file-manifest preimage. No arbitrary URL trimming/normalization or tuple deduplication is added. SourceId's interned original URL spelling and serialization can depend on construction order. Comparing serialized as_url strings is not this kernel and is not a total exact source equivalence test.

For a path package, require the already admitted path-source witness and lock source absence represented by the existing empty sourceId, plus an actual null metadata source. The source is never inferred from null alone. The actual source-kind/acquisition and manifest/snapshot/package mapping remain with their owning admission. Empty strings, missing fields, an arbitrary path+ URL, an ambient absolute manifest path or a caller's claimed source witness do not substitute. No registry/git source is relabelled as path, and no nonworkspace path owner is dropped.

## Why serialization text is insufficient

The actual installed first-party fixture metadata controls preserve Cargo.lock under --locked --offline --frozen. One pair uses a plain main branch and an encoded topic/foo+bar branch: lockv4 emits encoded Git query data, metadata emits unencoded data. Another pair uses identical GitHub URL spelling and a case/.git alias: the alias lock string stays unchanged while metadata returns the manifest-declared spelling. The same recorded executable digest is used in all four cases. Substituting observed source text changes pkg1 in both differing-spelling cases. The earlier advisory proposed comparing SourceId::from_url(lock).as_url() text; this selection replaces that UNADOPTED recommendation, not historical selected law. Exact source comparison must also not omit revision: SourceId equality alone deliberately ignores it.

The fixtures are synthetic first-party Cargo metadata observations only. Null package checksums and zero revisions are declared fixture assertions, not authentic Git trees or archives. Fixture code is neither built nor run. CARGO_HOME remains the user-prescribed /Users/sb/.cargo and HOME is not assigned; native CC2/constructed environment/carrier/platform/owner/custody admission is not proved. The opaque actual manifest paths and raw metadata artifact hashes are operational evidence, not semantic key inputs. Source inspection plus these four actual observation controls support this narrow comparison choice; they do not implement or qualify the future comparison function against all producer cases.

## Full join and remaining gates

A match is NOT package/source/owner admission. The host still needs exactly one lock tuple in the actual workspace/native context, a current target/config/activation witness and an actually owned sealed materialization mapping to this package's exact retained manifest and source tree. Cargo source-slot equivalence can map distinct raw lock tuples to one underlying slot. Zero/multiple/conflicting actual joins refuse; no first-row winner, normalized tuple, source deduplication or shared-tree substitution is selected. Equal comparison values do not transfer file-manifest/provenance authority. All acquired candidates still finish admission/rejection and all admitted candidates materialize whole before activation. Source-aware roots and actual physical distinctness are still owed; matching source strings missed the reviewed shared-directory wrong-tree fixture.

Keep existing source structural/typed/content/schema/identity/signature/CRC1/correspondence/custody ownership and precedence. Parse/mismatch/missing/ambiguous joins, first-party metadata nonzero/malformed output, genuine absent-input incompleteness and host/tool/provider provenance still require complete public failure/coverage composition. This unit supplies no public code, origin label or fallback; it cannot be used in product admission until those owning routes and the complete producer/profile/witness are published. Actual snapshot/dependency path manifests, workspace source selection, source labels/replacements/checksum/manifest views/Git carrier, population/capacity/physical alias/worker policy and actual security library/harness/product controls remain open.
