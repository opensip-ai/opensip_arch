# DT-MD1: dependency source transport manifest digest

Prospective narrow recipe successor, currently unaccepted and unbound. Existing law leaves the manifestSha256 transport annotation self-referential. This proposal supplies only the non-self-referential preimage. It implements no dependency transfer or source admission and fills no S-M placeholder.

For DependencySourceManifestV3 and DependencySourceSealV3, manifestSha256 is exactly the 64 lowercase hexadecimal digits of raw SHA-256 over the deterministic-CBOR encoding of the exact complete DependencySourceManifestV3.entries array. Use the existing protocol-3 deterministic-CBOR law, including the closed admitted entry maps and exact byte-string/text/integer/ordering rules. Hash the complete array in its actual admitted sequence order; do not sort, truncate, sample, deduplicate or normalize entries as a hashing repair. Existing source/entry admission and canonical-membership rules remain owned by their existing authorities.

The preimage has no domain tag or prefix/suffix. It contains no envelope, outer manifest object, dependencySourceSetId, manifestSha256 member, frame length, frame payload digest, direction, sequence or frameType. This is the same non-recursive entries-only raw-artifact form already named for snapshot/prepared-output manifests, selected here prospectively for dependency transport. It is distinct from H(native.dependency-source-set.v1,descriptor), H(native.dependency-file-manifest.v1,packageFiles), owner manifests, import2 identities and every full frame payload digest. Never erase or zero a manifestSha256 field and hash the remaining outer object; that is a different preimage.

Host and worker independently encode/recompute this exact entries preimage. The existing manifest/seal/accepted association and dependencySourceSetId/Plan joins still compare independently. Every chunk path/package/offset and full content digest, final counts/bytes/chunks, complete set membership, immutable VFS and reject-before-use rule still apply. Excluding dependencySourceSetId from this one raw-artifact digest does not exclude it from the transport frame digest or its mandatory Plan/phase/set association. Existing empty dependency sets still send the required manifest/seal sequence; their entries preimage is the single CBOR byte80.

This selects no field, frame, phase, identity version, H domain, member list, limit, grant, acquisition/owner witness, mount namespace, error code or failure precedence. Existing maximum frame/aggregate/source/counter limits apply before consumption; a digest never permits an oversized or malformed frame. Historical raw bytes and accepted identities are untouched; no circular predecessor digest is reinterpreted as this one. Existing bound NNS1 pkg1-based .opensip/deps/v2 namespace and other successors remain authoritative.

The adjacent two schema definitions copy every existing structural property by value and replace only each manifestSha256.x-opensip-digest.artifact annotation. The publication record must add the section3.2 recipe anchor and supersede the two exact old annotation passages; no whole native schema rewrite is authorized. Synthetic reference vectors demonstrate digest bytes and association distinctions only, not actual dependency validation, native source/profile admission, confinement, protocol or product qualification. Product code/inventory180 unchanged; a separate accepted contract bind is owed before implementation.
