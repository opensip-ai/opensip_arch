# NIJ-1: prospective native input import joins

PROPOSED, not accepted law. This unit publishes M3-C item13's native-owner successor. It does not implement C3a, resolve R3, select package/path codecs, put L in effect, launch native code, qualify a run or freeze ground truth. Existing authorities and historical bytes remain unchanged. Binding requires independent Grok acceptance and exact root assent. The selections below are new prospective law where an existing gap is named, not claims that historical schemas already admitted them.

## Host acquisition path disposition

Select literal null for the required `DependencySourcePayloadV1.acquisitionSourcePath` in every newly admitted M3 native dependency import. Preserve the member and payload domain; extend its schema from the historical bounded string to that string OR null. Existing required-member, length, closed-object and all other rules remain. The native M3 semantic guard requires null; absence, a string (even an empty, fixed or normalized string), another scalar, or an additional path-bearing payload member is inadmissible. String-valued historical records retain their original schema/document digests, payload bytes, ImportId, PlanId and replay standing under their historical admission. They are not silently rewritten or admitted to a new M3 Plan. A new wrapper must be freshly assembled under the new selected schema, never relabelled in place.

The actual source location remains an acquisition argument used by the existing custody/read-fence acquisition procedure before semantic payload assembly. It is not copied into the payload, set descriptor, blob logical path, configuration, observation, scope or any other content-identity preimage as a replacement for this removed host path. This selects no new durable path carrier or logging field. If an existing operational surface lawfully records the argument, its existing confidentiality/credential and retention guards apply. A source-location string never becomes a content identity, authority, package identity or evidence of admission.

This fixes only the explicitly named host acquisition-path leak. PackageKey, sourceId, owner/mount/vendor/OUT_DIR codecs and intrinsic semantic paths remain with their existing owners; NIJ-1 neither normalizes nor invents them. Source bytes, logical member paths, tarball raw digests and every other identity input retain their existing meaning.

Old readers reject the new null form. New general schema readers retain historical string shape validity, but the new-M3 admission guard rejects strings. No caller flag grants historical standing; the host chooses historical replay from an already retained accepted record/schema selection, and new Plan construction always applies the new guard. No field-defaulting, shared string placeholder, hidden path alias or path-stripping of an authenticated historical record is allowed.

## Payload self references

Every newly admitted M3 DependencySourceSetV1 row has acquisition.descriptorId null, for every admitted acquisition mode. Every newly admitted M3 PreparedOutputSetV3 row has preparation.importId null. The schema's existing null alternative is unchanged. These values are fixed before canonicalization and set identity derivation. A non-null value is rejected, not patched. There is no second admitted set projection with ids filled in. ImportId hashes its payload and must not occur inside its own payload. This grants no authority to fabricate a missing descriptor or set. Existing package, source, digest, preparation-kind, inert-media and custody checks still precede use.

## Authenticated core projections and wrapper digests

Retain CRC-1's exact core descriptor projections: producerClosure is the core provider closure for its import-producer use; adapterClosure is the core adapter closure. They are derived from the authenticated TR-CORE inventory and admitted descriptors, not supplied bare strings. No new kind, protocol major, manifest source, launch authority or closure recipe is selected. C2PM-1 governs component closure projections independently; its four passive interfaces are not these core producer/adapter identities.

Retain the existing closed ImportWrapperV2 and native import registry. The dependency/prepared payloads use their existing payload domains. payloadSchemaDigest is raw SHA-256 of the exact selected FULL schema document, not a selected definition or a reserialization. payloadDigest, sourceCorrespondenceDigest, buildDigest, scopeDigest and observationDigest are raw SHA-256 of their existing canonical closed preimages. ImportId alone is `import2:` plus the existing H("import", wrapper) recipe. No digest field is an H identity by name alone.

Both kinds retain exact-snapshot correspondence to the actual analysis snapshot, the analysis scope descriptor, BuildIdentityV1 {schemaVersion:1,buildIdentity:null}, and exact six-member observation {schemaVersion:1,kind:<dependency or prepared>,window:null,population:null,selection:null,revisionRange:null}. A mismatched/null/missing kind or missing observation member is inadmissible. The four null values mean observation semantics do not apply; they do not erase the kind. Wrapper blobs retain the existing UTF-8 order, bounds, digests and nonempty omissions for incomplete records. Existing partial-package omission grammar is unchanged.

## Plan-selected identity join

Before final Plan construction, the host resolves native candidate imports from already admitted retained wrappers and payloads. It first rederives every candidate's ImportId and auxiliary digests and validates its selected schema and correspondence, CRC-1 projections, scope, custody and native semantic preconditions. A matching key alone cannot admit bytes. The host's resolved selection is not an opaque caller-provided list and cannot bypass these prerequisites.

For each selected Rust context, a dependency set containing any imported-descriptor acquisition row requires exactly one selected dependency wrapper whose payload.set H identity equals context.dependencySourceSetId. Each context selecting an imported prepared set requires exactly one selected prepared wrapper whose payload.set H identity equals context.preparedOutputSetId. Kind participates in the join. Compare rederived identities; do not infer equality from wrapper names, keys, source path or cached labels. Zero matches and two DISTINCT ImportIds both reject. The same selected wrapper may serve multiple contexts with the same set identity. Duplicate copies of the same ImportId are not a second candidate: the existing canonical-set and identity/byte consistency rules reject duplicate/conflicting selection records before counting distinct admitted wrappers.

The final plan.importIds is exactly the canonical sorted unique union of B1's resolved ordinary evidence imports and the native wrappers resolved through these context joins. No native dependency or prepared import is named through configuration evidence.importIds: reject it there, including a wrapper already selected through a context, rather than silently filtering it. A retained but unselected native wrapper is never consumed. The identity requirement does not authorize scanning or admitting arbitrary retained imports; existing lawful explicit acquisition and selection boundaries remain.

Run closure rederives the same joins from the exact Plan-selected retained records, never substitutes another retained wrapper, and rejects zero or multiple matches under the owning closure failure boundary. Native imports are admitted evaluator inputs with their four nonapplicable observation values null. This does not make them runtime coverage, observations, source analysis or execution authority. A Rust context without imported-descriptor dependency rows does not acquire a dependency wrapper through this rule. Prepared M3 admission remains imported-descriptor/external/inert/explicit; authorized-execution and defaulted stale fallback remain forbidden.

Snapshot body edits with unchanged Cargo.lock, source bytes and dependency set descriptor preserve dependencySourceSetId. The dependency wrapper's correspondence to the edited snapshot changes sourceCorrespondenceDigest and ImportId. Moving only the acquisition argument while keeping every semantic input and selected schema identical preserves the new payloadDigest and ImportId; source correspondence must also be identical for that equality claim. It never implies equal PlanIds when another Plan input differs.

## Complete failure publication

native-import-routes.json publishes five exact new semantic predicates, actual possible origins, guard locations/order and full public composition. public-detail-extension.json selects exactly one new public detail code native.input-import-invalid for the known external precondition routes; its one code-keyed remedy covers all five external native payload/join/configuration failures. CONFIG.INVALID remains the configured native-import error with the new native.input-import-invalid detail; HOST.INVARIANT_VIOLATED remains the actual host bug answer. Existing class, exit, error and fault vocabularies remain unchanged. All four selected common schema copies preserve inherited enum order and add the new detail once. No origin-dependent key enters context-free aliases.

The schema candidate only extends the named path field. Route rows are an additive merge into the existing selected native registry, preserving all prior rows including C2PM-1. The materialization map must carry both prospective selections; no older complete schema may overwrite current accepted overlays. Actual failure envelopes use an allocated RequestId, derived exit and nonempty typed errors, with optional termination.domainDetail absent rather than null. Missing witness bytes keep evidence.missing/host-io; corruption, signature, shape, digest, CRC1, correspondence and scope failures retain their existing more specific owners and order. Run closure reuses these semantic joins under actual retained origin, never infers a provider fault from an explicit import or disguises a host contradiction as an external defect.
