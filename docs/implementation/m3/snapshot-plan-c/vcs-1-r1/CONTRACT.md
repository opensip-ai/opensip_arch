# VCS-1: M3 meaning of dirty

**M3 meaning of `dirty` (VCS-1, accepted M3-C item4).** At M3, `dirty` means that cleanliness has not been established. For a Git observation the host reads no Git object and cannot compare the working tree with HEAD's tree, so it records `dirty: true`; this is not a claim that a particular path changed. It must not record `dirty: false` from Git index stat data or infer a change set from this flag. `NoRepository` keeps `kind: none`, `commitId: null`, and `dirty: false`. The flag does not prove a clean Git revision, and an M3 Git observation cannot satisfy a `vcs-revision` correspondence requiring a clean commit. At M3 no runtime, test or history evidence import consumes such a correspondence.

The same Git `dirty` meaning applies to each admitted D15 member's schema-3 observation under B-S2 and its accepted successors. The schema-3 root remains `kind: none`, `commitId: null`, and `dirty: false`; it supplies no member correspondence. Schema-2 and schema-3 fields, admission, member order, canonical bytes, inventory-digest meaning and historical retained observations are unchanged. This passage changes no observed flag or retained identity by reinterpretation. It publishes no Git object reader, per-path change set, new correspondence mapping, new record member, schema version, launch authority or C1b implementation. C1b, its native reads and all dependent M3 units retain their accepted gates.
