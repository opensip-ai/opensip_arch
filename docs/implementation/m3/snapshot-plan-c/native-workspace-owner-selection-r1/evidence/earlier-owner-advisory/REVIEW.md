## Source choice

Rust packages joined from `workspace_members` through ids in the same admitted bundled metadata observation become snapshot-member owners. Activated nonworkspace packages become dependency-closure-member owners, including nonworkspace path dependencies retained inside the snapshot. A workspace member that another member names as a dependency keeps snapshot membership. The selector is this workspace and activation rule. Required witnesses still join the sealed snapshot, or the selected complete dependency package manifest, together with the current target, config, and activation. A missing or ambiguous metadata id, lock tuple, manifest, or source witness refuses that package. Metadata completeness and acquisition stay with current native law.

The retained semantic witness holds the exact name, version, and lock `sourceId`, the existing `sourceKind`, the package key, the workspace membership and activation facts, the source choice, and, where that source requires it, the sealed logical manifest locator. Metadata `id` and `manifest_path` are interpreted only through the admitted materialization map. Absolute Cargo ids, absolute paths, and path-containing raw observation digests stay outside the semantic witness. A caller-supplied witness or hash leaves the package unadmitted. Exact producer-to-lock, source, activation, custody, and failure publication remains owed.

Bound R3-MR1 still supplies the file-manifest bytes after this choice. A snapshot-member owner uses the complete sealed snapshot `sourceInventory`, so workspace members of one snapshot share that inventory digest. A dependency-closure-member owner uses that package's complete `DependencyFileManifestV1`. `own2` distinguishes the owner keys when those snapshot owners share one inventory digest. S10 already names the two source classes this selector uses. Test-runner and workflow owner vocabularies stay on their existing records.
