# MWS-1: Rust workspace membership selects owner source

Prospective narrow design unit. Exact bound R3-MR1/C-ENV1/NKC-1 and CSJ-1 comparison stay closed. This selects the owner source class only, not complete source admission, activation derivation, producer/profile, carrier, namespace, failures, library, product or R3.

For a Rust execution owner already proven activated in the current admitted native context, use the `workspace_members` array from the same actually admitted bundled Cargo metadata format-version1 observation that supplies its package and resolve rows. Join each member by exact opaque id equality to exactly one package row in that observation. If the owner's matched package id is a workspace member, source is `snapshot-member`; otherwise source is `dependency-closure-member`. A workspace member used by another member as a dependency stays `snapshot-member`. A nonworkspace path dependency stays `dependency-closure-member`, with its actual retained in-snapshot Cargo.toml locator required by NKC-1. Null metadata source does not establish workspace membership. Package name/version, equal bytes, package-key equality, default-members, resolve.root, current directory or a lexical path prefix do not select this source class.

The observation must be the result of the owning admitted producer/profile, sealed materialization, verified carrier, current target/config and activation. Installed Cargo experiment output or a caller's supplied metadata/witness is no admission. All package rows have unique opaque ids, workspace-member ids are unique and name existing package rows, and every used resolve node/dependency id joins uniquely in that same observation. Missing/duplicate/conflicting/unknown ids refuse rather than selecting the first row, normalizing ids, dropping rows or assigning a default source. This rule does not parse a PackageId string or invent a new public PackageObservationID. Actual source/lock tuples and manifest/tree correspondence still require their complete separate joins. Package-key equivalence alone never conflates separate workspace/native contexts.

Each selected snapshot member must join its actual Cargo.toml and package files to the sealed snapshot's materialization mapping; sourceKind is path with absent lock source represented as empty sourceId and metadata source null. For a dependency member, the actual acquisition/source-kind mapping and uniquely admitted complete DependencyPackageSourceV1/file manifest remain mandatory, including DS-4 path dependencies. The older reference helper's path-package exclusion is not permission to drop path owners or claim their whole source manifests admitted. Absolute metadata id/manifest paths and raw output digests are operational producer evidence only, not semantic key or file-manifest inputs. Retain and recompute existing NKC-1 package/owner witness and R3-MR1 source-selected raw file-manifest digest; no new witness field or owner preimage is introduced.

This source choice is conditional on actual activation already established by the owning UnifiedFeaturesV1/current config/target rule. It does not define that activation projection, turn every retained package into an activated owner, or grant execution. All acquired candidates still finish admission/rejection and every admitted candidate materializes whole before activation. A package absent from an activated metadata graph is not authority to omit its retained candidate/tree/lock row. Snapshot owner file-manifest recipe remains the complete snapshot inventory, not a subtree selected by this workspace membership rule.

Exact source/producer/profile/activation/manifest/custody correspondence, acquisition/carrier/checksum/Git view, source-slot injectivity and physical/worker namespaces and provenance-aware public failure/coverage composition must be published and implemented before product use. This rule supplies no public failure code or origin, no fallback or containment claim, and no authorization. EffectiveL/O7/D3/D13/GT/qualification and complete C3/R3 remain open.

## Evidence standing

Three actual installed Cargo1.95 locked/offline/frozen metadata observations over synthetic first-party fixtures: one virtual workspace has members a and b, member a depends on b and an excluded nonworkspace path package; an optional excluded path package is retained in the lock/tree but absent from the activated output. Two independent roots use the same package name/version and absent source: their opaque ids and actual manifest paths differ. Existing NKC-1 scopes package tuple identity and distinguishes logical path owners; no ambient path is used as a semantic key. Fixture code was not built or run. The prescribed CARGO_HOME remained /Users/sb/.cargo, HOME was not assigned, installation remains absent, and no native CC2/constructed environment/profile/custody/source admission or qualification is proved. Pinned Cargo source creates workspace_members from ws.members rather than default_members/root and normalizes resolve ids to package rows. This supports this narrow rule only.
