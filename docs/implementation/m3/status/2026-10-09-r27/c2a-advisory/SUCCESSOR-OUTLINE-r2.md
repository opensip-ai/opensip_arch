# C2a protocol major: concrete advisory successor outline

Recommended direction: one top-level signed closureProtocolMajor field for analyzer, toolchain, stdlib, rust-dev-llvm and grammar. Suggested declaration range1..9223372036854775807 matches existing signed manifest integer representation; closure identity's wider type is unchanged. The field is optional structurally to preserve historical admission, but authenticated presence is mandatory at new C2a closure projection. Analyzer declarations must equal compatibility.providerProtocol when present; passive artifacts do not gain a worker protocol through this declaration.

The advisory schema copy makes exactly one JSON-value change to the accepted CR-1 completed schema: the optional bounded integer property. Required keys, five role branches, command rules, capabilities, permissions and all other values stay equal. It is outside both repositories, unselected and unreviewed. No source/schema registry pin or generated file changes.

A full successor must replace CR-1's named unresolved source passage through an exact selector, and amend C's projection duty. It must select the absence-refusal route and typed semantic validation duty. The proposal must separately state each passive role's interface-version meaning and who assigns/increments its explicit declaration; initial values are not inferred from release versions or other protocol fields. These are owner decisions, not supplied by this outline. A reviewed proposal and owner direction are required before binding or product materialization.

Migration controls must preserve existing oracle bytes/standing, admit older manifests without the optional field under historical M2 validation, refuse to mint a new native C2a closure from absence, reject null/boolean/float/zero/negative/overflow, accept the two bounds as declaration shape, require analyzer equality, and use authenticated body bytes for each role. No automatic copy/default/backfill, version conversion or caller fallback. Newly signed manifests change their manifest digest and derived closure identity; retained historical bytes and closure standing are unchanged. The existing validators share one generated shape and do not implement schema-version dispatch.

This outline does not choose law, protocol values, a refusal wire key, or a native closure implementation. It makes the panel recommendation concrete for the pending owner direction.

Historical replay must use authenticated retained provenance and the applicable historical admission contract; caller flags, unsigned descriptors and an absent-field M2-valid body cannot bypass new-C2a mandatory presence. None of these controls supplies remaining role meanings or initial values.
