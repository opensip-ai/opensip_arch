# C2a protocol major: advisory panel, not accepted law

Three independent read-only agents inspected CR-1, C r7 and the admitted manifest and compatibility schemas. All agree current law does not select a field, control is a separate channel, and caller values/defaults/version inference are inadmissible. No repository, held tree, cargo lane or Herdr session was changed by this panel.

The law member recommends uniformly projecting compatibility.providerProtocol: minimum migration, existing signed required integer, with an explicit disclaimer of worker-wire semantics for passive artifacts. The schema member recommends a uniform new signed closureProtocolMajor with analyzer equality to providerProtocol. The challenge member recommends existing providerProtocol for analyzer and new compatibility.roleProtocol for resource roles; this needs a successor to the current uniform-field rule.

Lead recommendation: the uniform signed closureProtocolMajor successor. It keeps one projection rule for all roles and makes the previously undefined declaration explicit. The additional analyzer equality invariant and closed-schema migration are real costs. Four resource interface meanings and initial major values must be explicitly selected; no automatic major 1, provider-major copy, compiler-release inference or historical reinterpretation. Missing or mismatched declarations refuse new C2a projection. Existing retained signed manifests remain unchanged. The field changes signed bytes, manifest digest and closure identity. Historical closures keep their admitted projection semantics.

Existing manifest integers are positive signed-64, while identity projection admits unsigned-64 including zero. Recommend following manifest range for the new declaration without narrowing identity.

Owner direction requested asynchronously. Recommendation is not owner assent, Grok acceptance, a bound successor or C2a implementation authority.

Migration refinement from the schema panel: add closureProtocolMajor as optional in the successor signed manifest shape, but require its authenticated presence at new C2a closure admission. Enforce analyzer equality to compatibility.providerProtocol when present. Current validate and validate_inventory share one generated shape and have no historical version dispatch. Globally requiring the field would invalidate retained old manifests and the existing 11,010 shape-oracle cases. Existing absence therefore remains valid under M2 admission, while absence cannot mint a new C2a native closure. No backfill or reinterpretation of historical bytes, hashes or closure standing.

Future reviewed successor authority must specify the field bounds, cross-field equality, missing-field refusal route and projection boundary. It must retain old shape/semantic oracle bytes and add distinct role, null/type/bounds, mismatch and no-mint controls. A mandatory-version alternative requires an explicit historical reader and selector; manifestSchemaVersion alone supplies neither. Product schema, sources pins, generated table and semantic checks remain unchanged until that successor is selected and accepted. Resource interface meanings and initial majors still need explicit selection. This refinement is advisory, not owner direction or acceptance.
