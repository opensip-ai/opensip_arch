# O1-D1 r2: prospective operational definition selection

PROPOSED DESIGN UNIT. These are new explicit selections for O1-a's three named definition gaps. No product code, RequestId wiring, sink custody, harness sink, C6 corpus completion, platform qualification or full O1-a completion follows from design acceptance. Accepted SOP2-P/R/2b subjects stay closed and byte-identical; their bind order remains O1-a, S-OP-2-P, S-OP-2-R, S-OP-2b. SOP2 r6 becomes an accepted parent only at the S-OP-2-R bind. This publication pins those drafts as source context, never represents them as eligible accepted parents. It adds definitions independently and must compose with their exact meanings. Any contradiction is a required finding, not permission to rewrite an accepted draft.

## 1. Guard input and authority

Each projection encoder supplies the complete bounded UTF-8 record, exactly one final framing LF, and its own immutable string-token map. The map identifies every quoted string's encoded interior and which interiors are P2 names, including a K12 elided tail. The quote and structural delimiters are outside the interior. Metadata comes from the sealed encoder; caller maps and maps retained in input logs are inadmissible. The guard checks map order, disjointness, bounds and equality to the encoder's parsed quote/escape boundaries before using it. The read-back encoder constructs a fresh map after existing field re-admission and projection. Spans are recomputed separately for JSON and human output. Invalid UTF-8, framing, map, quotes or rule-E escapes refuse the projection; they are construction defects, never evidence of an admitted P2 name.

One final framing LF is excluded from body C0 inspection and included in the 4096-byte bound. Embedded raw LF, CR, TAB and every other C0 byte U+0000..001F are defects. ANSI removal uses exactly the recovered core pattern ESC followed by `[` then zero or more ASCII digits/semicolons then an ASCII letter. It runs before C0 removal. This is not an OSC/terminal parser; the subsequent C0 check also detects an ESC in any other sequence. No unrelated terminal-control language is selected. Rule-E escaped characters are inert encoded text: decoding for credential matching must not turn an escaped C0, ANSI or bidi character into a raw-control firing. DEL/C1/bidi escape admission stays with rule E, not a new byte-strip family.

## 2. Exact credential profile and match coordinates

Select exactly the three recovered adapter expressions in evidence/credential-pattern-profile.json, with the original `g`, `i`, `u` flags and source replacement mask `***`. Source commit and both raw file hashes are in evidence/source.json. No first-four prefix, hash, entropy threshold, additional key name, minimum token length or guessed credential family is admitted. Disclosure remains best effort.

Credential matching operates independently on each decoded quoted-string interior, or each maximal non-string body segment between quoted tokens. It never crosses a token boundary or the final framing LF. JSON/human quote delimiters are not matched characters. A literal quote decoded from a rule-E escape inside a string IS a character. Non-string segments are inspected too; do not assume all credential-shaped bytes are in values. Matching follows source family order URL, auth, inline, with leftmost nonoverlapping global matches inside each family. For classification, every original-source match in each family is inspected before replacements; overlapping family matches remain classified against the original map. The synthetic scrub transformation then applies the three source replacements in family order. Added mask bytes are not caller input and never produce a new disclosure.

The finite character profile in character-profile.json is selected explicitly. Word characters are ASCII letters/digits/underscore plus U+017F and U+212A under insensitive Unicode matching. ASCII-letter classes include ASCII upper/lowercase plus those two characters. Literal ASCII keyword comparison uses ASCII uppercase-to-lowercase, U+017F to `s`, U+212A to `k`; every other scalar is compared literally. Whitespace is exactly the listed 25 scalars, including FEFF and excluding 0085. Other classes are literal set union/negation and ranges from the pinned expressions; `\b` compares membership on adjacent scalars, with segment ends non-word, not locale/Unicode-word heuristics. Quantifiers count scalars, not UTF-8 bytes or UTF-16 surrogate halves; all characters eligible for auth's four-character minimum are single-BMP word/punctuation characters. Greedy matches stop at the segment end. No Unicode normalization or runtime locale selection occurs. This finite profile is independently observed across all 1,112,064 Unicode scalars and fixed here, so future host Unicode library revisions cannot change it silently.

A credential match wholly inside one encoder-owned P2 interior is `p2-name-match`, an expected disclosure, and remains byte-identical in lawful output. Matching uses decoded content but classification maps its complete scalar range back to that one encoded interior; escapes stay inside their original interior. A match in any other segment is a defect. No match may consume a closing quote, a neighbouring field, punctuation outside the token or a second P2 field. This fixes the demonstrated whole-line `password=CANARY` delimiter overrun without declaring the credential name a defect. Rule-E escaping alone produces neither category.

## 3. Bound, marker and defect disposition

The hard line bound is 4096 UTF-8 bytes including its framing LF. A guard's synthetic scrub transformation strips ANSI, strips body C0, applies exact credential replacements, then applies the length bound. Credential inspection precedes length cutting so cutting cannot expose a secret prefix by breaking a pattern first. The selected length marker is the recovered core ellipsis `…` (three UTF-8 bytes). If the transformed body plus LF exceeds 4096, retain the longest scalar-aligned prefix of at most 4092 bytes, append `…` and one LF. Never split UTF-8. Credential mask `***` and length marker `…` have separate meanings. The 2000-UTF-16-unit core diagnostic default is not selected. All defect flags reflect the original input, before transformations; a removed sequence cannot erase another original match or misplace a P2 span.

Scrubbed defective bytes are NOT an admitted replacement record. Cutting or replacing arbitrary encoded bytes can invalidate JSON or its descriptor. The guard returns an opaque defect result to production, and production never writes, persists, bundles, logs or caches that synthetic preview. Only the isolated synthetic guard controls observe previews. Every lawful projection, including P2 matches, is emitted byte-identically; neither a P2 name nor an escape is scrubbed on that path. The guard remains present immediately before every sink write; a producer check does not replace it. This explicitly selects failure handling where prior law named only the tripwire.

A defensive encoder refusal before ANY enqueue increment commits once to existing global `refused`. No producer drop is committed after enqueue. A defect detected by a physical sink guard before syscall admission closes that sink's existing gate with its ordinary release store; the next acquire admission sees closed, admits no syscall for the defective unit, and the unit/unwritten remainder gets existing `sink-stopped` through the writer's one immutable snapshot exchange. If exchange is after freeze, existing subtraction accounts it once as `drain-abandoned` and the later exchange is post-freeze only. A pre-scope unit keeps its pre/direct source partition and transfer accounting. This is a newly selected guard-triggered gate closure, not a fake I/O error. There is no retry, recursive log, new loss reason, fabricated errno, `sink-failed` or command termination/exit/Coverage/Run change. First actual I/O error state is unaffected. A writer must inspect the complete candidate record before appending it to any write unit; thus no part of a defective record is admitted. Existing at-most-one already admitted write-unit residual remains unchanged. All projected forms are inspected defensively before ANY source enqueue increment, so a construction defect there commits exactly one global refused and no sink projection is enqueued. Each bounded store also rechecks its immutable projection immediately before storage. The crash ring has no loss-matrix/source tally: a defensive ring-store refusal stores no bytes and never invents a producer drop, writer outcome or loss matrix after another projection enqueued. Its guard tripwire still makes any such defect fail C6. A pre-scope store refusal after its source increment commits no producer drop; the existing E_pre/T/outcome subtraction at freeze uses the ACTUAL file-capability/source partition: untransferred pre-scope records are unpersisted without file admission and drain-abandoned with file admission, transferred records use T minus committed outcomes. No new reason or successful delivery is fabricated. Physical writer snapshots and marker/gate laws remain as above.

The actual C4 corpus must still have zero construction defects and C7 must have zero defensive encoder refusals. Expected P2 name disclosures are counted separately, without retaining the names or exposing a new production event. Synthetic defects prove defensive handling, not product canary success. Marker, matching and mapping controls here are design controls only; exact Rust controls, all owning sinks and whole O1 corpus remain owed.

## 4. Nonempty K5 release catalog

Select the initial operational K5 release catalog as the sorted unique union of the eleven `/capabilities/*/id` values in the exact accepted native capability matrix and the four machine platform ids in security S8. The matrix's platformFamilies must equal that S8 population. evidence/catalog-proposal.json records the exact 15 expected members and source pin; catalog-definition.json adds the complete source/digest derivation. These are design evidence from existing authorities, not a product mint-list file. No component or bundled-pack ids are guessed. IDs do not claim capability availability or qualification.

The implementation materializes a sealed release-catalog module with fifteen explicit literals and the exact source receipts/digests. Reproduction extracts those named source values from the pinned architecture authorities and byte-compares the sorted members and receipt to the product module's reviewed output. Generation occurs in the controlled source workflow, NOT a build-script/OUT_DIR/runtime discovery step. A missing source, mismatched pin, duplicate source id, grammar violation, zero catalog or changed source selection fails generation/verification. Future changes require an exact reviewed successor and owning release catalog selection; a logged value cannot select a catalog.

The catalog digest is raw SHA-256 of canonical compact UTF-8 JSON of the sorted string array with no extra LF, BOM or Unicode escaping, as fixed by catalog-definition.json. The source receipt independently pins both exact documents; member digest does not stand in for source authority. Whole ASCII grammar is `[A-Za-z0-9_.:@/+-]{1,128}`, with no trim, search match, case folding or normalization; encoded V is 130 bytes including quotes. A catalog entry is a sealed owning type with private constructor, admitted only from this verified immutable module. A public exact lookup can select an existing entry, never mint a new string. Writer K5 conversion accepts only `From<ReleaseCatalogEntry>` or its owning typed equivalent. No From<String>, &str, blanket adapter, test-mint leakage or caller-supplied catalog is admitted. exceptions.json remains the existing sole audited exception list.

Read-back uses the actual running build's verified catalog object, after descriptor admission. It checks whole grammar, encoded V and exact membership. A known K5 field with a grammar-valid unknown member is invalid and follows existing invalid-field drop accounting. If the verified catalog prerequisite is unavailable, the reader must return a typed prerequisite-unavailable result before K5 filtering/re-emission; no empty catalog, successful empty bundle, guessed membership or silent drop-all is allowed. That result is an internal logging/read-back availability result preserving the existing public command-envelope owner; this unit invents no new public error/detail code or bundle-success route. O1-a ships a verified nonempty compiled catalog, so ordinary execution cannot construct an unavailable catalog. Negative controls exercise missing/unverified input to catalog admission, not a public constructor for unavailable catalog state. Any future bundle command exposing this internal failure owes its owning public composition before emitting an answer.

## 5. Event table definitions

event-tables.json selects literal registry entries. Sink stays exactly `file`, `stderr`; harness remains with S-OP-2b/O1-b. Every entry obeys K1's bounds/provenance; templates and member literals are written directly in the registry. These tables are not generated from arbitrary Cargo output.

Platform is exactly the four S8 ids, chosen from build target facts: target_os=macos, arch=aarch64/x86_64; target_os=linux, target_env=gnu, arch=aarch64/x86_64. No display aliases or musl/unknown mapping. Unsupported target facts refuse logger initialization with a typed internal unavailable result, emit no guessed platform/event, and preserve command invariance. This records build target family only; it proves no qualified OS/filesystem profile. RequestId scope gating stays unchanged: O1-a production still emits nothing until owning RequestId wiring.

BuildProfile is exactly `debug-assertions-on` and `debug-assertions-off`. The owning module selects the value only through the compiled artifact's `cfg!(debug_assertions)` fact: true selects on, false selects off. Both member strings are literal registry source. Preserve O1 item1: NO BUILD SCRIPT and no external dependency. No env!, option_env!, include!, OUT_DIR output, Cargo/runtime environment, caller string, optimization heuristic or debug-info observation selects this field.

This definition expressly reports one assertion-class property of the built artifact, NOT a Cargo named profile, dev/release inheritance, actual custom profile name, optimization level, debug symbols, harness feature/profile or qualification. The name BuildProfile does not imply those omitted facts. Four isolated bare rustc controls vary opt-level 0/3 independently of debug assertions yes/no; both optimized and unoptimized artifacts select the exact assertion predicate. The prior three Cargo PROFILE observations remain historical evidence for r1's rejected inheritance proposal only, not controls proving this new field. Existing explicit feature selection, no-assertions refusal and featureless release marker absence stay unchanged; a member on does not enable any sink or harness feature.

IoErrorKind is exactly `permission-denied`, `no-space`, `io-error`, `other`. For an actual returned io::Error, map ErrorKind::PermissionDenied first, StorageFull second; then any remaining error with an actual raw_os_error to io-error; every remaining actual error maps other. This complete stable mapping does not name Rust's unstable Uncategorized variant or hardcode cross-platform EIO values. Darwin EACCES/ENOSPC/EIO observations are evidence for this host only; Linux controls remain owed. Errno is independently K2-admitted only from the SAME actual returned native error and omitted when absent. Never format Error/Display/message or accept a worker/caller label.

A successful returned count smaller than the requested syscall unit is a short write, not an io::Error, and contributes no fabricated sink_error or errno. Its continuation still needs its own successful gate admission. Delivered complete records stay written; a remainder denied continuation is sink-stopped; a later actual I/O error has its own existing sink-failed outcome. An actual WriteZero io::Error without a native code maps other. Returned counts outside 0..requested are an actual host invariant, not other. If no actual I/O error occurs, both optional sink_error and errno are omitted, even if a short write recovered or a gate closed. The first ACTUAL I/O error and same error's admitted errno are carried in that writer's immutable cumulative snapshot at its owning exchange and frozen from that cell, never a separate late gauge or pair fabricated from two observations. This preserves the existing first-I/O-error meaning; the short-write controls test the distinct continuation law and require no new error-table member.

Keep SOP2 item23 descriptors exactly: log.stream.opened is info, version K4, platform K1 Platform, build K1 BuildProfile, sink K1 Sink, pid K11 P1, requires only RequestId, export no. log.loss.counted is warn, sink K1 Sink, counts K8 frozen eight-reason-by-five-level matrix, optional sink_error K1 IoErrorKind, optional errno K2 Errno, only RequestId, export no. Summary values remain element-wise saturating global+sink frozen counts. No renamed errorKind key, extra identity or emitted harness sink. No new ComponentRole members are selected.
