Applies only when the owning C3a importer has actually established its explicit named source, original lock tuple/candidate correspondence and canonical source order, and has a lawful route-specific reader/decoder over actual candidate bytes. No caller boolean/catalog entry/key/path or header quantity proves source custody, admission, activation or import authority. ## Selected logical observation events

1. Source event: one actual supplied nonpath candidate, once, in ascending rawUTF8(name,version,sourceId), before candidate body read. Duplicate/missing/correspondence faults keep their existing owning routes, not fabricated extra source entries. Source crossing reports16,385/16,384 and stops further acquisition. The count is not a successful admission count.
2. File event: one actually observed route-valid regular-entry/path, once, at the reader/decoder's regular-file begin boundary, BEFORE any content is delivered to charging or quarantine. For an archive this requires the checked header, accepted type0, selected effective path and no duplicate/path/long-name relation failure; the announced tar size is not evidence of content bytes. For a tree this requires the owning observed entry type/logical path and actual same-source filesystem discipline; a guessed filename or caller list is not this event. The file observation may later be incomplete or its candidate rejected. This prospective rule explicitly counts that observed attempted regular entry rather than requiring a completed whole-file event. Its acquisition charge is retained. File crossing reports4,000,001/4,000,000 and stops before its content or any later entry is processed.
3. Content event: actual regular-file payload byte delivered to the owning charging boundary, in logical byte order within the selected file order, BEFORE that byte is written to provisional quarantine or supplied to any materialization consumer. No announced size or unproduced prefix estimate is charged. Previously delivered payload remains charged if a later profile/IO/custody rejection occurs. The first byte that would make the cumulative count greater than34,359,738,368 proves the crossing, reports34,359,738,369/34,359,738,368 and stops. The crossing byte may be observed to prove the refusal; it is not written into a candidate delivered for admission or the adapter.

Archive files use actual archive order; trees use ascending owned logical-path bytes. Source and file events precede their own content, selecting existing sources-files-content precedence at that boundary. Independent IO/cancel/resource/custody/profile conditions follow their owning observation precedence; this text adds no priority between unrelated boundaries or default origin. Nothing may turn an unproven/malformed path/header into an acquisition bound merely from declared size. Late trailer/end/profile rejection excludes the candidate from admission/final population but does not undo earlier actual acquisition charges. An acquisition crossing observed before a possible later trailer failure is the actual stopping condition; no unseen trailer outcome is inferred.

## Chunk independence and actual physical work

Implementations may process payload slices, but MUST stop their logical charging/delivery at the first crossing byte. A slice longer than remaining allowance must not be assigned its whole length as the public observed value. Only bytes actually delivered before the stopping boundary are charged, and the byte proving refusal is counted once. Same canonical input and logical observation sequence yields the same field/observed/limit under every physical read/inflate/chunk partition.

The logical payload boundary is distinct from bounded physical reader and inflater buffering. The exact selected decoder already uses4096-byte compressed input and32768-byte history/output storage; those fixed buffers are not new semantic candidate allowances or complete resource guards. Buffered bytes must not be silently treated as already complete regular files, successful custody, returned manifests, quarantine commits or adapter input. Their actual compressed/inflated/work populations still count under existing per-archive and owning ledgers, without subtracting lookahead or counters. The new importer/decoder integration must expose an actual charging-before-write boundary and preserve its fixed buffering/resource checks; a callback over an unbounded already materialized object is forbidden. No generic fallback may read another candidate, ambient cache, home or network.

The exact prospective consumer controls must distinguish zero-content files at the boundary, framing/long-name/end-region work when content allowance is exhausted, partial rejected content, source/file-before-content priority, cancel/IO interruptions, deterministic scalar reports, and no returned/committed/adapter candidate after refusal. Actual physical buffering and work/resource controls are owed in the code review; pure symbolic chunk controls do not prove them.
