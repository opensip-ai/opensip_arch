# C3FN-1: explicit CRATE-ARCHIVE-1 FNAME field boundary

Prospective narrow native DS-2 decoder compatibility clarification. This draft is unselected until exact independent acceptance and separate design bind. It preserves accepted MC8/D5 and all earlier law/code as closed exact authorities; it does not claim the old MC8 prose already makes the terminator-count choice.

For native DS-2 extraction under accepted MC8 CRATE-ARCHIVE-1, the optional gzip FNAME field is limited to4096 on-wire bytes **including the terminating zero byte**. When the gzip FNAME flag is present, its field starts immediately after the fixed ten-byte header (all other optional-field flags remain outside the profile). Count each FNAME byte once as it is consumed, across every input-buffer boundary. A zero at field position1 through4096 completes that field. Consequently an empty name plusNUL is legal;4095 nonzero bytes plusNUL is exactly at the limit. A nonzero byte at position4096 proves that a legal terminating NUL cannot fit: refuse with the existing D4 archive-profile-bound cause without consuming a4097th FNAME byte. EOF before NUL is a truncated profile breach, not successful termination; an already proven D4 breach stays D4. With FNAME absent, consume no FNAME bytes and create no filename.

The count excludes the fixed header, DEFLATE payload and eight-byte gzip trailer. All those bytes, and consumed FNAME bytes, remain part of existing D3 compressed-input accounting. This clarification gives no precedence bypass for physical IO/cancellation/custody/acquisition/resource faults. It grants no read of another candidate or retry/fallback after a refused archive. No header-name character decoding or filename/path extraction is needed: FNAME is ignored metadata. It is never a regular-file path, package/owner identity, source correspondence, output locator or authority.

Keep gzip CM8, allowed FTEXT behavior, forbidden FEXTRA/FCOMMENT/FHCRC/reserved bits, exactly one member/no following byte, CRC32 and ISIZE trailer verification, all complete GNU tar/header/checksum/type/longname/effective-path/duplicate/end/D1/D2 rules and D3 integer population unchanged. Do not partially materialize an archive because its FNAME succeeded. Whole checksum/decoder completion and owned retained custody remain prerequisites for DS-2 assurance/source admission. A D4 profile refusal is not a raw checksum mismatch, final-set bound, successful native observation or implicit owner. Existing MC8 omission/acquisition/final activation/set/carrier rules and NMF-1 actual provenance-sensitive missing-input predicate remain unchanged; generic producer failure is still not missing-input proof.

The numeric choice retains4096total optional-field bytes instead of silently extending physical header allowance to4097. RFC1952 describes a zero-terminated optional name field but supplies no OpenSIP numeric limit or terminator-count selection. The old isolated miniz probe disclosed this total-field interpretation; that probe was neither law selection nor product decoder/admission. New independent boundary controls exercise exact proposed counting only; they do not re-review/reexecute the closed prototype and cannot qualify Cargo compression margins, signed Tool consumer compatibility, scheduling, custody, source, native profile or product.

Publication joins: this is an explicit narrow compatibility selection for the native DS-2 extraction consumer, anchored to the accepted native DS-2 extraction passage and exact accepted MC8 rule1/D4 authority references. It does not rewrite MC8 original bytes, register MC8/D5 as falsely accepted direct lock parents, publish a whole new extractor/profile, or put effectiveL/owner decisions in effect. Actual C3a implementation, every full decoder/control, owned read-completion/source/digest library, acquisition/import/final-set/NIJ/R3/activation/profile/tool/support/owner/product/qualification gate remains required.
