# GPE-1: required Git package eligibility without first-winner admission

Unfrozen prospective narrow selection. All bound native definitions remain closed. This interprets required package eligibility only after a complete DS3 source carrier and its original source/current observation correspondence have actually been admitted under the full source profile. It supplies no new tree acquisition, carrier root, mount namespace, parser read-set, failure code or source/owner admission.

For that carrier, distinguish two independent populations. The complete original retained file manifest/custody/acquisition population contains every admitted file under its owning root and is never derived from Cargo's package/file inclusion filters. The package eligibility population follows Cargo 1.95 commit f2d3ce0bd7f24a49f8f72d9000448f8838c4e850 RecursivePathSource's pinned read_packages/read_nested_packages interpretation of that same bounded owned carrier. Virtual manifests are not packages; unrelated malformed or broken nested manifests retain the pinned eligibility/error behavior. They remain retained source files and count under their source/file manifest/acquisition rules. Their failure to yield an eligible package is not license to crop their bytes, drop acquisition accounting, invent an empty source or claim they were never supplied.

The compatible parser/loader must preserve the complete PackageId-to-eligible-manifest-location vectors before first_package. Cargo's public RecursivePathSource read_packages/query/download methods choose a first package and warn for duplicate locations; their resulting singleton is not a uniqueness witness. A required original Git lock tuple/source must correspond to exactly one eligible real package manifest in the actual owning carrier/current observation. Multiple eligible locations for that required package refuse correspondence rather than warn-and-pick, including duplicates whose publish=false suppresses a warning; zero locations establishes no package and retains its owning missing/malformed/unsupported origin, not a default owner. Exact original lock/source tuple, CSJ1 kind/CanonicalURL/precise identity and NKC1 raw key rules remain mandatory. A mismatched manifest or semantically equivalent lookup that maps ambiguously to multiple raw declared tuples cannot take a first winner.

Preserve the actual original relative manifest ancestry, workspace inheritance and required sibling/parent source bytes within the admitted carrier. Do not rewrite Cargo.toml, hoist a nested member, discard a virtual workspace root or substitute a foreign carrier solely because it declares the same name/version. Eligible foreign packages encountered while interpreting one carrier gain no acquisition row, package key, owner or activation merely from encounter. The actual complete source profile must separately join each requested package to its own admitted supplied candidate and whole file manifest before SourceMap insertion or use.

The required eligible manifest locator is an owned operational correspondence within that carrier. It is not a new global PackageObservationID, a public dependency own2 manifestPath, an absolute metadata path inserted into semantic identity, a SourceSlot trust proof or caller-provided constructor. Existing nonpath NKC1 owner-witness manifestPath stays null; actual manifest/source/tree association is still required behind it. Equal keys/source URLs or a shared Git revision do not merge distinct observations or prove shared physical bytes.

This unit does not adopt Cargo filesystem traversal as security custody. The full compatible producer must establish a bounded complete owned parser read-set, exact path resolution/workspace boundary and no link/escape/ambient read, explicit handling of the pinned walker's permission-error behavior, every source request gated against the same admitted input population and exact source/package/manifest correspondence.
