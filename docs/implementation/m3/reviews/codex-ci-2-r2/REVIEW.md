## Non-blocking observation

**CI2-R2-NBO-1 (P3): Qualify the allocation-free claim to distinguish names from error carriers.** StackName removes the unfunded heap copies identified in CI2-R1-RF-1. The broader statement that no primitive allocates is not literally true on every rejection path: invalid_input and supported_io construct message-carrying io::Error values, and the counting-allocator test exercises successful name-bearing calls plus selected budget/name refusals. The lifecycle allocation guard already explicitly excludes error-carrier construction after refusal. This does not leave an unfunded native-name copy in the admitted transaction, but the scope should state that convention and the tested coverage accurately.

Requested: Describe name/path/target copies as allocation-free, qualify error-carrier construction separately, and avoid claiming the counting test exercises every error path. Allocation-free ErrorKind conversions are an alternative if an unconditional no-allocation primitive contract is intended.
