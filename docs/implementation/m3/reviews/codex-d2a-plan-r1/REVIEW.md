## Decisions and Q1–Q3

- **LD-D2A-1 / Q1: acceptable.** The pure classifier needs explicit reference context for exact replay. Keeping larger test bounds separate from a production constructor fixing bound and offer to 65,536 faithfully implements item 9. The schema minimum plus the offer maximum forces an accepted production helloAck to 65,536. Implementation review must verify that the production construction/update surface preserves that policy, with nonproduction corpus contexts confined to the promised test seam.
- **LD-D2A-2 / Q3: acceptable.** An iterative arena reader preserves integer lexemes and avoids recursive parsing, destruction and comparison on hostile depth. All sixteen-digit signed integer tokens fit i64; larger tokens need no conversion. Decimal/exponent tokens remain non-integers for known-message checks. The reference scanstring accepts escaped unpaired surrogates, and its unsupported-major hello path returns RF1 before the body UTF-8 walk. Preserving such escapes until that walk is therefore correct, including RF1 inside an opaque future-major body. Raw invalid UTF-8 still refuses first. Decoded-key duplicate detection must treat equivalent literal/escaped names alike; no string repair or normalization is authorized.
- **LD-D2A-3: acceptable.** The closed schema interpreter covers the observed keyword vocabulary. Root oneOf is dispatched by the sixteen distinct type constants; message validation implements the specified type, bound, object/array, conditional and negation semantics. There are exactly two distinct patterns, used four times: the full lowercase UUID and full lowercase digest matchers. Rejecting unknown keywords/patterns at load prevents silent schema drift. Identity substitution is a schema-validation exception only; generated carriers are populated after admission and serde does not read wire bytes.
- **LD-D2A-4: acceptable.** The stated ordering matches the checker: framing/parser/frozen envelope; opaque unsupported-major branch; known-message numeric/schema checks with the faulty-seq sentinel and schema-only identity substitutions; UTF-8 bounds over original identity/body strings; deferred RF7; then direction, replay/window/sequence/major, identities, tuples, offer, nonce and effect correlations. An over-offer helloAck is RF2 after applicable RF3/RF4 checks, as recorded.

## Item 11 and controls

The plan introduces no seventeenth control message or common provider semantic frame type. Schema-validation substitutions, seq sentinels and typed construction are internal validation mechanics; they must not alter received octets or supply a substituted received identity. Writing host-owned control frames is separate from translating TS2/Rust3 semantic payloads. The plan leaves provider octets, provider-protocol admission, execution, permission decisions and supervision outside D2a. Its opaque references and supplied effect evidence confer no mint or grant authority.

D2a-T1/T2 cover exact verdict dictionaries, trace state/stops/sequences and the full matrix. D2a-T3 combines prefix refusal with a counting-reader witness and bounded stream reads. D2a-T4 plus the small-stack nested-input test address the retained depth/large-integer failures. Supplementary controls cover -0, opaque future-major surrogates, schema-loader closure, encoder round trips, constructor defaults and the one-tuple offer. These are sufficient plan-level controls, subject to inspecting actual assertions, buffer behavior, production boundaries and nonrecursive traversal during implementation review. Finite corpus replay is not universal proof.

The listed mutations each target a material rule: early seq refusal and missing sentinel expose CCR-1 precedence; omitted identity substitution exposes RF3 handling; UTF-8 walking the substituted copy exposes CCR4-1; delayed helloSeen changes the replay/window ordering; early over-offer changes RF3/RF4 precedence; accepting duplicates changes JSON admission; converting a 17-digit token violates lexeme preservation; dropping refusal if/then weakens the closed conditional body; parsing a stopped direction violates permanent direction stopping. Their implementation verdicts must be genuine assertion failures, not compilation failures or unconditional fault injection.

The proposed equal-failure-set lane, formatting/Clippy, FW-01, environment exceptions, source/mint census, verify_design and unchanged-closure checks are appropriate. P0 and M3-L remain the law's start gates; D2a's unit dependency is P0, and its lack of a code dependency on D1a is consistent with that row and the now-integrated D1a. D3a/D4, D2b, SD-2, supervision and product qualification remain outside plan acceptance.

## Non-blocking observations

### D2APLAN-R1-NBO-1: Show the encoder as fallible and clarify its test population

Section 0 writes encode(&Control3Root) -> Vec<u8>, while LD-D2A-8 requires refusal of a multi-tuple hello. Spell the API as a Result (or an equally explicit typed refusal), and clarify that encoder acceptance tests cover host-sendable messages, while decoder/schema/matrix tests cover all sixteen types. The context candidate already uses Result<Vec<u8>, EncodeRefusal>, so this is a written-plan clarification rather than a missing refusal decision. Generated public carriers alone are not a guarantee of all wire bounds; implementation review should verify invalid constructed output is refused as required.

### D2APLAN-R1-NBO-2: Distinguish frame-buffer storage from parser arena storage

LD-D2A-6's bound-plus-four limit should explicitly refer to the raw stream-frame buffer. LD-D2A-2's arena, container stack, decoded strings and validation work have additional frame-bounded storage, so the one-bounded-allocation wording should not be read as a total allocation ceiling or an exact allocation count. Preserve a clear linear-in-frame storage argument and the nonrecursive Drop/Debug/equality requirement; do not report a 65,540-byte total parser-memory guarantee.
