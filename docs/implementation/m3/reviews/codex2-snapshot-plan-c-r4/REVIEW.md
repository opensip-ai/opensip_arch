## Required finding

### C4-R1 — An oversized prefix is not an admitted oversized package

**Location:** item 12, lines 531, 538–541, 551–554, 564–566 and 578–582; C3-T6c, lines 629–630.

**Problem.** The new oversized-candidate shortcut stops decoding at the per-package protocol threshold, before complete archive-profile admission, then treats activation as proof of admitted-set overflow. It cannot establish that proof, and its route to Cargo activation is unspecified for the stopped candidate.

**Evidence.** The law now correctly excludes rejected archives from protocol totals and requires final package admission before their counts are committed. But line 551 stops decoding as soon as the candidate exceeds 8 GiB or 1,000,000 files, and line 552 requires `DependencySetBound` if activated. A digest-matched archive can contain an oversized regular-file prefix and subsequently fail its gzip CRC, tar end rule, duplicate-path rule or another profile check. Stopping at the prefix cannot distinguish it from a valid oversized package. Under lines 564–566 that rejected archive is not admitted and contributes no protocol bytes; an activated one takes `missing` plus `undecodable`, not a proven set overflow. The same issue occurs at the file threshold. C3-T6c's late-rejection case and oversized case need a combined control.

The adapter path also needs a defined input. Step 1 materializes only candidates inside the profile, and line 565 forbids a partial tree or manifest reaching feature resolution. A stopped candidate has neither completed profile validation nor a complete tree. If it is required, NE:1789–1791 says its absence makes Cargo fail and maps to incomplete input. That does not produce the successful activation evidence assumed by the oversized branch. Naming a candidate “in-profile” in C3-T6c does not supply either missing proof.

**Fix.** Remove the stop at the protocol threshold and complete package validation/materialization within the separate acquisition and D-law scratch bounds. An 8 GiB + 1 candidate is within the 32 GiB acquisition bound. After Cargo supplies activation, commit counts only for fully admitted active packages and apply the protocol limits. A late profile failure retains the existing missing/undecodable disposition. A genuine acquisition or scratch crossing keeps that owner's refusal.

If an early-stop optimization is retained, specify and successor-gate a lawful activation input and a validation process sufficient to prove complete package admission; do not infer those from a decoded prefix or supply an unadmitted partial tree. Add active and inactive oversized candidates with a late profile failure, including a required oversized package whose absence would make Cargo fail. No oversized-candidate route may manufacture activation or count rejected bytes as a set overflow.

## Non-blocking observations

**C4-N1 — The new “D1 alone” control still does not cross D1.** At line 624, an end region of 10,241 bytes cannot exceed the formula at line 556. For n files, even using the maximum 18,431 bytes of permitted per-file framing, total framing is at most `18,431n + 10,241`; D1 allows `18,432(n + 1) + 10,240`, leaving `n + 18,431` bytes of slack. Also, 10,241 is not block-aligned, so the completed stream fails rule 6. Replace this with an aligned stream whose total framing actually exceeds the formula while satisfying the other profile checks. For example, an empty tar stream of 29,184 zero bytes exceeds its 28,672 allowance and is block-aligned. If a separate strict 10,240-byte end-region cap is intended, state that additional check explicitly rather than attributing its breach to this formula. [arithmetic_checks.json](arithmetic_checks.json) contains calculations only.

**C4-N2 — Qualify admission by source route.** Line 531 defines all admitted-set packages as checksum-matched archives inside the profile. The unchanged DS-1 and DS-3 routes at lines 573–574 also yield admitted non-path packages: self-consistent vendored trees and declared Git trees, with no DS-2 archive. NE:1671–1686 and NEM:1846–1875 preserve those cases. State that final totals include every admitted activated non-path source, with full CRATE-ARCHIVE-1 validation required specifically for DS-2. Define how the acquisition package quantity applies to tree candidates as well as archives. Add a mixed DS-1/DS-2/DS-3 counting control; the declared assurance levels must remain unchanged.

**C4-N3 — Commutative totals do not make the first breached field commutative.** Line 550 infers an order-independent refusal from order-independent totals. Four candidates with 8 GiB/one file each, plus four with 1,000,000 files/1,000,000 content bytes each, exceed both acquisition totals while every candidate stays at or below its individual protocol threshold. Reading the large-content group first crosses the byte limit first; reading the many-file group first crosses the file limit first. The code class is the same, but `{field, observed, limit}` differs. Specify deterministic processing/first-breach ordering, or an explicit multi-overflow selection rule. Narrow the claim and extend C3-T6c beyond a single overflowing quantity. The scratch JSON records this arithmetic without constructing or decoding archives.
