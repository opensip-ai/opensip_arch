## Finding

**RF-1.** Item 5’s anchor step cannot be executed by the owner it cites, and the same sentence assigns one public row to refusals that items 14, 16 and 22 assign to another.

F5 (`PROPOSAL.md:251`) requires `ANCHOR_SOURCE`, `ANCHOR_RANGE` and `ANCHOR_UTF8` during the candidate join, before a view exists, by calling the owner. Line 259 says every refusal in item 5, and the item’s opening includes each in-host syntax candidate, takes MJ row 30. The same item rejects a host copy of the anchor law.

The only product function that emits those three keys is `inspect_plan_view_joins` (`crates/evaluator/src/view_joins.rs:388-407`). It walks `view.facts` of a view the caller has already minted (`view_joins.rs:212-223`, `:367-407`). Item 14 (`:416`) runs that function after the view is minted and classifies every refusal as a host invariant (NE:3573). Item 22 (`:614`) repeats that classification for the view self-check: host-internal, `HOST.INVARIANT_VIOLATED`, MJ row 29. Item 16 (`:475`) sends every refusal of a record E3 hands H to that same host-internal row.

A provider anchor that names a blob the sealed inventory does not hold, runs past that blob, or splits a UTF-8 character (IE:164, IE:1426-1429) is a producer-boundary lie. Under the text as written it is discovered only inside a call whose refusal is defined as a host bug, or it is discovered by a copy of the anchor law, which item 5 forbids.

Identity does not close the gap. `payload_prefix` (`crates/identity/src/relations.rs:334-341`) checks anchor cardinality and returns `RelationRule("anchor cardinality")`. `inspect_relation_snapshot` (`crates/identity/src/closure.rs:485-494`) checks that a `file` payload’s anchors name that payload’s path and returns `RelationRule("anchor foreign path")`. Neither emits `ANCHOR_SOURCE`, `ANCHOR_RANGE` or `ANCHOR_UTF8`. IE:1038 uses `FACT_ANCHOR_CARDINALITY` as prose for the cardinality under which the file-row clause is subsumed. It is not the owner’s runtime key, so “the owner’s key verbatim” does not name `FACT_ANCHOR_CARDINALITY`.

**Fix.** Keep payload and snapshot joins on `inspect_relation_payload` and `inspect_relation_snapshot`, and record that owner’s `RelationRule` text as the diagnostic key. Run `ANCHOR_SOURCE`, `ANCHOR_RANGE` and `ANCHOR_UTF8` once, inside the item 14 call, after the view names the facts. When the fact came from a provider return, those three keys take MJ row 30 (`PROVIDER.PROTOCOL_VIOLATION` / provider-protocol, `domainDetail` absent). `FACT_SOURCE_PRODUCER_JOIN`, `FACT_SCOPE_JOIN` and an overlap H introduced while minting take MJ row 29. For a record E3 handed H, every item-5 refusal, including those three anchor keys, stays host-internal, as item 16 already says. Qualify line 259 so it covers provider returns only, and qualify item 14 so a view-join refusal is a host invariant only for the keys H itself assembled.
