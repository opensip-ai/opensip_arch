## Guard behavior

`CandidateBudget::new` starts all three quantities at zero and carries no source, path, class, custody, or admission value. `decode_with_budget` charges one source and returns before `archive_decoder::decode` receives the reader. A source total of 16384 therefore reports observed 16385 with zero reader calls, even when files and content are already at their ceilings.

The existing decoder calls `begin` only for a type `0` entry after the effective path parses. The guard charges one file at that call, before the delegate `begin` and before any content. Path, duplicate-path, long-name, and other non-regular refusals remain decoder profile errors and add no file charge. The announced length is forwarded and is not added to content. A file total of 3999999 accepts the first real BASE member and refuses the next member before its delegate `begin`.

`content` adds only logical payload bytes supplied by the decoder, and it does so before the delegate write. A chunk that stays within the remaining allowance is charged whole. A chunk that crosses charges the lawful prefix, writes that prefix, counts the next byte once, and withholds that byte and the unread tail from the delegate. The observed content value is 34359738369 and the limit is 34359738368. Equality at 32GiB stays inside: BASE's 17 payload bytes succeed from `CONTENT - 17` and write all 17. An empty archive and one empty regular file at the ceiling add sources and, for the empty file, one file, with no content change. The next BASE payload then crosses on its first byte.

A delegate error while writing a lawful prefix is returned with its original token. The budget records `Aborted` and does not replace that error with a later content bound. Checkpoint, begin, content, and end delegate failures do the same. `DecodeError::Io` keeps the injected `PhysicalFault(99)`. `DecodeError::Profile` leaves the stop clear, so a later candidate charges another source on the same budget and keeps the earlier totals. After a bound or an abort, another call returns the same bound or `Unavailable` and does not read the new reader or call the delegate.

The ceilings are 16384 sources, 4000000 files, and 32GiB. The guard uses `Totals` and `Bound` as private data. It does not call the closed whole-file counter API, and it does not change that API. Package name and version stay caller-supplied. There is no canonical sort, filesystem write, public error catalog, CLI route, source capability, owner, context, or Plan/Run/Coverage type.
