## Static rules

The JavaScript, TypeScript, and TSX rules for `string`, `regex`, `regex_pattern`, `regex_flags`, `escape_sequence`, `template_string`, and `template_substitution` are the same objects. A double-quoted string is a quote, a repeat of an unescaped fragment or an escape, and a quote. The fragment pattern is `[^"\\\r\n]+`. The escape token is a backslash plus a form that includes `[^xu0-7]`, so the source characters backslash and `n` are the escape token. `true`, `false`, and `null` are those exact strings. A regex is `/`, a pattern, an immediate `/`, and optional flags `[a-z]+`. The pattern alternative `[^/\\[\n]` admits `a`, `b`, and `+`, and `[a-z]+` admits `gi`. A template is a backtick, a repeat of external template characters, an escape, or a substitution, and a backtick. A substitution is `${`, an expression, and `}`. In each grammar, `template_substitution` reaches `primary_expression`, and that rule directly includes `string`, `number`, `true`, `false`, `null`, `regex`, and `template_string`. The number token's decimal form `\d(_?\d)*` admits `1`.

The retained JavaScript scanner and the TypeScript `common/scanner.h` scanner use the same template-character scan: content ends before a backtick, before `${`, or before a backslash, and empty content is not emitted. Both scanners list `escape_sequence` and `regex_pattern` so they can refuse an HTML comment while those tokens are valid. Their scan functions do not emit those two symbols. The immediate-token rules above are the static rules for the escape and the regex spelling. The TypeScript and TSX `scanner.c` files only forward to that common scanner. The lane pins of those members match the crate bytes read in memory.

Rust `_literal` is the choice of `string_literal`, `raw_string_literal`, `char_literal`, `boolean_literal`, `integer_literal`, and `float_literal`. `string_literal` is `[bc]?"`, a repeat of an escape or external `string_content`, and external `string_close`. Its escape token is a backslash plus a form that includes `[^xu]`. The copied `scanner.c` stops `string_content` at `"` or `\`, and `string_close` consumes a quote, so the recipe span `"a\nb"` is the whole parent rule. `raw_string_literal` is the external start, content, and end. The scanner's start accepts `r`, then hashes, then `"`. For `r#"raw"#` that start is `r#"`, the content is `raw`, and the end is `"#`. `char_literal` is an optional `b`, a quote, an escape or `[^\\']`, and a quote, so `'a'` keeps both quotes. `boolean_literal` is `true` or `false`.
