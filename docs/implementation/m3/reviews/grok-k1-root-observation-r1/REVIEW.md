## Mechanism

`observe_root` runs only when `sys.platform == 'darwin'`. It requires a nonempty argv of strings whose first element is absolute and contains no NUL, an explicit string environment with nonempty keys and no `=` or NUL, a positive integer deadline in nanoseconds, and two nonnegative integer output descriptors. The launch is `subprocess.Popen` with that argv, cwd, and environment, `stdin` at `DEVNULL`, the caller’s stdout and stderr descriptors, `close_fds=True`, and `start_new_session=True`. The helper never calls `Popen.poll` or `Popen.wait`, never reads the collectors, and never turns stdout or stderr text into a public route.

The same call reaps with `os.wait4` on `child.pid`. `InterruptedError` retries. A zero `WNOHANG` result sleeps at most 5 ms, bounded by the remaining deadline. When the deadline is already exhausted, the call sends `SIGKILL` only to that pid and blocking-`wait4`s that pid. It does not signal the new session or any other process, and it does not claim descendant settlement. `ChildProcessError` from the wait propagates without a further signal, so a lost reaping owner is not permission to signal a pid that may already have been reused. `BaseException`, including parent interruption, sends `SIGKILL` to the pid this call created, blocking-`wait4`s it, records `child.returncode`, and re-raises. Exclusive root-reaping ownership, and caller ownership of the authorized command and the two output collectors, are prerequisites stated on the operation. They are not capabilities this result admits.

A launch `OSError` returns `RootObservation` with only `launch_errno` set. Absence of a usable pid, return code, root-reaped time, or RSS is the retained launch fact. It is not proof that zero OS processes existed: a failed exec can leave an intermediate child that `Popen` reaps internally. A returned observation requires the reaped pid to match, the monotonic spawn-to-own-reap span to lie in `1 .. 2**64-1`, and `ru_maxrss` to be an int in `0 .. 2**64-1`. That RSS value stays on the observation. It is not copied into `cgroupMemoryPeakBytes`, not joined to an operational record, and not used as a Q6 sample. Caller-built `RootObservation` values and slot dicts remain supplied data.

## Q0 r13 accounting

`slot_evidence` uses the existing `measurement._slot` classifier and emits only the existing QD-27 fields. Every slot receives `memory-peak-unavailable-platform` and `settlement-unverified-platform`. A missing pid or a nonzero return code adds `run-failed`. A deadline adds `timeout`. Measured rows set `elapsedNanos` and `cgroupMemoryPeakBytes` to null and copy `rootReapedElapsedNanos` from the observation, including null when no root time exists. Priming and warmup rows carry reasons only.

That shape matches DESIGN-r13.md lines 890–897 and the existing `summarize_slots` rules in `measurement.py`. A non-null root-reaped time requires `settlement-unverified-platform`. A measured slot with that reason and without `run-failed` must keep a non-null root-reaped time. A launch with no returned root keeps the time null and carries `run-failed`. A failed run whose root was reaped may keep the known value. `elapsedNanos` stays null, so the root-reaped span cannot enter a median. `cgroupMemoryPeakBytes` stays null. The envelope schema r13 still enumerates these reasons and types `rootReapedElapsedNanos` as seven nullable samples. The helper does not emit an envelope.
