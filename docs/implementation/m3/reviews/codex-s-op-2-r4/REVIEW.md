**SOP2-R4-01 (P1): partition the pre-scope-to-file handoff.** Item 16, lines 614–644, specifies both file pending subtraction and pre-scope pending subtraction, without defining disjoint sets. One buffered file projection can produce two file losses:

1. The producer commits pre-scope enqueue `P=1`.
2. The file capability becomes available. To preserve the stated file enqueue/snapshot subset invariant, handoff commits file enqueue `E=1` before its push.
3. Pause before the file writer exchanges a snapshot containing the transferred record: outcomes `O=0`, pre-scope taken `T=0`.
4. Freeze reads that snapshot, then the tallies. Line 643 derives `E-O=1`; line 644 derives `P-T=1`, also charged to file `drain-abandoned`.

The ordering invariant holds, but the sum is two for one file projection. If handoff instead omits the file enqueue, a later file snapshot with one written pre-scope record makes the first equation `0-1`, contrary to non-negativity. No exclusion or partition currently resolves those alternatives. “Taken” also needs an explicit terminal-accounting meaning if it can precede completion.

Specify which origins the file enqueues and outcomes contain. A bounded atomic file snapshot can hold separate direct-file and pre-scope terminal totals, each subtracted only from its own enqueue total. Alternatively use one combined incoming total against all file outcomes and do not add the buffered pending entries again. Intermediate transfer must retain pending ownership. Preserve `unpersisted` when no persistent sink is admitted. C-7 needs the handoff pause above, asserting exactly one frozen file loss and the same final-envelope count.
