## What the primitive does

`copy_raw` is crate-private. It reads the supplied `Read` through a fixed 4096-byte buffer until a zero count, updates the existing consuming `RawSha256` with each positive slice, writes that slice in order through partial `Write` results, then calls `flush`. A caller `CopyCheckpoint` runs before every read, write, and flush attempt. `Interrupted` retries that attempt and therefore passes the checkpoint again. Any other read or write error is returned as `CopyError::Read` or `CopyError::Write` with the original `io::Error`. A checkpoint error is returned as `CopyError::Owner`. A read or write count past the buffer or the remaining slice is `InvalidReadCount` or `InvalidWriteCount` before any use of the unobserved tail. A zero write count is `NoWriteProgress` and does not loop. `RawSha256::update` failure stays `CopyError::HashLength`, the existing raw-message length error, and this unit adds no separate compressed-size cap.

`Ok(CopiedRaw)` is reached only after EOF, a complete ordered write of every read byte, and a successful flush. The returned `byte_length` and SHA-256 are the plain bytes passed to `update`. EOF and flush do not add bytes. On every error the function returns before that summary. Bytes already accepted by the writer stay where the writer put them. The function does not roll them back, name a source, charge a source attempt, or publish a profile.

The module, trait, error, summary, and function are `pub(crate)` inside a private module. The new files do not use `std::fs`, process, environment, `unsafe`, or serde.
