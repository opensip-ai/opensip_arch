## Encoding and witness shape

`NativePackageWitnessV1` retains exactly `name`, `version`, `sourceId`, and `packageKey`. Name, version, and `sourceId` are the admitted Cargo.lock values, with `sourceId=""` for a path package. `packageKey` is `pkg1-` plus 64 lowercase hex digits of raw SHA-256 of C of the ordered three-element array. The preimage excludes a host path, a Cargo id, an acquisition path, a raw metadata digest, a context id, a wrapper, a domain H, and a trailing newline. The same tuple in two contexts yields the same spelling. Admission scopes that spelling to the one admitted native context whose tuple names exactly one actual package. A conflicting pair inside that context stays inadmissible. The separate source-mapping advisory is not the selector in this unit. Source choice arrives only through the actual admitted owner mapping.

`NativeOwnerWitnessV2` retains exactly `source`, `sourceKind`, the full package witness, `snapshotManifestPath`, and `ownerKey`. It applies to new Rust native build-script and proc-macro prepared owners. `source` is `snapshot-member` or `dependency-closure-member`. `sourceKind` is `registry`, `git`, `path`, or `vendored`. A snapshot-member witness requires `sourceKind` `path`. Every path witness requires `sourceId=""` and the exact admitted in-snapshot `Cargo.toml` logical path. A nonpath dependency witness requires JSON null. The path's basename is `Cargo.toml`, the path is in the sealed snapshot inventory, and the admitted materialization map identifies this package. Those joins are prerequisites. A caller label, a host path, or a lone suffix does not satisfy them.

`ownerKey` is `own2-` plus 64 lowercase hex digits of raw SHA-256 of C of `[source, package.packageKey, snapshotManifestPath]`, recomputed after the package key. Equal name and version at two logical manifests share a package key and receive different owner keys. Moving the manifest changes the owner key. Editing source bytes without moving the manifest leaves the key in place and changes the bound R3-MR1 owner-file-manifest digest. `sourceKind` stays in the witness and stays outside the preimage, so the same tuple and null path share one owner key for registry and vendored acquisition of that tuple. One context still admits only one actual package for the tuple. This raw digest, the package key, `ownerFileManifestSha256`, the native dependency-file-manifest H, `ownerSourceDigest`, `inputBinding`, and an operational grant remain different values.

Both spellings are 69 ASCII bytes, one logical-path segment under `.opensip/out/v1/<ownerKey>/`. PO-1 and PO-4 still require the configuration, site, kind, path, and `inputBinding` join, and the row stays inert. This unit leaves `.opensip/deps/v1/<name>-<version>/`, acquisition namespaces, adapter scratch rules, filesystem alias proof, and collection capacities unchanged.
