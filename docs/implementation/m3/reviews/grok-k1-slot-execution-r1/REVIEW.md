## Schedule

`observe_slots` requires `reset` to be the string `cold` or `warm` and `prepare` to be callable. A cold batch is warmup indexes 0–2 and then measured indexes 0–6. A warm batch inserts priming index 0 ahead of those ten slots. Each iteration passes the callback a copy of the slot dict, requires the return value to be an `Invocation`, and calls the accepted `observe_root` with that invocation’s argv, cwd, environment, stdout descriptor, stderr descriptor, and deadline. The next callback runs only after that call returns. The helper then takes `slot_evidence` for the slot and unions the reason `record-missing`, sorted with `canonical`. It returns the per-slot observations together with `summarize_slots(reset, evidence)`.

The accepted Darwin `slot_evidence` already records `settlement-unverified-platform` and `memory-peak-unavailable-platform`, adds `run-failed` when the pid is absent or the return code is nonzero, and adds `timeout` when the deadline fired. In the existing summarizer, `record-missing` is evidence-only: it makes the batch incomplete and leaves numeric samples unchanged on its own. That composition matches DESIGN-r13.md lines 805 and 890–897 and the reason rows at lines 978 and 982. Warmup and priming rows carry reasons only. The helper emits no envelope and performs no second attempt for a slot.
