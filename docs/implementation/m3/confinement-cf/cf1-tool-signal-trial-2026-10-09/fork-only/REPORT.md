# CF-1 tool signal trial — preliminary, partial

On this recorded macOS host, the original amended tool profile\'s `(deny signal (target others))` permitted SIGUSR1 to reach an owned child and grandchild, while an unrelated owned same-user observer was denied with EPERM. Both trial alternatives, exempting `target children` or `target same-sandbox`, behaved the same. These are new measurements of the specific open CF-1 signal question, not a re-review of accepted CF-P or a policy change.

Two independent first-party fixture sets were run: fork-only, and fork-then-exec through a separately built helper file. Each set contains four variants (unconfined control, original others rule, children exception, same-sandbox exception), each repeated three times. The control delivered all three signals, including the unrelated observer. In every constrained row, apply returned0 and sandbox_check returned1; child and grandchild received their signals and the unrelated observer was denied. In the fork-exec set both descendants independently reported sandbox_check1 after exec, and their reported identities were joined before signalling. Parent receipt confirms actual SIGUSR1 delivery; kill success alone is not substituted for receipt.

All signalling targets were newly created first-party fixture processes owned by this harness. The harness held each root unreaped until process-group cleanup and used only its own recorded groups, then waited on the exact root. A root/group from another unit was never signalled. The two runs each held the owned Darwin lane directory for the whole compile/run set, checked for other builds, used nice10 and an owned0700 canonical temporary directory, and removed only their own lane lock. HOME remained unchanged. No repository source, script, build script, proc-macro, provider or real cargo metadata target ran. Linux lanes did not run.

The fixture applies the trial policy to itself before testing; this is an ad-hoc first-party test, not the production trusted-launcher path. It is neither a signed hardened/notarized launcher nor a signed target closure. The trial therefore does not satisfy CF-1\'s signed-launcher/real-target/per-major enforcement row, change F-3, select a signal policy or prove other signals, arbitrary topologies, setuid transitions or unrelated sandbox populations. The exact current OS version/build are in both results.json files. No production confinement availability, provider launch, effective L or qualification is claimed.

The accepted law and CF-P record leave the signal issue for CF-1, with the expectation that target others would also deny tool children. These limited observations do not reproduce that expectation. The next CF-1 real signed tool-closure control should test retaining the original rule before selecting a broader exception; its full lane evidence and independent publication still remain owed. No existing accepted law or review is rewritten here.
