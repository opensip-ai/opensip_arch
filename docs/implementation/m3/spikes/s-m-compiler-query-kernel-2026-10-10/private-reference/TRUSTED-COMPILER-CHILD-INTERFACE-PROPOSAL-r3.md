# Proposed native compiler information and child boundary

Lead preparation, 2026-10-10. UNREVIEWED and UNBOUND. This is a proposed remaining NP-PREP-04 mechanism, not a complete profile or permission to execute. Existing explicit-constructor and cargo/rustdoc-location DATA controls are closed; they do not initialize rustc or establish actual Tool custody. O7, D3 and D13 are closed, while effective L and actual Tool/owner/worker/qualification remain gated. Preserve the earlier advisory r2 unchanged.

The new COMPILER-CHILD-BOUNDARY-AUDIT-r1.json pins the original Cargo sources and nine concrete boundaries. Native metadata constructs RustcTargetData before resolving the whole workspace. Its host information query invokes the compiler, independently of any later build. Printing a proc-macro output filename does not execute repository proc-macro code. The ordinary cache collects and retains output strings, clones them for consumers, and identifies queries by a u64 process fingerprint. These are observed source facts, not current native capabilities.

## Proposed native branch

Create the compiler state only from the same attempt's actually admitted closure executable and operational private-root capabilities. Do not enter get_tool, resolve a bare name, consult rustup, inspect an original home, or accept a wrapper. Seed this state before Workspace or RustcTargetData can acquire it. The already accepted supplied absolute cargo/rustdoc cells remain their own DATA construction, rather than evidence that this rustc association exists.

Do not call ordinary Cache::load in the native branch. Its fingerprinting resolves and reads executables even with disk caching absent. Native compiler-info caching is fresh and invocation-local, with no persistent cache read or write. A reuse entry must compare the full actual owned query association: exact argument sequence, actual executable/closure association, constructed environment, operational cwd, stdin and relevant interpretation inputs. A hash may accelerate lookup but equality of that hash alone cannot authorize reuse. Store all actual retained buffers and consumer copies under the complete resource lifetime accounting; no free cache allowance or new numeric cap is proposed.

Build each actual child command from an empty environment through the D-owned process mechanism. The context's debugging Env map is insufficient: stock ProcessBuilder uses Command::new and inherits the real environment. Admit only the exact class keys selected by the complete C3b profile and D item3, with all forbidden keys absent. In particular, TMPDIR cannot convey a temporary directory, and no CARGO_HOME variable can convey the private home. All scratch/output/temp locations are actual private capabilities or explicit operational APIs. No inherited jobserver state or descriptors may be recovered from the environment; any owned jobserver association requires its separate exact profile rule. The default proposed native metadata branch uses no jobserver client.

Retain compiler-information behavior needed by the pinned metadata consumer, while prohibiting repository compilation, build scripts, repository proc macros, linkers, wrappers and arbitrary child commands. Publish an exact command-construction grammar for the version probe and the host/requested-target information calls; its arguments must come only from the admitted target and selected projected rustflags, plus pinned first-party query constants. Conditional unstable build-std/target-spec probing must be absent in this profile, rather than accepted merely because the source has such a branch. Do not substitute JustHost for the actual admitted target selection.

Compiler --print=cfg output is operational Cargo query data. The native context's baseCfg still comes from the pinned signed toolchain table under MC8; the query cannot mint that table or silently change its identity. The complete profile must define how producer observations correspond to the actual selected toolchain and target without inventing an unheld manifest version field.

Disable ordinary argfile retry and its default temporary-file owner in the native branch. If a command does not fit the actual platform launch boundary, retain the owning launch failure; do not retry through an ambient file or a fabricated missing-input result. A later explicit charged private argfile API would require its own reviewed compatible selection. This proposal does not permit a fallback path.

The child's cwd, read roots, descriptors, process tree, output capture and deadline/memory ownership remain D's actual owned launch/confinement duties. The native profile must price compiler-info stdout/stderr, cache entries, parsing and copies explicitly. D's metadata Tool fd1 bound is not automatically a new private compiler-info allowance. Actual cancellation, IO, launch, malformed output, closure mismatch and resource failures retain their first owner; neither exit101 nor English stderr proves NMF1 absence.

## Required controls before use

Prove actual closure/path ownership before launch; deny equal-path/equal-byte foreign associations and bare names; verify real child environment/descriptors/cwd rather than supplied maps; reject wrappers/rustup/cache/ambient temp reads before IO; verify exact query arguments and stdin for host and requested targets; preserve same-attempt cache correspondence under distinct queries and deliberate hash collisions; charge every retained output/copy and private write; test cancellation/IO/output/resource failures without missing-input relabeling; prove no build script/proc-macro/repository executable; prove scratch relocation leaves semantic config/key identities unchanged and actual baseCfg remains signed-table derived.

These controls have not run. Exact child-command grammar, real runtime support/closure association, permitted read populations, resource classification/public failure composition and the full source/input/provenance/owner profile must be reviewed together before native use. All six native publication duties remain open. No product helper, inventory, lock, public code or qualification changes here.
