# K1c Darwin root-observation mechanism

An actual fresh caller-authorized root is launched through explicit argv/cwd/environment, EOF stdin, the caller's two output collectors and closed extra descriptors. The caller exclusively owns root reaping. The monotonic spawn-to-own-root-reap span and native wait4 ru_maxrss are observed. No Popen poll/wait may steal wait4 counters. A caller-supplied deadline kills and reaps only this unreaped root; no other process/group is signalled and no descendant settlement is claimed. Parent interruption reaps the created root before propagating. A lost external reaping owner is not permission to signal a possibly reused pid.

A failed launch retains only errno and no usable returned root handle/time/RSS. A failed exec can have an intermediate OS child reaped by Popen internally; this utility does not claim that no OS process ever existed. Signal/nonzero/deadline exits retain actual root facts, not an English stderr route. The helper captures no raw stdout/stderr text, parses no operational record, grants no identity/closure/source/custody/authorization and is not a provider launcher. Caller-supplied RootObservation instances are data, not unforgeable evidence; independent record/lane/custody/selection joins remain required.

All Darwin slots retain memory-peak-unavailable-platform and settlement-unverified-platform. Failed launch/exit adds run-failed, deadline adds timeout. Existing measured elapsedNanos and cgroupMemoryPeakBytes stay null; rootReapedElapsedNanos remains informational when a root was actually observed. Priming/warmup rows carry no numeric samples. The current quality accounting owner validates the resulting reason/null shapes. No Q6 budget input, whole-tree timing or charged-memory measurement is manufactured.
