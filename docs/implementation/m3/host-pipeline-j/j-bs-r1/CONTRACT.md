# J-BS/S13 r1 — first-use backup-status carrier

PROPOSED contract successor under accepted M3-J1 r6 item9. Independent design acceptance, exact root assent, reviewed product schema/regeneration and design-lock binding are required before the amended carrier is integrated. This does not integrate J3d or put L in effect.

The invocation-v5 schema retains its existing $id and major. $defs/RetentionDisclosure gains only the optional backupStatus member, with exactly backed-up, not-backed-up and unknown. Its required policy/provenance/firstUse/storageRoot fields and all other schema values stay unchanged. A conditional if/then/else requires backupStatus exactly when firstUse is true and forbids it when firstUse is false. Missing firstUse is still refused by the existing required member; present null, boolean or other strings are not a status. Presence is not inferred from a detector, minted intent, storage scan or successful response. No invocation6/envelope8 bump or acknowledgement field is introduced.

firstUse is true exactly when this invocation's creator act performed publication rename and returned created=Some, including every refusal after rename. LostRace and NotPristine create nothing and remain false, despite minted intent. The value is the classification retained by THIS invocation's CreationIntent, not a later target probe or another invocation's classification. Under accepted 464 item2 the classifier returns unknown. No missing detector becomes not-backed-up. The notice is still written and flushed before effects; the carrier replaces nothing. No positive backup detector lands.

Once created is Some, every durable success/failure envelope carries retentionDisclosure with policy durable-unbounded, provenance DEFAULTED, firstUse true, the intent's disclosed storageRoot and its backupStatus. Refusals after rename, including attempt B's producer/gate/barrier/recheck failures, retain that disclosure. The empty-errors interrupted branch is the exception: it never carries retentionDisclosure; on first-use interrupt the notice is the carrier. Otherwise durable disclosure starts only after R3 succeeds, with firstUse false, the admitted account-derived storageRoot and no backupStatus. Before R3 it is absent. Ephemeral disclosure starts after capture opens, with policy ephemeral, provenance EXPLICIT-FLAG, firstUse false, temporary custody root and no backupStatus. M3 adds no bounded retention/purge/GC.

The existing envelope7 retentionDisclosure reference already names invocation5's definition, so this successor changes only the selected invocation5 schema copy. The current envelope7 empty-errors interrupted restriction stays byte-identical. The generic RetentionDisclosure shape may represent the three classification spellings; actual M3 emission remains unknown and its policy/timing/creation semantics are separately enforced by J3d, not by a generic shape validator.

The first emitter remains J3d's durable envelope. J-C18 validates every presence combination and interruption absence; J-C19 proves firstUse from this invocation's created value on success and post-rename refusals, with the retained intent's exact classification. Independent schema evidence here supplies generic presence checks and source joins only. It does not execute publication, create a real installation, qualify a classifier or implement the gated host pipeline.

The schema/regeneration code leg follows design acceptance, uses the closed existing eight-output generator lane, re-pins changed schema/registry/generator-closure bytes and separately undergoes exact Grok code review. The schema successor binds after that reviewed code leg, with code and lock in separate product commits. No new inventory path is expected. Accepted units and O1a/J4a/E2s/SOP held worktrees/drafts remain untouched. J3d end-to-end controls, remaining gates and product qualification stay open.
