# F2-min TypeScript provider lane selection (F2MIN-LANE-r1)

PROPOSED. A contract successor selecting, by value, the provider loader policy re-pinned to the F2-min provider worker delta (the Analyze path: import extraction, the symbol census, candidates and Coverage, the broker bootstrap), and the lane registry that names it. It adds no exception, target, loader or capability.

- `provider-loader-policy.json`: F1B-LANE-r1's policy with 18 row digests re-pinned and 28 rows added, at product `51f940e1` (`audit.json` lists them). No row removed; the two exception digests (gen-ts-enums.mjs, compiler.ts) and the two disclosed unfollowed loaders are unchanged. `lane` is the registry's provider lane record, whose `inputs` list gained the added files.
- `product/tools/typescript-lanes.json`: the registry, byte for byte the product file. Its parent is F1B-LANE-r1's copy; the differences are the provider lane's `record.inputs` (the added files) and its `toolPolicy`.

## Why each pin moves

Changed rows (the file's own bytes changed in the F2-min delta):
- `src/context/decide.ts`: the verified context also hands the Program its inputs (`ProgramFacts`).
- `src/data/analyze.ts`: the relation rung table gains `unresolved-edge: observed`.
- `src/data/machine.ts`, `src/data/thread.ts`, `src/main.ts`, `src/node-ambient.d.ts`: the Analyze wiring (READY_ANALYZE runs an Analyze to its terminal, the compiler is imported once at data-thread start), the broker bootstrap before anything else (exit 9), the post-terminal Cancel rule, the Worker `env` option.
- `src/data/pump.ts`: a host frame after the worker's terminal is decided by the machine (one well-formed Cancel is a no-op).
- `src/program/meter.ts`, `program.ts`, `resolve.ts`: the six budget dimensions and the bulk charge; the Program exposes its resolver, confinement and options; `recordFor`.
- `src/embedded/source-census.ts`: regenerated by its emitter for the new file set.
- `src/test/census.test.ts`, `context-census.test.ts`: the census guards name the Analyze path's edges (runtime imports into `src/program/`, the census harness, the `unitRoot` users); `context-decide.test.ts`, `control.test.ts`, `machine.test.ts`, `emit-golden.ts`, `fixtures/program/support.ts`: tests, the golden emitter and the unlimited test meter follow the new behaviour.

Added rows (new files, all lane inputs): `src/bootstrap.ts`, `src/data/run.ts`, `src/facts/*.ts` (admission, analysis, candidates, census, census-wire, coverage, imports, manifest, offsets, scope, subject-ids, text) and the F2-min tests and fixtures. None adds a loader, a built-in module route or an exception: the policy's two exceptions and its two disclosed unfollowed loaders are unchanged, and the K-5 census (`src/test/census.test.ts`) still admits `node:fs` only in the files it names.

`tools/check_typescript.py` verifies the design lock, finds this registry's digest in exactly one accepted contract successor (this unit, once bound), pins the 161 checker files, then runs the `report`, `provider` and `generator` lanes. The provider lane's boundary check pins the 107 policy rows to the product bytes, requires `policy.lane` to equal the registry's provider lane record, and runs the provider's tests and census checks. Also required, and staged separately as F2MIN-INVENTORY-v252-r1 (the provider lane refuses a bound package input that has no selected inventory row): the additive inventory successor v252, whose own review, assent and design-lock entry come first (the lock's `inventoryPassageInheritance` is re-derived by that binding).
