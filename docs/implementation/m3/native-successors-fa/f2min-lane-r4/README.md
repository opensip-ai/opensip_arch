## Why each pin moves

Changed rows (the file's own bytes changed after F2MIN-LANE-r2's staging at product `6e5a40f4`):
- `src/data/thread.ts`: the data thread takes the main thread's stop cell `stop` from `workerData` and passes it to `writeDescriptor` for fd1; a write that returns "stopped" (the cell was raised while fd1 was full) calls `pump.stop()` and returns, so nothing more is written on fd1 (8 lines added, 2 removed).
- `src/embedded/source-census.ts`: the output of `scripts/embed-source-census.mjs`: the same 96 entries by path; the five entries that moved are the other five re-pinned files, each entry now equal in bytes and sha256 to that file; `SOURCE_CENSUS_SHA256` changed (16 lines added, 16 removed).
- `src/fdio.ts`: `writeDescriptor` retries on a non-blocking descriptor: EAGAIN, EWOULDBLOCK or a zero-byte write waits on the stop cell (`Atomics.wait`, 1, 2, 4 then 8 ms) and retries from the same offset, EINTR retries at once, any other error throws; it returns "written", "stopped" (the cell was raised) or "full" (`patience` waits with no byte written), and takes an injectable write function; adds `stopCell`, `raiseStop`, `WriteFn` and `writeControl` (fd4: about a second of patience, then the error "fd4 not drained"); `diagnostic` (fd2) waits not at all and drops the line under a full pipe; comments state the non-blocking invariant (review A2) and the diagnostic loss (A3) (68 lines added, 6 removed; `readDescriptor` and `closeDescriptor` unchanged).
- `src/main.ts`: the `spawn` callback makes the stop cell and passes it to the data thread in `workerData` (the Worker options stay exactly `{ workerData, env }`); the data link given to the control loop raises the cell before posting `data-stop` and before `terminate`; fd4 writes go through `writeControl` (24 lines added, 6 removed).
- `src/test/census.test.ts`: adds the test "census: FDIO-SYNC-1 A2 the data thread's Worker is constructed without stdout or stderr options": over the census text, the one production `new Worker(` is in `src/main.ts` and its options are exactly `{ workerData, env }`, naming neither `stdout` nor `stderr` (22 lines added, none removed).
- `src/test/control-loop.test.ts`: adds three FDIO-SYNC-1 tests (T3, T3, T4) of `writeDescriptor`, `writeControl` and `diagnostic` over an injected scripted write function, touching no descriptor: the retry from the same offset, EINTR not spending patience, a raised stop cell ending the write with nothing more written, the patience bound, hard errors thrown, fd4 giving up, and a full fd2 dropping the line (64 lines added, none removed).

## After the change the lanes check

`tools/check_typescript.py` verifies the design lock, finds this registry's digest in exactly one accepted contract successor (this unit, once bound), pins the 161 checker files, then runs the `report`, `provider` and `generator` lanes. The provider lane's boundary check (`tools/typescript-boundary/bin/check-boundary.mjs`, launched by `tools/check_typescript.py`, which runs `src/check.mjs`'s `checkBoundary`) pins the 107 policy rows to the product bytes, requires `policy.lane` to equal the registry's provider lane record, analyzes and emits the package source and scans it for loader edges, and checks the boundary census and its staleness.
