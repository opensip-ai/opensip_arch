# F2-min TypeScript provider lane selection, restage 5 (F2MIN-LANE-r5)

PROPOSED. A contract successor selecting, by value, the provider loader policy re-pinned to the provider as it is after BOTH of the provider's reviewed changes since F2MIN-LANE-r2: FDIO-SYNC-1 (the data thread's writes on a non-blocking fd1 and the stop cell; F2MIN-LANE-r4) and PROVIDER-14A-1 (the path `extends` candidates of erratum M3B-14A-E1 r2; F2MIN-LANE-r3), merged in the integration train's second car; and the lane registry that names it. It adds no exception, target, loader or capability. Its parent is F2MIN-LANE-r4's registry copy, the registry that product main selects. F2MIN-LANE-r3 is a sibling of r4 (each has F2MIN-LANE-r2 as parent); it is bound in the design repository, but the product's design lock does not carry it, so it cannot be named as a parent (the verifier accepts only parents the lock has accepted); this unit nevertheless covers r3's provider change too, and the policy rows are compared with r3's below. F2MIN-LANE-r1, F2MIN-LANE-r2, F2MIN-LANE-r3 and F2MIN-LANE-r4 stay bound and unchanged; this unit's registry differs from each of r3's and r4's only in the provider lane's `toolPolicy` (this unit's policy path; r3's copy is compared by the stager, not named as a parent), so the product registry's digest is selected by this unit alone.

- `provider-loader-policy.json`: F2MIN-LANE-r4's policy with 5 row digests re-pinned and 0 rows added (equivalently, F2MIN-LANE-r3's policy with 6 row digests re-pinned and 0 rows added), at the frozen provider commit `fd407249` (the merge of the stack's PROVIDER-14A-1 provider commit `3b694794` into product main's FDIO-SYNC-1 provider commit `37123b16`; the `providers/typescript` tree `707c81c82b1624517ce41853f16a2f6a5c761085`, which the product head `758f4d3e` has too; `audit.json` lists the rows). No row removed; the two exception digests (gen-ts-enums.mjs, compiler.ts) and the two disclosed unfollowed loaders are unchanged. `lane` is the registry's provider lane record, unchanged from r3 and r4.
- `product/tools/typescript-lanes.json`: the registry, byte for byte the product file. Its parent is F2MIN-LANE-r4's copy; the one difference from it, and from r3's copy, is the provider lane's `toolPolicy`.

## After the change the lanes check

`tools/check_typescript.py` verifies the design lock, finds this registry's digest in exactly one accepted contract successor (this unit, once bound), pins the 161 checker files, then runs the `report`, `provider` and `generator` lanes. The provider lane's boundary check (`tools/typescript-boundary/bin/check-boundary.mjs`, launched by `tools/check_typescript.py`, which runs `src/check.mjs`'s `checkBoundary`) pins the 107 policy rows to the product bytes, requires `policy.lane` to equal the registry's provider lane record, analyzes and emits the package source and scans it for loader edges, and checks the boundary census and its staleness. It does NOT run the provider's tests or its freshness commands: those are the separate `npm` commands in `providers/typescript/package.json`, and a green boundary result does not establish that they ran. No inventory successor is staged with it: no file is added or removed relative to F2MIN-LANE-r3's and r4's provider trees, and the bound inventory v253 pins no file's bytes. Missing before binding: the independent review (verdict ACCEPT-DESIGN-UNIT naming this subject manifest's digest) and the lead's assent record (`f2min-lane-r5-unit.json`); then the design-lock entry (`bind_f2min_lane.py`). The product commit that carries the lock also carries the registry with this `toolPolicy`.

The code was reviewed separately (the FDIO-SYNC-1 and PROVIDER-14A-1 reviews). No product qualification follows from this unit.
