# Enumeration reference integer-conversion process profile

Proposed reference-only successor. All new complete reference executions use the pinned CPython3.12.13 interpreter with `-I -B -X int_max_str_digits=0`. Enumeration checks both startup flags and effective runtime value at import and every package-projection entry. An incompatible interpreter raises the separate ReferenceEnvironmentError; it must terminate reference execution and must never become a repository syntax finding, resource outcome, or enumeration refusal. No per-call process-global mutation is performed. The rest of the reference AST is unchanged.

The existing oracle inherits an ambient CPython integer-conversion cap. A valid manifest containing an unused4301-digit decimal field raises ValueError under the default4300cap, although an equally long hexadecimal literal parses. The chosen process profile removes that ambient difference and preserves arbitrary numeric literals for package classification. This is an OpenSIP/CPython oracle choice, not a claim that TOML1.0 mandates arbitrary-precision integers. Rust retains literals and adds no decimal conversion cap. Existing JSON-profile rules, Cargo syntax/UTF8 failures, identities, schemas and enumeration law are unchanged.

The portable checker accepts --source32 (extracted frozen export), --source32-manifest, --python (pinned3.12.13 executable), and --output (fresh directory). It checks every reference member against the frozen source32 manifest before copying; the only overlays are separately pinned before/new enumeration modules. Its child processes set the explicit profile flag. It preserves the earlier UnicodeDecodeError syntax correction. Old frozen reference evidence and historical harnesses are unchanged. Future harnesses must load the complete new module or carry its helper/environment class and function-entry gate; a single-function AST overlay may not omit these dependencies.

Official process-setting semantics: https://docs.python.org/3.12/library/stdtypes.html#integer-string-conversion-length-limitation. Isolated -I ignores PYTHONINTMAXSTRDIGITS, so that environment variable is not a substitute for -X. TOML integer representability guidance: https://toml.io/en/v1.0.0#integer. The Python oracle still performs integer conversion and has development execution costs; this is not resource/security qualification.
