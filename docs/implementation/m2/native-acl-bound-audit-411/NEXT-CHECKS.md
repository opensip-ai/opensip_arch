# Concrete follow-up for audit411

No qualification or adapter change is accepted by this note. The next experiment should request bounded descriptor-based volume capabilities and establish actual valid/supported VOL_CAP_INT_EXTENDED_SECURITY alongside ACL capture. Pinned XNU code reports EXTENDED_SECURITY only when va_acl is supported and non-null; the current32-byte no-ACL fixture therefore cannot alone distinguish null ACL from unavailable support. A positive supported-volume premise plus exact pinned platform semantics may disambiguate that case, but must be established and rechecked on the same descriptor; a filesystem name string alone is not evidence of every capability. Unknown/missing capability remains a refusal.

Compare two implementation choices before changing product source: (1) derive a qualified conservative allocation/work bound for the existing statx wrapper using its strictly growing returned-size loop, bounded native filesec size and fixed ACL conversion allocation; or (2) replace variable user-space capture with fixed caller buffers and checked attribute/ACL parsing, preserving error, absence, identity and custody semantics. Option1 needs actual supported-runtime/kernel/libc provenance, not only public main-branch source. Option2 needs native positive/empty/unsupported/denied/truncated/malformed fixtures and an explicit metadata/ACL observation consistency rule. Neither is justified by this single probe.

Do not use private syscall symbols merely because libc calls them. Never set KERNEL macros to fake SDK declarations. sys/acl.h before sys/kauth.h is sufficient for the relevant public layout declarations, as probe-r3 demonstrates. All OS-account and UUID-membership service allocations/latency remain separately disclosed TCB premises; the number of outer calls is not their full allocation proof.
