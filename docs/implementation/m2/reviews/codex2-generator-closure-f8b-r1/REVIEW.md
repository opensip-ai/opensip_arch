## Required finding

### F8B-RF-1 — Give the rebuild-01 comparison a separate evidence procedure

**Location:** PROPOSAL.md:94, Procedure step 5, following the pin updates at line 90.

Step 4 installs rebuild-02's observed receipt and selects its executable in both `toolchain.json` and the closure. Step 5 then asks for the same public drift check with rebuild-01 to establish output equivalence. For the different executable digest that the proposal expects, that invocation cannot generate any output.

At the reviewed product commit, `tools/generate_contracts.py:67–83` joins the selected toolchain, closure and build receipt before calling the pipeline. `tools/contracts/pipeline.py:40–44` compares the supplied executable with the selected generator pin and raises `tool bytes differ: generator` before snapshotting inputs or running a child. The synthetic assent authorizes the new closure; it does not change this executable check. Restoring the old receipt is also insufficient: `tools/contracts/adapter.py:19–26` joins both the exact Cargo.toml source bytes and the executable pin, and rebuild-01's receipt describes the unlicensed manifest.

**Required correction:** Keep the selected public drift gate on rebuild-02 and replace the rebuild-01 bullet with an explicit comparison procedure. A disclosed, separate executable-equivalence probe can run each observed binary against identical prepared inputs, compare every generated byte, and cover both generator invocations: ordinary generation (`pipeline.py:132`) and `--format-rust` (`pipeline.py:160`). Identify the actual inputs, outputs, binary pins and scripts in the frozen evidence. Describe that probe as comparison evidence, not as admitted F8b drift. Alternatively, specify a fully coherent comparison snapshot and its distinct selection assumptions. Do not hand-edit the receipt or weaken the selected public checks.

Until this is specified, the promised functional fallback when normalized executables differ is not executable as written.
