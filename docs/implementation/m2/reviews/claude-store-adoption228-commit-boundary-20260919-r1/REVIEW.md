## 0. Correction to my root-check Case B — withdrawn
I proposed `prepare_commit(ReplayedRun, CommitSession)` under a generic-`mutation` `evidence-restore` operation. **[E]** workflows §1 (l.82–85): "Only `analysis` and `verify` steps seal or link a content-derived `run3`. `comparison`, `query`, `render`, `import`, `repair-preview`, `repair-apply`, `test-execution`, `native-preparation`, `mutation`, `export-delivery` and `doctor` are operational steps that never mint a Run." A commit receipt, Run manifest and SEAL from a `mutation` step is exactly what that sentence forbids. Root is right that this would change a core invariant, not fill a missing row.
I also proposed "evaluated iff the commit operation is a seal; imported iff a record exists" as a Run-level standing. **[E]** `run3` is content-derived and "Duplicate retry can share a Run but has a separate attempt receipt" (identity l.1683); the same Run can be imported, later analysed locally, or arrive from several origins. A RunId-global bit is contradictory as soon as two histories coexist. Withdrawn.

## 1. The two paths against source boundaries
**Path A — widen the commit law.** Requires amending, together: workflows §1's closed seal/link list and the invocation-record schema's step semantics; `CommitSession`'s permitted-operation set (**[E]** build plan l.64: it "Binds namespace, store generation, ExecutionId, admitted producer closure and permitted operation"); the meaning of `commit-receipt` (**[E]** identity-schemas v3: eight members, including `sealedAssurance`, no provenance discriminator) — every reader that today treats "a joined commit receipt" as local commitment (**[E]** identity l.1716: "A valid joined receipt establishes historical commitment on its own") would have to learn a selector, and **any consumer that forgets it grants authority to foreign evidence**. A fails *open*.
**Path B — guarded maintenance admission, no Run row.** Verified immutable objects plus a distinct imported-evidence record and retention root; no authoritative Run manifest, no commit receipt, no SEAL, no invocation Run link. Every existing authority consumer keeps requiring what it requires today — a local seal/link — which imported material never has. B fails *closed* by construction. **I agree with root: B.**

## 3. Same-Run mixed provenance **[P]**
Standing is **not** a property of a RunId. It is the *set of provenance records* that exist for it, each scoped to its own act:
- **Local commitment:** zero or more `commit-receipt`s, one per local analysis/verify attempt (**[E]** "Duplicate retry can share a Run but has a separate attempt receipt"; build plan l.82: "A new attempt using the same semantic Run still requires a new session and its own ExecutionId/receipt").
- **Imported evidence:** zero or more imported-evidence records, keyed by `(runId, origin bundle seal digest)` — one per admission, so several origins coexist.
Rules: (i) an authority consumer asks "does a local seal/link exist?" and never consults imported records; (ii) a read selector names which record kind it relies on and reports both when both exist; (iii) a later ordinary local analysis that derives the same `run3` performs a **normal** commit — the blobs are already present and content-addressed, so publication is idempotent at the object layer — and deletes nothing: the imported records remain as history; (iv) importing a Run that is already locally sealed adds a record (and, if bytes were missing, Case A's availability transition) and changes no standing; (v) neither a scope exemption nor caller-supplied JSON creates either kind of record: local commitment comes only from `prepare_commit`, imported evidence only from the guarded admission after complete replay under current trust.

## 4. Export
**[P]** agree with root: `evidence export` initially requires an existing **local commit inventory** per Run; a Run present only as imported evidence refuses with a typed detail. Consequence to state openly: a backup of a machine whose evidence is partly imported does not round-trip the imported-only part. If that is later required, the export owner needs an explicit closed `inventorySource` variant (`local-commit{executionId}` | `imported{originSeal}`) so a re-exported bundle says truthfully whose inventory it carries; a foreign commit receipt is never presented as local.

## 5. What B adds, in total
One guarded maintenance admission API (input: `ReplayedRun` + a maintenance session under fence/lease; output: not a commit); one insert-only imported-evidence record `{runId, origin seal, origin ProjectId, origin host release, origin inventory, local verification}` **(shape owed)**; one retention-root kind; one read-selector variant and one typed refusal detail; purge semantics **[U]**. It removes from my earlier notes: the `evidence-restore` member of `CommitSession`, any local commit receipt for foreign Runs, and the RunId-level standing bit.
