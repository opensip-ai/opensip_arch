## 0. Correction to my 228 r1 E-1 wording
I wrote "no imported-evidence publication after REV". Root is right that this erases an inherited distinction. **[E]** S6: "`ADMITTED = 1`, `LATCHED = 2`: `0` is preparing, `1` admitted, `2` latched before admission, `3` admitted then latched. Commit admission is a compare-exchange `0 → 1`; the observer always fetch-ORs `2`, including `1 → 3` … A latch winning at state `0` prevents the gate entirely. State `3` does **not** revoke the already admitted attempt or relabel its outcome: it records the latch and forbids further effect admission or retries. The observer bound bounds admitting new effects; it cannot abort an in-flight syscall or rewrite its outcome. A confirmed durable commit stays committed; an uncertain commit or barrier stays durability-undetermined with its ExecutionId and no automatic write retry. The gate orders admission only and is not the durability point." The correct statement is: **no *admission* of an imported-evidence publication after the latch**; an already admitted one completes, keeps its durable outcome, is never retried, and its delivery fails/discloses.

## 2. Proposal **[P]** — one IRREVERSIBLE brokered effect, no SEAL, no journal-schema change
**Records:** `RA → ICI → (native publication) → ICO`. The publication is append-only into an immutable ledger with a new retention root; it has no lawful `inverseRef` (purge is a separate EXCLUSIVE authority), so it is the IRREVERSIBLE pair, not RCI/RCO. `SEAL` and `runId` are never used; no `commit-receipt` is written.
- `operationRef` = the maintenance operation's ref; its ExecutionId is recovered through the inherited `AttemptCustodyV1` mapping — the **original attempt** that did the replay is the one that publishes.
- `requestRef` = a bounded opaque id of this publication request (it must not smuggle RunId/seal semantics into the journal).
- `ICO.postimageSha256` = raw SHA-256 of the canonical bytes of what the ledger transaction published (the imported-evidence record set + retention-root rows), binding the outcome to exact bytes with an existing member.
- **Join without touching the journal:** the ledger transaction also writes a *private association* `{executionId, grantGeneration, icoSeq?/iciSeq, postimage}` beside the imported-evidence record(s), exactly as the commit path writes "exact receipt and private recovery association in one synchronous ledger transaction". The **maintenance receipt** is the inherited `receipt_id` over (carrier digest, grant generation, ICO sequence) plus that postimage — it is not, and cannot be parsed as, a Run `commit-receipt`.
**Order (mirrors facade steps 3–6; nothing slow under the final lock):**
1. *Before any lease:* under the fence, all host-owned trust work — 222 successor check and durability reconfirmation, S4 write-ahead, clock-driven role events — then epoch capture at operation start (S6). Acquire APPEND-WRITE; release the fence. **From here no `I/trust` write and no fence re-acquisition**; if one would be needed, refuse.
2. Replay and stage verified immutable objects as **unreferenced** content-addressed blobs. They are not a retention root and confer nothing; a refusal or crash leaves GC-eligible orphans (inherited: "Orphan blobs are unreferenced and eligible for GC after reconciliation").
3. Prepare the level-3 transactions non-waiting, journal first, ledger second; on failure release and return busy.
4. Take the level-4 append checkpoint and, under it: writer guard/lease still held and store binding unchanged (custody); **re-read the trust epoch** and apply S6's predicate to every closure the replay relied on (a higher counter naming one, or a policy-digest change removing a required grant ⇒ refuse; unrelated change ⇒ drift recorded); observer freshness (last successful read ≤ 10 s); grant generation still current; operation not cancelled. Then the **gate `0 → 1`**. If the observer already latched (`0 → 2`) the gate fails: **no RA, no ICI, nothing published**, typed refusal, staged blobs stay orphans.
5. Append **RA** then **ICI** durably (intent before effect), publish the ledger transaction (record(s) + retention root + private association) and satisfy its barriers, append **ICO COMPLETED** with the postimage. Release.
6. A latch arriving after admission (`1 → 3`) changes nothing already admitted: the publication completes and stays durable; no further effect is admitted and nothing is retried; delivery reports the latch. An uncertain barrier is `durability-undetermined` with the ExecutionId.
**Crash / footprint table (inherited rule: the footprint decides, never the missing record):** RA only ⇒ REV `process-death`, CLN `not-begun`; ICI without outcome and ledger rows absent ⇒ not begun/failed via the CLN residual path; ICI without outcome and rows present with the recorded digest ⇒ recovery appends `ICO COMPLETED`; undeterminable ⇒ nothing appended, indeterminate, retry-later. Read-only `recover(ExecutionId)` inspects, never repeats.
**One permit, one prepared publication.** **[E]** "A successful gate mints one internal single-use permit for the already prepared commit and is not a reusable grant for later effects." So a bundle's records and roots are **one** ledger transaction under one permit (all-or-nothing per bundle — which is also RESTORE's "publish nothing until the whole bundle verified"), bounded by the ledger transaction limits; a bundle too large for one transaction refuses at preflight rather than publishing in slices under a reused permit.

## 3. The additional typed law this needs (smallest set)
1. **S6 amendment, one sentence:** the commit-admission gate also admits *one prepared imported-evidence publication*; the permit is typed by what it admits and is not interchangeable with a commit permit. (Today's text says "commit".)
2. **Security type:** an opaque `MaintenanceSession` created only by security admission (registered project/store custody, live writer guard, actual grants, operation identity `evidence-restore`, grant generation). It is **not** a `CommitSession` and has no conversion to one.
3. **Storage API:** `prepare_imported_evidence(ReplayedRun…, MaintenanceSession) → PreparedImportedEvidence → PublishedImportedEvidence`; none of these converts to `PreparedCommit`/`PublishedCommit`. Generic maintenance does **not** inherit the facade checkpoint; this path states its own, identical in content to step 5 of the facade.
4. **Grant row:** RA presupposes a current grant; the permission truth table needs an explicit effect value for "append imported evidence to the project ledger" **[R — I did not find one; not invented here]**.

## 4. Risks and points to verify
- **[R] schema-3 `outcome` is `const "COMPLETED"`**, while v8 §7.5 speaks of `ICO COMPLETED | FAILED | INDETERMINATE`. Under the current schema the non-completed endings must go through the CLN-residual/footprint route, as §2 assumes; root should confirm how current recovery expresses them before relying on either.
- **[R] `AttemptCustodyV1`** is described for committing attempts; confirm that a generic-mutation attempt has the same `executionId ↔ operationRef` row, otherwise the association needs its own attempt-custody entry.
- **Consequence to disclose:** `REV(trust-revoked)` rolls back only *reversible* effects; an imported-evidence publication admitted just before it is irreversible and is "disclosed as completed". Read selectors therefore must evaluate current trust at read time (a revoked closure "is never executed, whatever bytes are present") rather than treat presence as standing.
- The three-step durable sequence (RA+ICI, ledger, ICO) spans two SQLite carriers and is **not** atomic; correctness rests entirely on intent-before-effect plus footprint-decides recovery, as it does for HE-1.
- Holding the level-4 mutex across the ledger publication is lawful only because that transaction contains rows alone (all bytes were staged in step 2); if record sets grow large, the "nothing slow under the final lock" rule becomes the binding limit.
