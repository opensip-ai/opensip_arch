## 3. Census inference and partition

**Partition — sound, and the right strengthening.** Separating locally constructed records (`I/trust/records`, `NodeRef`) from imported bodies/envelopes (`I/trust/objects`, `DocRef`) removes the confused-deputy route my r2 proposal left open: an importer content-addressing attacker-chosen bytes that *parse* as a descriptor. With "internal typed constructors only" and "equal hashes across the two collections are not an authority cast", descriptor evidence can only originate locally; if custody of `I/trust` itself is lost the capsule is lost too, so nothing weaker is being trusted. The closure, BeginBatch, history nodes and prepared images all fall on the records side and reference objects one-way — consistent.

**Inference — correct as stated, with one false positive and one unstated consequence.**

### R-1 (Medium) — power loss can fabricate "rollback" evidence: a successor may be prepared from a capsule that is current but not yet durable
r3 (correctly) narrows the inference to "n was **admitted as current** … not that its original caller received durable success". But the detector's *conclusion* is "the observed capsule is behind ⇒ retained rollback refusal/quarantine", and that conclusion needs **durably** current. Reachable without any restore: invocation 1 replaces the capsule and stops before confirming the file/parent barrier ("uncertainty stops further effects"); invocation 2 admits the *visible* capsule n+1 as current and durably publishes the records for n+2; power is lost; the unconfirmed rename is gone but the fsynced records survive. The store is now at n with a proven-committed descendant n+1 on disk — a quarantine for an install nobody rolled back.
Probe (`claude-out/probes/census_false_positive.py`, owner model unmodified, result `io/census-false-positive.json`): without reconfirmation the crash world `{capsule r1, records D2 and D3}` exists and the census proves r2; with reconfirmation no crash world yields a proof.
**[P] one rule:** *step 1 of the publication law (re)confirms the current capsule's file and parent durability barriers under the fence before any record of the next revision is published.* Then "D(n+1) exists ⇒ n was durably current", which is what the quarantine rule needs; the original-caller caveat stays true and harmless. This also makes the repeated-`acknowledge-restore`-after-uncertainty sentence exact.

### R-2 (Medium) — what the detection is compared on, and what ends the quarantine
(a) r3 triggers "when its accepted heads/counters contradict the restored current state". The capsule is the sole authority and its revisions are linear per store, so **any** proven-committed descendant means the observed capsule is not the latest durable state — including descendants that changed only F/L/anchor, a private reset, a batch binding or audit. **[E]** v8 §5.5 keeps "`evalHighWater` as floors" and "a restore never decreases a counter"; a lost clock revision is a lowered floor. **[P]:** trigger on *existence* of a proven-committed descendant of the same store, not on a field comparison.
(b) r3 forbids the census to "raise a counter" — right — but then a detected rollback ends exactly like an undetected one: **[E]** v1 quarantine lasts "until an ordinary payload re-establishes state", and that payload is checked against the *rolled-back* counters, so a payload between the rolled-back and the true counters is accepted. Detection would then deny service without protecting anything. **[P], refusal-only and adopting nothing:** *while a proven-committed descendant exists, an ordinary payload whose root/catalog/revocation versions are below the greatest versions named by any proven-committed descriptor of this store is refused.* Nothing is read from those descriptors except three integers used as a lower bound; no head, identity or floor is installed from them; the accepted payload installs its own. If root prefers not to add this, the text should say plainly that detection changes availability only.
(c) State the consequence of *detection-unavailable* for `acknowledge-restore`. Since the declared reset is itself purely restrictive, I suggest: unavailable detection is reported and does **not** block the declaration — otherwise an install whose records collection has simply outgrown the census budget can never declare a restore.

### R-3 (Low–Medium) — the closure makes the work profile an undeclared payload-size cap, and the ordinary time-proof closure should be the minimal one
`payload.schema.json` allows 100,000 manifests/envelopes; the profile admits 65,536 distinct objects. A schema-lawful recovery payload whose signed-scope metadata exceeds roughly half the profile (body + envelope each) can never be staged — acceptable as a deliberate bound (r3: "refused before staging … never truncated"), but it should be **stated as an effective cap on recovery payload metadata**, as I noted for the journal bound in 206. Separately, "ordinary refused-import time proof uses the same retained metadata-closure owner" should not mean the same *contents*: the time witness relies only on manifest/envelope, root chain and revocation context (r6 D). If every ordinary import had to retain all role-member proofs before its S4 write-ahead, every large ordinary payload would be refused by the closure budget before dispatch. **[P]:** same owner/codec, two closed scopes — `time-proof` (manifest, chain, list) and `ceremony` (full signed scope).

### R-4 (Low) — census start and cost
Finding the descendant of the observed capsule means matching `previousCapsule` across the records collection, which never shrinks (no GC), so the census cost grows with every revision ever prepared, orphans included. That is consistent with "bounded, detection-unavailable on exhaustion", but combine it with R-2(c), and say that only **descriptor-kind** records are parsed (kind is known only after a bounded read — charge it), so history/closure nodes cost one entry each rather than a full admission.
