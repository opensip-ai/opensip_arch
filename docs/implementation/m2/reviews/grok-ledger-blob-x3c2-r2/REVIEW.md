## Law items 4 to 7 and 9 to 11

`publish_objects` takes `&AdmittedAttempt`, and `admit_attempt` returns that token only after its own `COMMIT` succeeds, so no object is written before the attempt row. Length and SHA-256 are checked with `VerifiedBlob`, and a repeated digest is refused, before the first `publish`. The whole commit is one charge (`OBJECT_COST` of 1 object, 12 edges and 512 bytes, plus each declared length). A short ledger returns the budget failure with no write.

Publication calls `blob_store`'s `publish`: `publish_new_regular`, and only an exclusive-link `AlreadyExists` with unchanged visibility and no cleanup error falls through to `confirm_existing_regular`. `confirm_existing_regular` compares every byte and applies its own file and directory barriers. A second link or a mode with group or other write is `InvalidData` from `confirmation_metadata`. With the objects directory still reachable, `InvalidData`, confirmation `InvalidInput`, and `ELOOP` are `LEDGER.CORRUPT`, and the entry is left in place. Prepare's non-regular refusal (`Publication` at `Prepare`, `InvalidInput`, no errno) is the same row. An unreachable objects directory on that confirmation path is `StoreCustodyRefusal::NameChanged` (`CONFIG.CUSTODY_REFUSED`, subject `name-changed`). Any other publication or I/O error is host I/O. A failure returns before `PublishedObjects` exists. The module contains no delete, unlink, rename, `OR REPLACE`, attempt update, `ReadSnapshot`, or `busy_timeout(`, and exactly one `.commit()`.

`begin_prepared_ledger` consumes `PublishedObjects`, so level 3 follows every barrier. Another attempt's objects refuse as `StagingMismatch` before `open_verified`. `open_existing` sets `busy_timeout` to 0 and checks it, then `BEGIN IMMEDIATE`. Busy is `LEDGER.BUSY_TIMEOUT` and the refusal holds no `WriteTransaction`. `PreparedLedger` is owned, not `Clone`, and has no SQL method. Its drop is the local rollback.

`stage` consumes `self`. It charges `STAGE_COST` plus `COMMIT_COST` plus the staged body bytes, then, in the open transaction, checks the association's operationRef and the receipt/association run, runs `stage_recovery_pair`, `stage_run_material` (returned `blobDigests` must equal the published set), `stage_availability` with expected generation `None`, and `stage_pin_change` as a first publication from an empty expected set under the attempt's operationRef. A poisoned transaction is not returned as an adapter. Any error drops the transaction. A stored schema whose configuration name ends in `_schema` is `LEDGER.CORRUPT`. SQLite and I/O are host I/O. A retained-key collision and the join, availability, pin, and material refusals are `StagingMismatch`.

`PreparedLedgerCommit::commit` performs only `COMMIT`. Success is `Committed { execution }`. Any error is `Undetermined { execution }`, and `refusal()` is `CommitUndetermined` on `DURABILITY.COMMIT_FAILED`. There is no retry and no read-back. Dropping the adapter rolls back. `ObjectDeclaration` and `StagingMismatch` share the invariant row with a reused ExecutionId. The host projection of these rows stays X3d's, as X3c-1 already states.

## Judgment calls

1. Accepted. `JournalSealBinding`, `JournalWriteTxn`, and `AdmissionPermit` are not named. Staging takes the joined receipt, association, carrier digest, manifest, inventory, availability, and pins. `commit` is a plain consuming method. The storage order is the types: `AdmittedAttempt` before objects, `PublishedObjects` before level 3, staging before the adapter, and one `commit`. Journal-before-ledger and level 4 stay X3d's.
2. Accepted. `commit_run_material` had the reader and the DDL. `stage_run_material` uses that DDL equality check, `paired_run`, and `parse_material`, then inserts the same columns the reader loads. A failed insert leaves the transaction poisoned.
3. Accepted. `commit-inventory.blobDigests` is "a retained blob published by this commit; the CAS key is the digest itself". Staging requires that set to equal the published digests, including cardinality. The typed `objects` array stays inside the inventory body.
4. Accepted. Pins are a first publication from an empty expected inventory under the attempt's operationRef. Equal empty sets take the existing no-op arm (`pin_inventory_change_admitted` false) and write no pin fact.
5. Accepted. `expected_generation: None` is the initial record: `check_initial` when the ledger has no current row, and `availability_stale_generation` when one is already present. No extra state rule is added.
6. Accepted. A second hard link and a group- or other-writable mode cannot be confirmed and are not overwritten, so they join item 4's unequal, length, and non-regular cases on `LEDGER.CORRUPT`. An objects directory that is unreachable during confirmation is the custody name-changed row.
7. Accepted. Item 10 names the invariant row for a reused ExecutionId, a host pre-use rule. A bad declaration and staged values that do not join are the same kind of broken composition: `ObjectDeclaration` and `StagingMismatch`, including objects from another attempt. They are not a retry.
8. Accepted. One charge covers every object before the first write, so the caller's ledger cap bounds the commit's declared object bytes. `BEGIN` has `BEGIN_COST`. Staging reserves its fixed cost, the body bytes, and `COMMIT_COST`, so `commit()` takes no ledger inside the permit closure.
9. Accepted. The platform publication primitive has no fault injection. Each `cfg(test)` point writes the residue that step leaves through `RetainedDirectory::create_exclusive_regular` and stops: a partial staging file, a full staging file, the digest name holding the bytes, or a full staging file with the name absent. The `COMMIT` fault is a real failing `COMMIT` from the test hook. The crash test keeps earlier objects, the attempt row `admitted`, and nothing staged, and the next attempt completes.
10. Accepted. `publish_new_regular` and `confirm_existing_regular` run on the `ObjectDirectory` handle (`SuppliedDigestDirectory` over `directory.retained()`), and each receipt's directory barrier is that call's barrier. Each `PublishedObject` records the kind.
11. Accepted. `AdmittedAttempt` is not `Clone` and is returned only after the attempt `COMMIT`. Publication requires it.
12. Accepted. Storage's `test_scratch` is the F3 parent `<temp>/opensip-test/<pid>-<nanos>`, mode 0700. The X3c-1 fixture is `pub(super)` and rooted there. The support directory stayed absent.
13. Accepted. `stage` returns the adapter only when `poisoned` is false, and the adapter has no other production method. `WriteTransaction::commit` would refuse a poisoned transaction before `COMMIT`; `PreparedLedgerCommit::commit` would still report `Undetermined`.
14. Accepted as deferred. `project_ledger.rs` still says "No object publication, staging, commit, settlement or read-back." That remains true of the file's own functions; the child file has its own row. `recovery_material.rs` still truly "Read and join" the snapshot material, and the new insert is the understatement. Both are inherited by value. The v102 README records them for the same description-only successor as `carrier_floor.rs`. That is the 461b shape. `project_ledger_tests.rs`, `blob_store.rs`, and `lib.rs` descriptions stay true.
