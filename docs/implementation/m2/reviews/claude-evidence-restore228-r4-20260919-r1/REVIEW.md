## 3. The two areas root asked me to press
**Unknown-present scope.** The hazardous shape is: the transaction ran, so the COMPLETED receipt is visible and `completed_mutations[scope]` is set, but the barrier was uncertain. r4 checks `uncertain_scopes` **before** the completed lookup, so the visible receipt cannot serve a same-invocation delivery replay. My variants (`claude-out/probes/my_variants.py`): completed lookup moved before the uncertain check → rejected (`unconfirmed or failed scope is not replayable`); uncertainty recorded only when the footprint is absent → rejected (same label); uncertain reported as `failed` → rejected (`integration preserves non-durable outcome`); gate grants delivery when an uncertain receipt is visible → rejected (`uncertain footprint is not success`). After a restart the question cannot arise through replay — a new process has a new RequestId and therefore a new scope — and read-only inspection returns `unavailable` when durability/custody is not admitted; both are what MUTATION-PUBLICATION states.
**Final barrier.** Barrier moved after the unlock → rejected (`checkpoint lock spans admission and barriers`); publication moved after the unlock → rejected (`publication under checkpoint lock`).
