## 2. What inherited law fixes
1. **[E] S4 definitions.** "`lastAccepted` (L): issue time of the newest accepted signed document … **Admitted time evidence** A = max(L, accepted witness time, presented root issue time), where a witness is the newest issue time of a presented payload whose signature already verified and which is not older than L. The wall clock is untrusted."
2. **[E] S4 steps.** (1) "an issue time > W + 24 h refuses `PAYLOAD-NOT-ADMISSIBLE`; nothing is written"; (2) fresh install needs admitted time evidence, else `TRUST.NO_ADMITTED_TIME_CONTEXT`; (4) W > A + 90 d refuses before any write; (5) tEval = max(F, W, A), write-ahead, "L advances to A when A > L".
3. **[E] S5.** "the final root must be unexpired at tEval and not issued more than 24 h after the wall … Success advances the root counter to M and L to the final root's issue time"; per link "not issued before its predecessor" — so issue times are monotone along a verified chain and the **final** root's is their maximum.
4. **[E] Model.** The two values are TCB *assumptions*: "`payload.newestIssuedAt`, `presentedRootIssuedAt`, `epoch.issuedAt`: issue times read from documents whose signatures were already verified." It checks the future bound on each, rejects a witness `older-than-lastAccepted` **without refusing the import**, and never says which documents feed `newestIssuedAt`. Root is right: these scalars are not authority and no producer law exists.
5. **[E] Which signed trust documents carry `issuedAt`.** Exactly: root (v1/v2), catalog, revocation list, payload manifest (`payload.issuedAt`), and `TrustRecoveryEpochV1`. Of the eight envelope routes (`manifest`, `catalog`, `root`, `revocation`, `inventory`, `payload`, `trust-recovery-epoch`, `platform-profile-set`), the component `manifest`, `inventory` and `platform-profile-set` bodies and the permission policies have no `issuedAt` in the schemas I read. **Proposed** by 215 A: `RootRecoveryAuthorizationV1` with `issuedAt`/`notAfter`.
6. **[E] S4.5** is not an S4 witness: "(f) `issuedAt` ≥ L and |`issuedAt` − W| ≤ 24 h … On success: F := L := `issuedAt`"; "The accepted root's expiry is not consulted for this one document".

## 3. Actionable contradictions / gaps
- **T-A — "newest issue time of a presented payload" has two readings that produce different durable writes.** R1: `payload.issuedAt` (the manifest) only; R2: the maximum over every authenticated time-bearing document in the payload. Probe: L = 01-01, wall = 06-20, manifest/catalog issued 02-01, revocation list issued 06-01 → **R1 refuses `CLOCK-EXCURSION-FORWARD` and writes nothing; R2 proceeds and writes F, anchor and L = 06-01.** The same payload is importable or not depending on an unstated choice. R2 is the only reading consistent with L's own definition ("newest accepted signed **document**") and with S4 step 1's "an issue time".
- **T-B — 215 B extends the witness to the recovery payload "through the same S4 witness mechanism" but never says whether the authorization's `issuedAt` or the replacement root's `issuedAt` participate.** It matters most exactly where recovery is needed: an install long offline with an old L. Probe: recovery payload documents issued 03-01, authorization issued 06-19, wall 06-20 → **without** the authorization the staging evaluation writes nothing and refuses beyond-horizon; **with** it, it proceeds and L = 06-19. Separately, 215 A's COMMIT check "`issuedAt` ≤ tEval < `notAfter`": if the authorization is a witness source, `issuedAt ≤ L ≤ tEval` holds by construction and only `tEval < notAfter` is live — fine, but it should be stated, not discovered.
- **T-C — order of the future check and authentication.** S4 step 1 precedes everything; 215 C.3/B-6 require all relied-on authentication (including the second-pass revocation union) **before** the payload is time evidence. An issue time read from bytes that later fail authentication must not produce a `payload-future` result. Both outcomes write nothing, but the public reason differs and the rule "unauthenticated time is never an input" should be explicit.
- **T-D — BEGIN and COMMIT present no new documents, yet every dispatched role event needs a `clockObservation` (v14 audit) and 215 A applies "current admitted-time/future-time rules" at COMMIT.** Which payload input does their S4 evaluation receive? Unstated.
- **T-E — `presentedRootIssuedAt` for a recovery payload.** S5 defines it for a *chained* final root. The replacement root is not chained (the old root keys are what was lost); 215 authenticates it by authorization + own possession. Whether its `issuedAt` is a "presented root issue time" is not stated, nor is the S5-like semantic admission it still needs (issued not before the authority root; issued before its own expiry).

## 4. Proposed producer **[P]** — one function, reused unchanged by the existing verifier
`TimeInputs(op) = { newestIssuedAt, presentedRootIssuedAt }`, computed **only** from documents in the operation's complete relied-on authentication closure, **after** that closure authenticated under the retained∪incoming revocation view. Never stored as authority: the capsule's `T` references the closure; a re-admission recomputes both values from it under the ORIGINAL context.
| Operation | Newly presented, time-bearing | `newestIssuedAt` | `presentedRootIssuedAt` |
|---|---|---|---|
| **Ordinary import / refresh / embedded bootstrap** | manifest, catalog, revocation list; root chain | max of the three `issuedAt` (shared members authenticate in the prospective frame even when their role is a non-target; inert members carry no time) | `issuedAt` of the **final** chain root M (equals the chain maximum by S5's per-link rule); when the final root is the already-held head it adds nothing (≤ L) |
| **Recovery staging** (payload.2) | manifest, catalog, revocation list, **authorization**; replacement root | max of the **four** — the authorization is the freshest document signed by the highest remaining authority and is what lets a long-offline install pass the 90 d horizon | replacement root's `issuedAt`, admitted only after authorization + possession + second pass, and only with: not issued before the authority root, issued before its own `expiresAt` |
| **BEGIN** (no payload) / **COMMIT** | none new | the **same** `TimeInputs` recomputed from the retained staged closure | same |
| **S4.5 recovery-import** | `TrustRecoveryEpochV1` | not an S4 witness; S4.5 (f) and "F := L := issuedAt" apply unchanged | — |
Rules that make this exact:
1. *Authenticate, then read time.* Closure authentication (signatures, role/namespace, second-pass union, shape) precedes any use of an `issuedAt`; failure there is a pre-dispatch no-write refusal and never `payload-future`.
2. *Future bound per document.* S4 step 1 applies to every member of the set and to the presented root; the diagnostic names the document. Refusal writes nothing (inherited).
3. *Older-than-L is not a refusal.* A `newestIssuedAt` below L is a rejected witness, the evaluation continues with A = max(L, presented root time) (inherited model behaviour) — for recovery staging too.
4. *Retained closure at BEGIN/COMMIT.* Staging succeeded only if its S4 evaluation did, so L ≥ every retained time thereafter (S4.5 cannot lower L: "(f) `issuedAt` ≥ L"). Passing the recomputed inputs again therefore never moves L or `T` ("keep the prior timeEvidence when L does not change"), may advance F/anchor, and re-applies the future bound against the **current** wall — if the wall was set back so that a retained document now looks future-issued, COMMIT refuses pre-dispatch with no write until the wall is corrected. One producer, no COMMIT special case.
5. *Old-root expiry exception is narrow.* The authority root's `expiresAt` is not an input to admitting the authorization's or the epoch's time (215 A; S4.5). It is the only exception: the replacement root must be unexpired at COMMIT's tEval, the authorization window `tEval < notAfter` is evaluated then, and catalog/list freshness are COMMIT guards — none of them is evaluated as a TRUSTED-entry guard at staging.
6. *Phases.* **P0:** no L; "not older than L" is vacuous; S4 step 2 needs A from these inputs, else `TRUST.NO_ADMITTED_TIME_CONTEXT`; on success F := tEval, L := A, `T` := this closure ⇒ P1, even if the import then refuses. **P1:** as P2 for time; accepted-document times stay null/unknown. **P2:** unchanged. S4.5 only in P2.
7. *Proof closure (root's decision kept).* `T` = the **complete** relied-on authentication closure of the operation that advanced L — for recovery the staged closure including the authorization body/envelope and the authority context (held head admission chain or embedded core anchor) — with no attestation shortcut and no minimal subset. The time-relevant dependency edges inside it are: manifest → TR-BUNDLE keys of the final/replacement root; catalog → TR-INDEX keys of that root; revocation list → root threshold of the root version it names; authorization → `recoveryAuthority` keys of the authority root; replacement root → its own root keys **and** the authorization's `replacementRoot` binding; every one filtered by retained∪incoming revocations. A root that appears only here is authenticated-not-accepted.
