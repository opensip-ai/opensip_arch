### Judgment calls

1. **The pure core is the evaluator.** Accepted. D1-plan G28 line 318 sets `.evaluator` to `pure core`, `.result` to `policyOutcome inside CoreCompletion`, and forbids the host from minting a fail/warn verdict. That is the policy-evaluation locus. The build plan's component join (line 703) gives each selected provider artifact a `closure2` identity and a TR-INDEX-signed component manifest, and it does not list an evaluator component. EC1's definition, the core descriptor with `kind` set to `evaluator`, is the lawful reading of that locus. The identity consequence is call 5, flagged to the owner.

2. **`manifestDigest` for kind evaluator is the TR-CORE inventory body.** Accepted. `bind` already stores that digest on the core descriptor (lines 384–387). Kind evaluator keeps the member. An admitted component manifest is a different object (`kind: "component"`, `role: "analyzer"`, as the law and the build plan state). Inventing an evaluator component manifest would describe a release that does not exist.

3. **Text-only overrides, and X3d-3 must leave the product schema source unchanged.** Accepted. `schemas/sources/identity-v3.schema.json` line 287 still says the artifact is "the admitted component manifest body bytes under the security metadata profile, excluding the signature envelope". The same sentence is inside the generated `selectedSchemaBytes` string in `apps/report/src/generated/report.ts` (line 6847). No Rust source contains that sentence. stage-meta-reference-selection-v1 (README line 11) keeps current schema bytes, hash recipes, and generated artifacts unchanged, and makes explicit passage overrides the semantic owner. X3d-3 item 13 already requires both product copies to keep their bytes, along with `crates/identity/src/closure.rs` and `crates/evaluator/src/view-joins-registry.json`. Updating the schema source would change those bytes and the generated report, which this unit excludes. The passage overrides own the new meaning.

4. **Retention.** Accepted as a disclosed application of the existing rule. Default `preimage` retention, through the identity walk's raw-artifact rule, means a Run that names the core evaluator closure retains the inventory body and every core tree file of that platform. The store keys them by raw SHA-256, once per store per release. EC1 states this and does not change the retention rule.

5. **Identity.** Accepted as disclosed and flagged. Every core release is a new evaluator closure, so a Plan that selects it gets new PlanIds, RunIds, and cache keys. The header says the owner may override the decision. That flag stands.

6. **Rejected alternatives.** Accepted as stated in the README and in the X3d r8 header. (a) A session field with no definition has nothing to expose, because no authenticated record names an evaluator closure. (b) A tree-membership test is unstated, leaves `manifestDigest`, version, and platform unbound, and would be a weaker identity law. A signed inventory member changes the release format and 463h's builder and still needs this rule. A TR-COMPONENT evaluator contradicts G28 and the analyzer-only component role. Admitting kind `core` in replay breaks `closureKinds`. Dropping the check removes the build plan's producer-selection comparison (line 67).
