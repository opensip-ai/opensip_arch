## What the unit does

EC1's value is computed where the core closure is computed. `bind` still builds the `kind: "core"` descriptor, with `manifestDigest` the raw SHA-256 of the inventory body. `closure_id` is that same `closure2:` plus H("closure", D). `evaluator_descriptor` clones the descriptor and sets `kind` to `"evaluator"`. `Projection::evaluator_closure()` sits beside `closure()`. `InitialCore::evaluator_closure()` reads `release.authentication().core().inventory()`, the same object `closure()` reads, so the running arm and the injected arm share it. `PlatformReceipt::core_evaluator_closure()` and `ProjectOperation::core_evaluator_closure()` are read-only `&str` values beside `selected_core()`, which is unchanged. `CommitSession::core_evaluator_closure()` reads through the operation. `open` holds it by holding that operation. `core_closure()` still returns the receipt's selected core closure. Its doc comment now says a Run never names that id. Its value and its other uses are unchanged.

`Bound` keeps `evaluator_closure`, filled from `CommitSession::core_evaluator_closure()`. `Bound.core_closure` is gone. `plan` compares `run.evaluator_closure()` with the new field after the project check. `PlanRefusal::Closure`, `plan`, and `prepare_commit` name the core evaluator closure. A mismatch is still the invariant row.

The shared accessor is one `#[doc(hidden)]` function, `CommitSession::core_evaluator_closure_preimages`, gated `cfg(any(test, feature = "crash-matrix", feature = "scenario-fixtures"))`. The fields on the way are private, so it takes two crate-private hops, `ProjectOperation` then the write receipt, each under the same predicate. The read is `InitialCore::evaluator_closure_preimages` inside `initial_core.rs`'s existing joint-predicate `tests` module (`#[cfg(any(test, feature = "crash-matrix", feature = "scenario-fixtures"))]`, included from `initial_core_tests.rs`), so that module adds no site. It opens each tree member through `open_release_file` (no-follow, exact name, core-tree predicate) on a fresh `WorkLedger::new()`, which is the platform ledger at its global caps and is not the session's attempt ledger. A member that cannot be read, or whose SHA-256 or length disagrees with the inventory, panics. It returns the descriptor, the inventory body, and the tree bytes by logical path. `crash_matrix_sites.rs` names this shared gate 5 and pins one joint-predicate row in each of `commit_session.rs`, `operation_handoff.rs`, and `read_premise.rs`. ## The tests the law requires

`bound(execution, operation)` takes `project` and `evaluator_closure` from `session_values()`. That opens one real `CommitSession` per process over `ScenarioHome::operation`, records the two values and `core_closure()`, builds the candidate, ends the session (`reserve_end_path`, `refused`, `finish`), and drops the home. It never reads a Run. `replay()` is `replay_run` of that candidate. Recover and sweep call the same `bound` without a Run argument.

- `a_run_of_another_project_or_closure_does_not_bind`: the candidate's Run names the session's project and closure and `plan` succeeds. Another project is `Project`. Another closure is `Closure`.
- `a_corpus_run_does_not_bind_to_a_real_session`: the raw corpus Run is `Project`. The corpus with only its project rebound keeps the corpus evaluator closure and is `PlanRefusal::Closure`. The same Run, rebound to a fresh session's `project_id()`, is `NotPrepared::Refused(Invariant)`. The project directory is absent. `finish` appends the `REV` (`seal` 0, `rev` 1).
- `the_core_closure_is_not_the_evaluator_closure`: the two session ids differ. The retained closure is `kind: "evaluator"`, and the same descriptor with `kind: "core"` hashes to `core_closure()`. A Run renamed to that core closure is `replay_run`'s `Structure(Graph(Input(Candidate(Schema(Mismatch)))))`. The control, the same rename with `semanticVersion` set to `0.0.1-x3d3` and kind left `evaluator`, replays to a different closure id.
- `the_first_real_commit_composes_prepare_commit_and_publish`: a fresh scenario home and `CommitSession::open`, the candidate for that session, `replay_run` after `open`, then `prepare_commit` and `publish`. The closure's manifest and tree digests are among the retained blobs. The outcome is `Committed`, sequence 1, the session's RunId and ExecutionId, no latch after admission. `finish` appends neither `REV` nor `CLN`, has no settlement failure, and enters the end step. The carrier census is one `SEAL`, zero `REV`, zero `CLN`. The ledger holds the published receipt bytes, parsing to (RunId, ExecutionId, N), and an `admitted` attempt. `objects/sha256` equals the retained frame and blob digests.
- `ec1_vector_core_evaluator_closure` pins the fixture case `baseline-macos`: 5990-byte body, both closure ids, both descriptors' canonical SHA-256, and `manifestDigest` `1d012c7d…ac5d` equal to the body's SHA-256. Those constants match `evidence/vector.json`.
- `every_accepted_case_has_a_distinct_core_evaluator_closure` accepts 53 `core-inventory318` cases. The descriptors are equal except `kind`, the evaluator id is the closure recipe, and the two ids differ.

Nothing here is X8c's suite or X9-2's matrix rows. The candidate is the piece X9 r7 moved into this unit.

## Judgment calls

1. **The accessor's reach.** Accepted. Two gated hops, and the read stays in gate 1's `tests` module. An ungated `&InitialCore` through the receipt would expose more than the read-only values item 13 names.
2. **Shape and ledger.** Accepted. The return is a tuple. The read uses a fresh `WorkLedger::new()` at the platform caps, so it does not spend the attempt ledger. A bad member panics, as the other fixtures do.
3. **`Bound.core_closure` removed.** Accepted. Step 1 was its only use. `CommitSession::core_closure()` keeps the store pair, X4's closure subjects, and live revocation.
4. **Where the candidate compiles.** Accepted. One source file, the existing support-module gate, and a `#[path]` include for the plain test build. `duplicate_mod` is allowed only on that include. The helpers are `cfg(test)` because the feature's copy never calls them. Widening the support module to `test`, or copying the source, would add a site or a second text.
5. **The candidate's input.** Accepted. It takes `&CommitSession` and calls only the getters and the accessor. X9 r5's "accepts no session" rule is about the three driver entries, which this unit does not add.
6. **The rewrite.** Accepted. The law requires recomputation and gives no algorithm. Outputs are found by deriving over the corpus, then re-derived. The textual rewrite stays on the inputs. The corpus closure and its manifest blob are dropped. The `#[cfg(test)]` rename helper does rewrite a whole candidate, including outputs, and the law's required kind-`core` refusal uses that helper. It is not the candidate `synthetic_run_candidate` returns.
7. **Test order.** Accepted. The end-to-end test replays after `open`, which is when the first registration's ProjectId exists. Replay takes no custody. The host's order stays X9-5's.
8. **The mismatch Run.** Accepted. `plan` checks the project first, so the corpus is rebound to the session's project and keeps the corpus closure. The raw corpus is asserted `Project`. The session side is the real session's project, which is what r8 requires.
9. **Once per process.** Accepted. One real session supplies the binding values and the candidate, then ends. The end-to-end test opens its own session.
10. **Vector constants.** Accepted. The body comes from the existing fixture. Copying `vector.json` into the product would add a fixture row for the same values. The constants match the vector.
11. **The core-closure refusal.** Accepted. The pinned error is the identity schema mismatch, and the evaluator-kind control replays.
12. **Exports.** Accepted. The four names are public on storage's support surface. Host's glob forward is unchanged. The replay bounds are `synthetic_replay_limits()`.
