# Reconciliation — the maintenance publication checkpoint (four contradictions, source-checked)

Reviewer: Claude. Date 2026-09-19. **Read-only on candidates/product/architecture; written only here; earlier reports unchanged; no commit/push; no implementation approval.** Source hashes: `claude-out/io/source-hashes.txt` (all from my verified reference-201 extraction, plus the historical `security-completion.v8.md` from my verified 211 owner-inputs). **[E]** inherited, quoted · **[P]** proposed · **[?]** unresolved.

## 0. Two corrections to my checkpoint note that change the shape of the answer
**(a) `AttemptCustodyV1` does not cover this path.** **[E]** identity §2 (l.83–101): "**Separately, and only for durable-authoritative commit-capable attempts**, the evidence ledger additionally carries a private `AttemptCustodyV1` row … `{phase: admitted | settled, settledOutcome: null | committed | refused, operationRef}` … **Its scope is exactly the attempts that can publish an authoritative commit receipt through the guarded commit facade.**" A guarded maintenance publication never reaches that facade, so it has no such row; my "recovered through the inherited `AttemptCustodyV1` mapping" was wrong. Its closed `settledOutcome` (`committed | refused`) could not truthfully describe imported evidence either.
**(b) GRANT / RA / ICI / ICO are the vocabulary of *component-requested brokered effects*, and no permission token is missing.** **[E]** `permission-truth-tables.v9.json` mints exactly eight tokens; `PT-HOST-EFFECT-BROKERED` is "the permission side of" the control-plane function "broker separately authorized host effects", and the file lists as **deliberate non-tokens** "clock, entropy, host output, host-initiated writes to a user-named output path", with "anything not enumerated is denied by absence". **[E]** v8 §7.5 HE-1 is an SDK→host request ("The SDK writes … and sends the request. The host then … (2) appends **RA** … (3) appends the intent record …"). **[E]** the host's *own* durable act — the Run commit — is journaled as `SEAL`, not as RA/ICI/ICO, and "Durable commitment is established solely by the guarded evidence-ledger receipt and its private association" (S6). So my item "the permission truth table needs an explicit effect value" was mis-aimed: a host-initiated ledger publication is not a component permission, and I withdraw it. **Found, not merely not-found:** the table's closure rule excludes it by construction. The same observation makes RA/ICI/ICO a semantic stretch for a host-internal publication: a host-synthesized `requestRef` would be "accepted" against no component request.

## 1. Two lawful shapes; I now recommend the smaller one
### Shape α **[P, recommended]** — no journal record of its own; the checkpoint is the lock, the REV test and the gate; the ledger is the only durable evidence
Under the level-4 append lock L, in this order: (1) custody/writer-guard, store binding, grant generation current, cancellation; (2) **no `REV` exists in this operation's journal** and the re-read trust epoch passes S6's predicate for every closure the replay relied on; observer freshness; (3) **gate `0 → 1`** — the last act before the effect; a latch already set (`2`) fails the gate and nothing is published; (4) publish **one** ledger transaction (imported-evidence record set + retention roots + private association) and satisfy its barriers; (5) release L.
- *Why this is enough for linearization:* **[E]** "after `REV` no `RA`, intent, commit or `SEAL` is appended, and no brokered effect commits" is enforced by whoever holds L checking for REV; it needs no record of ours. A `REV` can only be **appended** when L is free, i.e. before step 1 (then step 2 refuses) or after step 5 (then the publication was already admitted and durable — S6: state `3` "does **not** revoke the already admitted attempt or relabel its outcome"). The **latch** is a lock-free bit and may flip at any instant; only its value at the gate matters.
- *Crash:* one SQLite transaction in one carrier is atomic. Rows present ⇒ published; absent ⇒ not. There is no cross-carrier prefix to repair, no intent-without-outcome state, no ICO to append later, and therefore **contradiction 1 cannot arise**. An uncertain barrier is `durability-undetermined` with the ExecutionId and no retry (inherited).
- *Observability without an ICO-derived id:* completion is read from the ledger's private association by ExecutionId — the same principle S6 states for commits. The maintenance receipt id needs no journal position; it can be the association's own identity (see §3).
- *Cost, stated:* the journal shows nothing about a maintenance publication; an attempt that dies before step 4 leaves only orphan blobs. That is the same evidence level the commit path has for an attempt that never commits, minus `AttemptCustodyV1` — see **[?]-1**.

### Shape β — RA → ICI → effect → ICO, if root wants journal-visible intent despite §0(b)
Reconciled ordering for contradictions 1 and 2:
- Hold L continuously for: final checks (as α 1–2) → append **RA** and **ICI** and make them durable → **gate `0 → 1`** → ledger transaction + barriers → append **ICO COMPLETED** durable → release. Gate **after** the durable intent, so "no effect without durable RA+ICI" holds, and a latch that lands during the appends is caught: gate fails ⇒ no effect; we release L having appended only a lawful prefix `RA, ICI`.
- *Latch vs REV:* the latch is the observer's atomic fetch-OR; the durable `REV` is appended by the observer **under L**, so it can never interleave with our appends while we hold L. "No append after actual REV" then reduces to: every later actor (including crash recovery) must look for `REV` under L before appending anything.
- *Closure table* — **[E]** `security_unit_lib_v8.he1_recover` (still shipped in the candidate, `3e28bc7b…`), lawful prefixes `[RA] [RA,intent] [RA,intent,outcome] [RA,REV] [RA,intent,REV] [RA,intent,outcome,REV]`; IRREVERSIBLE intent without outcome: footprint present ⇒ `ICO COMPLETED` **if not revoked**, `CLN completed-irreversible` **if revoked**; absent ⇒ `ICO FAILED` / `CLN not-begun`; unknown ⇒ `ICO INDETERMINATE` / `CLN indeterminate`. So my table's "recovery appends ICO COMPLETED" is lawful **only when no REV has been appended**; once a REV exists, **`CLN <requestRef>:completed-irreversible` is the only lawful closure** — "never through a post-REV RCO/ICO".
- *Closed schema 3:* **[E]** `JournalRecord.outcome` is `const "COMPLETED"`. `ICO FAILED` and `ICO INDETERMINATE` cannot be written. Without adding outcomes, every non-completed ending must go **REV-first** (`REV process-death`, as he1 already does for "RA without intent") and then close by CLN residual `not-begun` / `indeterminate`. That makes every gate failure and every failed publication consume the operation's grant generation ("It closes the dead operation's grant generation") — a real availability cost of β.
- *Receipt identity:* he1's `rid` "derives from the outcome record's position"; on the CLN path there is **no ICO position**. Under β the stable identity must therefore be the **ICI** position `(grantGeneration, iciSeq)`, which is durable before the effect and exists in every case where an effect could exist. That is a new derivation, not the inherited `receipt_id` — **[?]-2**.
- *Standing of the owner:* the only text I found that owns intent-without-outcome recovery is the historical v8 §7.5 and its unit library; the current `security-and-lifecycle.md` does not restate it, and the current reference `linearize` models `COMMIT` as effect + ICO in one atomic step, so that state does not exist there. Whether he1's law is the *current* owner for a new effect kind is **[?]-3**.

**Why α:** it needs no new journal semantics, no schema member, no grant, no cross-carrier recovery and no derived receipt position; it mirrors how the host's other self-initiated durable act is evidenced. β buys journal-visible intent at the cost of stretching RA's meaning, a REV-first failure path and two open derivations.

## 2. Contradiction 2 — exact lock / gate ordering (both shapes)
1. L is an in-process mutex (S7 level 4, "bounded, in-process") acquired **after** both level-3 transactions are prepared non-waiting (journal first, ledger second) — build-plan step 4; no lease upgrade, no fence, no `I/trust` write from here on.
2. Checks, then (β only) durable RA+ICI, then the gate as the **last** step before the effect, then the effect, then (β only) ICO, then release. Nothing slow under L: the ledger transaction contains rows only; all bytes were staged earlier as unreferenced blobs.
3. Latch `0→2` before the gate ⇒ no effect. Latch `1→3` after it ⇒ the admitted effect completes and its outcome stands; nothing further is admitted; no retry. Uncertain barrier ⇒ stop, report `durability-undetermined`, append nothing more, never retry.

## 3. Contradiction 3 — the postimage self-reference
**[P] fixed direction, bytes still owed:** `body` = canonical bytes of the imported-evidence record set + retention-root rows **only**; `postimage = SHA-256(body)`; the private association = `{executionId, requestRef, postimage, …}` (β adds `grantGeneration, iciSeq`, both known before the ledger transaction; never an ICO sequence, which does not yet exist). The association is **not** part of `body`; nothing in `body` names the association. Dependency: `body → postimage → association` (and, under β, `→ ICO.postimageSha256`). **[?]-4:** the exact canonical projection of a *set* of records and roots (ordering, row identity, whether per-Run or one digest per bundle) is not designed here; I am fixing only that it is acyclic.

## 5. Unresolved, concretely
- **[?]-1** Attempt correlation for maintenance: a commit-capable attempt gets an `admitted` row at admission so a pending `REV` can be correlated even if it never commits. Under α/β a maintenance attempt that dies before publication leaves no ledger trace. Either accept that (it produced no effect), or add a sibling private row with its **own** closed outcomes — extending `AttemptCustodyV1`'s scope or its `committed|refused` enum would be untruthful.
- **[?]-2** (β only) a receipt id derived from the ICI position is new law.
- **[?]-3** (β only) whether v8 §7.5 / `he1_recover` is the current owner for a new IRREVERSIBLE effect kind.
- **[?]-4** exact `body` projection for the postimage.
- **[?]-5** one S6 sentence is still needed in either shape: the gate's single-use permit is today "for the already prepared **commit**"; it must be stated to admit one prepared imported-evidence publication, typed and non-interchangeable.
- **[?]-6** under α, whether root requires *any* journal trace of maintenance publications for audit; if yes, that is a new record kind (schema successor), not a reuse of RA/ICI/ICO.
