## RF-1

The amendment says each closure member is admitted by `native_current::capture_p2`, `current_record_bindings::bind`, and `trust_ordinary_roots::bind_retained_head`, and that a role counts only when bound to the event its `accepted.by` names, "as `check_capsule_projection` and the event binder already require." Those functions admit a smaller set.

`capture_p2` loads `state.v1` and the publication descriptor from `Collection::Publications`, then calls `bind`. `bind` requires `clock.phase == "retained"` and admits the inline `clock.record` through `admitted_trust_records::admit`. It binds the descriptor operation and loads the descriptor's events through `current_event_trace::bind_trace`. `clock.record` is the inline object (`node_347`). `bind` does not load a clock-record file, `history`, or `timeEvidence`. `timeEvidence` on a retained clock is a `{bytes, sha256}` reference. `capsule_clock` clones that reference and is not on this path.

`bind_retained_head` requires `Phase::Retained` and loads `heads.root`'s document body and envelope from `Collection::Objects`. It keeps `heads.root.admission` as the reference stored on the capsule. It does not open `heads.catalog` or `heads.revocation`. `admitted_revocations::verify_revocation` verifies bytes and an envelope it is given; it does not open `heads.revocation`. Catalog and revocation heads, and every head admission, are `{bytes, sha256}` references (`node_4`). `history` is the same kind of reference or null (`node_51`). The history loader in `trust_input_bindings` (`Input::History` from `Collection::Records`) belongs to the restriction-observation walker. It is not called from `capture_p2`.

`check_capsule_projection` checks the capsule already in memory: retained heads and history are non-null, the three head counters match, trusted and revoked roles have `accepted` non-null, and `eventHead` equals the last listed event. It does not read `accepted.by`. `bind_trace` is the event loader inside `capture_p2`. `publication_events::bind_events` is a separate replay, and `capture_p2` does not call it. On a standing reset both write `reset.by`. Neither compares `accepted.by` to an event. Item 2 step 4, item 12, and item 13 still require that join and still say the existing binders are the only parsers. An X4T-a that only calls the named functions would leave catalog, revocation, history, time evidence, and the admission records unread, and would treat a role as bound to `accepted.by` without that check.

Required: name the existing function that opens each of `heads.catalog` (body, envelope, admission), `heads.revocation` (body, envelope, admission), the root admission record, `history`, and `timeEvidence`, or state that no existing binder opens them and that X4T-a opens them by the same retained-object load as `bind_retained_head` (objects for signed bodies and envelopes; the collection the reference names for history, time evidence, and admission records). `verify_revocation` then verifies the revocation bytes that load supplied. Item 2 steps 3 and 4 name those same loaders. `clock.record` stays the inline object `admit` shapes. Item 11 may keep the 47-file ceiling; that inline object is not an additional open. The `accepted.by` sentence states only a check a named function performs. The checks those functions perform are: `accepted` non-null for `ST-TRUSTED` and `ST-REVOKED`, head-counter identity, and `eventHead` equal to the last listed event, with events loaded by `current_event_trace::bind_trace`. If the view must join a role to the event `accepted.by` names, item 1 names that join as a check X4T-a performs. Item 12 and item 13 use the same rule. The round-trip may keep `publication_events::bind_events` as an additional acceptor; the loader inside `capture_p2` remains `bind_trace`. The r4 note's point 2 follows the corrected item 2 loaders. The read order otherwise, the 32-event list bound, the 40 MiB total, `TRUST_VIEW_COST`, the ChainBudget row, and the F-absent pre-acceptance row stay.
