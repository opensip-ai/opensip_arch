# Ordinary excluded-component integration

This records the implementation boundary clarified by the actual Grok reviews of [290](reviews/grok-native-availability290-20260920-r1/INERT-ROUTING.md) and [291](reviews/grok-native-contextplan291-20260920-r1/INERT-IDENTITY.md). Those reviews are planning evidence; they do not approve later candidate bytes or installed behavior.

The ordinary import first verifies shared BUNDLE, catalog and list evidence, derives the finite key-revocation union, and uses qualified role contexts to determine which roles remain targets. ROOT chain admission is also shared and mandatory. An excluded component cannot bypass document validity or inventory identity. The omission applies to its delegated key/namespace/signature threshold authority; it does not make the document usable.

Every component keeps the immutable envelope kind/domain/literal-role route, well-formed nonempty signatures, raw stored digest, canonical preimage and inventory capture bindings. Its body keeps the closed manifest schema and intrinsic command, path/tree, capability, permission, dependency, compatibility interval, configuration and prerequisite/declaration rules. It must match its authenticated catalog release by four-part identity, body/preimage/envelope digests and hostCore constraint. Envelope namespace must equal body publisher even when no key is delegated for that publisher. Catalog reserved command names remain an inventory constraint.

Current host classifications, approved exception references and live-name registry checks have a separate host-admission owner. Their absence cannot veto an inert excluded component during shared import. Native code must represent inventory validity separately from full host validation, without manufacturing host approval or weakening the existing full validator. Installation or execution still requires the appropriate full current admission.

292 implements only the distinct shared-signature phase and explicitly lists pending component bodies/authority and unresolved ROOTs. The frozen293 candidate adds inventory body validation and catalog joins while retaining separate result types. It does not choose targets or authenticate component authority. A subsequent composition must derive targets from shared evidence and qualified current/BEGIN contexts, then require component authority for relied-on roles. Supplied context arithmetic remains conditional until its history/population/BEGIN provenance is established. Time, minimum versions, role effects and durable publication remain separately open.
