# Private full-document package parser profile

This source is frozen for independent source review and remains unaccepted. It composes pure identity parsing with evaluator-owned package classification and retained snapshot hash/length diagnostics. It does not admit a complete enumeration, mint an evaluation subject, establish Run/replay authority, or prove retained-byte custody.

Identity owns a borrowed opaque TomlDocument and read-only table/string views. The host supplies bytes; evaluator still has only identity as an internal dependency. Parser containers may borrow input literals; callers must retain input bytes and the document while observing fields. No upstream TOML type or deserialization constructor becomes the public identity API. Numeric literals remain literals, so valid large integers and floats elsewhere in a manifest do not narrow through JSON, i64 or f64.

The proposed exact parse-only graph is toml0.9.9+spec-1.0.0(parse), toml_parser1.0.5+spec-1.0.0(alloc), toml_datetime0.7.4+spec-1.0.0(alloc), serde_spanned1.0.4(alloc), winnow0.7.13(no features), all default features disabled. Exact direct transitive pins prevent semver-compatible TOML1.1 drift. Existing sha2/tinyvec/unicode sources remain unchanged. The identity source/dependency policy binds all8dependencies, full archive hashes, extracted source census and exact features. Serde, std, display, preserve_order, unbounded and unsafe/simd parser features are not selected.

Full DeTable::parse must succeed before any package fields are read. A leading BOM is refused to match tomllib. An iterative whole-tree walk rejects calendar year0, seconds above59, and empty lazy integer literals (incomplete0x/0o/0b), including unused nested fields. Month/day/calendar validity, duplicates, strings and TOML1.0 grammar remain the full parser's job. Recoverable parsing is not used. Existing package.json parsing remains exact JSON-profile parsing; whitespace and unsorted object keys are accepted, while profile violations become syntax failures.

The separately accepted reference39 process profile is pinned CPython3.12.13 -I -B -X int_max_str_digits=0, with both startup and effective settings checked at import and package-projection entry. Wrong profile is ReferenceEnvironmentError, never syntax or an enumeration refusal. This avoids ambient decimal conversion limits without per-call global mutation. Rust adds no decimal digit limit. Arbitrary literal retention is this oracle/profile choice, not a TOML1.0 mandate. Reference39 selection does not accept this implementation.

Local development resource bounds: preparse byte maximum4MiB, upstream array/inline nesting and key-path guards80, postparse walk maximum1million values. Byte/depth/node exhaustion returns typed local resource errors; evaluator aborts projection, never emits a partial package result or invents a parseFailed syntax reason. Projection row/prefix visits and package visits each use a copied caller steps bound; these are not aggregate CPU or Plan work units. Full-tree parser allocation precedes node accounting. The profile does not claim a measured aggregate memory/time bound or release qualification.

The selected development host must parse and drop on a stack of at least2MiB. The no_std parser cannot provision or inspect that stack. A host test covers depth80, depth81 refusal, mixed80table+80array and a4MiB unclosed-array document on an explicitly provisioned2MiB worker in this macOS/Rust1.95development environment. Grok's independent probes show real stack overflow on much smaller workers. Cross-platform/compiler/LTO/panic-profile stack qualification and future host scheduler enforcement remain integration duties.

Winnow contains compiled unsafe implementations and ASCII conversion helpers. Actual Grok source review found no executed unsafe block on the selected DeTable path with toml_parser unsafe/simd disabled, but that is not a memory-safety proof. The dependency remains explicitly in the trusted source boundary. Cargo --cap-lints means -F unsafe_code on a build is not a proof of absence of transitive unsafe. Prior unicode-normalization unsafe accounting remains applicable separately.

Cargo metadata includes weak-feature optional serde_core edges from the two alloc-only helper crates that the compiled Cargo tree excludes. The proposed checker permits only policy-selected inactive optional edges on exact source-pinned packages. It checks each declaration is one optional, unconditional normal dependency and expands enabled features: dep: and strong dependency/feature references activate dependencies; weak dependency?/feature does not. Unknown or active exceptions refuse. The normalized name must also match exactly one unconditional normal resolve edge; absent, duplicate, renamed, build or conditional edges refuse. Five controls include real workspace feature unification and source-census refusal. Actual Grok reviewed the initial mechanism, and root addressed both guard/test findings before this freeze; it is not blanket optional-dependency omission or policy authentication.
