# Conditional ordinary-import completeness proposals 288

Private, unselected successor to287; product fa72e50 unchanged. This adds the post-authentication/post-time conditional completeness calculation to the existing private six-role planner. It does not authenticate its shared/entry guard observations, write a clock/head/role record, issue a grant, or publish an event. Its private Proposal contains a calculated completeness bit, proposed roles and proposed event trace; none is an admission capability. No authenticated flag is accepted by the native API.

The calculation calls287 internally on the same role/observation arrays. Completeness requires the shared guards AND every remaining T1 entry guard; excluded-role entry guards do not veto it. Even an empty T1 does not waive shared guards. On incompleteness, every original T0 role gets a refused PRESENT proposal, including healthy siblings and roles tentatively removed from T1. All tentative observations are discarded and all original role fields retained exactly. On completeness, provisional OLD-subject revocations and quorum observations precede accepted PRESENT proposals for T1 only. Successful entries become TRUSTED/established and close their conditional recovery restriction projection. REVOKED/RECOVERY peers cannot gain an ordinary entry merely through this calculation.

Clock write-ahead and actual audit/publication remain separate owners. In particular, this function does not report clock_written or metadata_advanced and cannot erase a prior S4 revision. Guard facts, current shared-signature admission, exact role records and event references must be supplied/bound by the eventual qualified orchestration. This is conditional arithmetic, not that producer.
