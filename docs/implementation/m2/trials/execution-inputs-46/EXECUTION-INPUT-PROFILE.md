# Retained execution-input diagnostic

The public inspect_execution_input_join entry takes immutable RetainedInputs, Plan/execution/evaluator locators, shaped evaluation refs and explicit local budgets. It requires exactly one capture reference and exact canonical-set equality with selectedRefs plus that capture. Expected evaluator closure must equal the capture and be selected by the Plan. All maps and logical promises derive inside the boundary. No caller ADMIT, store census, optional views/coverages maps or callback can replace an owner.

The reader runs parameter/emission, enumeration, Plan view/import/stage prerequisites and rehashes named objects/blobs. It reads facts only through named views. Promise derivation makes one pass over the initial object set and one over the initial blob set; it does not recursively expand newly promised objects. Extra ambient objects/blobs do not affect the result. Capture is a host TCB observation, not proof that a malicious host returned every result.

Owner/missing/schema/local-limit errors return typed Err before a join result. Once those prerequisites hold, Ok contains the exact X diagnostic document, which may be ADMIT or REFUSE. Late semantic REFUSE retains derivedAccounts, derivedOutcomes and requiredCellDeficiencies but has digest null. input_digest names the retained capture even when the join refuses; it is not an admitted-result identity. Early X shape refusal is empty, although the public reader normally rejects malformed captures earlier with a schema Err. Rust's typed maps cannot express X's non-map STORE_REQUIRED inputs; no tested coverage of that raw Python branch is claimed. Optional caller view/coverage equality maps are intentionally absent.

This bounded unit does not complete first-evaluation structural closure, atom truth, evaluator reconstruction, Run replay, storage custody or provider execution. The reader never requires Run/seal/proof/finding/semantic-evidence/evaluation-subject/predicate-output objects. Complete structural admission of first-evaluation inputs remains a fixed composition obligation; existing full Run traversal is not its substitute.

Resource controls are separate local counters: reader visits, kernel visits and each nested owner/schema budget. They are not an aggregate Plan CPU/memory budget or M6 qualification. The inherited parser stack and dependency TCB profile remains in force.

Tests: 2125 pure helper comparisons,84 promise controls,10 full kernel packet comparisons,1028 mutations,81 captured selected checker calls (2 typed-container/optional-map exclusions),51 permanent host cases. Host51 =18 no-output owner-admitted original packets +4 rehashed semantic refusals +29 local controls (including27 typed errors and2 ambient/set-selection positives). Candidate, target/incoming and incomplete coverage cases are included. Reference checker fixtures use the reference's own builders; they are self-consistency evidence, not independent host reconstruction. Initial probe compile/size failures and the corrected stage-spec fallback discrepancy are preserved.

Portable reproduction: pinned CPython3.12.13 -I -B -X int_max_str_digits=0 check-execution.py --cargo /absolute/cargo --output /fresh/directory. It verifies explicit product/reference pins, derives registry tables from selected law, reruns all stored reference comparisons and all workspace tests with test-only adapters injected into a disposable copy. The production API never exports those adapters. Source review and formal runtime selection are required before installation.
