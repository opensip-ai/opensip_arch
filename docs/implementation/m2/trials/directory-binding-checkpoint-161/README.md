# Retained absolute directory names — candidate161

Private, uninstalled, unselected successor159; reference160 is a separate proposed policy revision. Platform adds RetainedDirectoryPath, an OS mechanism for the name-binding gap in actual Claude124 F1. It is not complete custody or closure of that issue.

open accepts a strictly segmented absolute native POSIX path and a caller-supplied maximum child-component count. It opens process root and each component with O_DIRECTORY/O_NOFOLLOW/O_CLOEXEC/O_NONBLOCK, retaining every descriptor and component name. It rechecks the chain before returning. No directory is created, no untrusted path is canonicalized, and no symlink/dot/empty/reserved-staging component is accepted. Native path bytes reach the OS unchanged. This APFS host refuses invalid UTF8 names with EILSEQ; that refusal propagates, without lossy decoding. The initial test incorrectly expected this filesystem to create such a name; r1 is retained, and r2 tests the actual filesystem result.

recheck reopens process root, then every named edge relative to its retained parent, comparing retained/reopened directory kind, link count and device/inode. Missing edges and changed identity return false; type/permission/other observation errors remain errors. The retained leaf remains available for descriptor-relative reads, even if moved, which is why directory() is not a name-binding assertion. No F_GETPATH buffer or absolute-path reopening of each descendant is used.

The check is a sequence of observations, not atomic or lasting. ABA succeeds after the original directories return; a deterministic test demonstrates that limit. Owner/ACL policy, mount/local-filesystem assumptions and exclusion through the consuming operation are still owed by the caller. The actual witness/floor/SQLite consumers have not yet been wired to this mechanism. Never treat this alone as authority to consume Absent or publish a witnesslessRestore marker.
