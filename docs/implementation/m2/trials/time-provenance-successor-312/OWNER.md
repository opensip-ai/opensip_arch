# Proposed original-core context correction312

This is an unselected successor to the frozen125 private schema. It completes an encoded locator and its conditional joins, not original proof authentication, native publication or runtime selection. Root and actual Grok310 identified the first-clock gap. Grok's separate ADDENDUM withdraws permanent creator pinning and use of index zero as the final evaluating authority.

## Explicit input version and legacy handling

Preserve S4EvaluationInputV1 exactly. Add S4EvaluationInputV2 with inputSchema2, unchanged kind `s4-evaluation`, the existing eight members, and REQUIRED `authority: NodeRef`. Both are closed records. The internal S4EvaluationInput union discriminates the versions. TimeInputV1 and TimeEvidenceV1 include that union; S4 clock-event evaluation/new-proof edges target it. S4.5, challenge and restriction formats do not change. The successor schema has127 definitions rather than125; the exact dependency inventory has136 reference sites rather than134. Two clock-event target mappings change and the two V2-owned reference sites are added. Old definitions other than the two enclosing unions remain structurally identical.

New producers emit V2. A reader can still decode V1, but decoding does not establish sufficient original provenance. Legacy P2 can derive its original authority reference from its exact BEFORE head, subject to all existing historical admission obligations. Legacy P0/P1 lacks the core locator and is unavailable to dependent proof admission. Do not infer it from the creator, later selected core, payload root or a scan of unreferenced records. Do not re-encode a historical V1 into V2 and pretend its newly added reference was part of the original proof. No installation migration is selected here: all these formats are unselected candidates.

## Authority context is upstream of the evaluation

The field locates the ORIGINAL context used in this evaluation, not the AFTER head that may later cite it.

* P0/P1: authority targets CoreAnchorNodeV1, the existing `kind:anchor` branch of RootAdmissionNodeV1. This locates the evaluating core's index-zero authentication anchor AND its retained core inventory/bootstrap-manifest bytes. It is NOT a claim that index zero is the final root authorized to sign a recovery. Admit the COMPLETE embedded chain specified by that original bootstrap manifest, in order and time-free; use its FINAL head under229 G1. Missing later roots, missing envelopes, gaps, invalid old/new quorums and shorter prefixes refuse. The final embedded head is not accepted store/role standing.
* P2: authority must equal beforeImage.heads.root.admission in both hash and length. Its document/binding and rootVersion must agree with the before-head and clock record. Admission still requires the original ancestry, body/envelope semantics and proven accepted standing; literal equality does not provide them.

All phases bind beforeImage to its exact raw canonical bytes; store and the entire beforeClock must equal that image. P0/P1 have null heads/history; P2 has non-null heads/history. The current conditional helper checks these literal joins only. It does not establish capsule publication, role context, root/body authentication, clock floor provenance or native custody.

The pre-acceptance anchor belongs to the core actually relied on for THAT evaluation. There is no new rule pinning every evaluation to CreationInput.deliveringCore forever. First-use and current evaluation require the existing independently admitted installation/launch TCB and selected context. A CoreAnchor's own fields cannot prove that its writer executed those bytes. Historical replay uses the retained original evaluating context, never the replaying/current core. This correction neither introduces nor authorizes any new same-store core transition; existing transition ownership decides whether a proposed transition is lawful.

## Complete embedded-root bytes without a forward reference

CoreAnchor already retains inventory body/envelope, bootstrap manifest body/envelope and index-zero root body/envelope. Keep those exact six blobs. The retained bootstrap manifest declares the complete embedded root list and envelope inventory; its bound core-inventory tree supplies every declared member's length. Resolve later root bodies and envelopes from THESE committed addresses, not the current S4 source.closure and not a store-wide scan.

This proposal makes the retention obligation explicit: retain every body in that embedded rootChain AND EVERY listed embedded envelope candidate before a first/advancing-L proof is published. Read all listed envelopes in bounded UTF-8 path order and apply existing exact subject/domain/body-preimage pairing. Each selected root must have exactly one matching declared envelope. Missing an unrelated-looking candidate is unavailable: without its bytes, uniqueness is not established. Distinct matching candidates refuse. The current source payload's raw metadata closure remains separate and retains its own ordinary/recovery scope. Unused embedded catalog/list bodies, executable and artifact contents are not newly required by this root-chain resolver; when used as time evidence they retain their existing payload-closure obligations.

This clarifies229 C.5's “ordinary edge”: before S4 it is the authenticated old/new signed root-chain relationship over retained raw pairs. It cannot require a RootAdmissionNodeV1 whose mandatory OriginalContext.time points forward to this S4 input. Downstream admission nodes may cite the completed evaluation afterwards. S4 depends on the upstream raw core/closure bytes, never those future nodes. Existing raw PayloadMetadataClosure remains free of admission/time backreferences.

The resolver charges the SAME operation budget as surrounding work:65536 distinct physical objects,131072 edges,256MiB captured bytes,4MiB per object; profiles may only lower limits. It derives lengths before member capture, rechecks exact hashes/lengths, caches immutable bytes within that operation and latches failure. This does not qualify a filesystem capture implementation. The existing metadata-index declared-path checks and ambiguity rule still apply. Lifetime authority ancestry is not limited to the per-payload64 roots.

## Conditional implementation and remaining admission

The reference prototype loads an anchor via the existing shared operation budget, reuses229 byte-binding checks, then resolves the complete root pairs with the inherited metadata index and inventory lengths. It computes the conditional final root binding. Its result is explicitly byte-binding-only: the reused229 fixture signatures are synthetic zeros, and the conditional selector assumes upstream full old/new authentication. No test here counts those signatures as valid.

Actual original authority authentication, retained/incoming revocation context, OLD/R populations, current versus original validity, per-root signatures, proven clock publication, scoped old-T exceptions and accepted standing remain required. A typed TimeEvidence node is not proof that its floor was established. Every write retains311's fresh evaluation distinction; Keep preserves the original T.222 dependency-before-descriptor-before-capsule durability, admission fences/custody/census/capacity and the qualified final age check are unchanged and not implemented by this proposal.

The original full125 reference operation and all native311 modules remain unmodified. This packet introduces a separate successor typed reader and conditional helper; it is NOT full reference-workflow integration. After independent review, update selected reference consumers, regenerate native schemas/visitors, update native input producers and run the relevant cross-boundary tests in a new candidate. Do not install a mixed old/new consumer pipeline.
