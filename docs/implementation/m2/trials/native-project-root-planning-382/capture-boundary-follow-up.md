# Native root capture boundary follow-up

Planning observation, not selected new law or implemented admission. The current retained path mechanism is deliberately a generic/internal primitive, not the final project-root producer.

`RetainedDirectoryPath::open` counts child components through a caller bound, opens and retains the complete chain before a caller can charge `Budget::directory`, and returns sampled identity rather than custody. `Budget::directory` explicitly cannot retroactively bound earlier opens/ACL work. The eventual root producer must account for its actual retained chain and captures through the same operation budget; inventing a new independent per-root budget or using a test's128 component constant does not settle that boundary. Decide and review charging before native work and before allocation, including negative old-carrier observations. Fixed-size metadata need not be mislabeled as immutable document bodies.

The primitive currently rejects backslashes and all STAGING_PREFIX components. In contrast, registry-v2 root syntax represents raw POSIX bytes and excludes only its specified malformed path spellings. A syntactically admissible native root value therefore does not imply this generic helper can open that path. Before wiring project admission, explicitly reconcile these restrictions and exact native name checks; do not silently normalize raw paths, assume a portable repository-path grammar, or claim universal accepted-path support. This is a pending availability/producer boundary, not evidence of unsound admission or a request to weaken internal staging-name isolation.

Original name/descriptor/custody observations must remain retained and rechecked. Reacquiring a pathname or obtaining later equal metadata cannot turn a failed original session into authority. A project filesystem-type membership result from384 is conditional and insufficient to settle this capture/budget boundary or qualify persistent volume identity.
