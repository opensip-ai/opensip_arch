# Trust budget scope415: preserve failure through caught errors and unwind

Fixes two independently reproduced behaviors in existing security trust retained_metadata_index::Budget::scope. Previously an inner scope could fail/latch the budget but an outer callback could catch its error and return Ok, which escaped as success. Also, unwinding bypassed the post-call failed=true assignment, leaving the same budget usable after catch_unwind. Original regressions demonstrate both failures (one positive nested-work control passed, two negative tests failed). No production entry point or first-party creator was enabled.

The new private BudgetScope Drop guard closes the original budget on unsuccessful exit or unwind. Scope accepts Ok only if no nested operation has latched the budget; otherwise it returns existing Error::Closed. Original explicit callback errors retain their error type/value. Successful nested work remains possible; failed=true is not set before the callback, which would block valid nested charges. Counters, limits, caches, handles and all existing algorithms stay in place; no reset, refund, new constructor, error variant or public runtime API is introduced. This is a boundary guard: it cannot observe an error hidden entirely inside a callback without entering a nested budget scope. Qualified adapters remain responsible for routing their actual failures and original-owner obligations correctly.
