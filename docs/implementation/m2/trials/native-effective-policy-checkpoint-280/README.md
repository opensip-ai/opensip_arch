## Derived output bound

Source admission still stops at 4 MiB. The effective document can be larger because it includes source digest fields and may combine inherited and supplied fields from two sources. A fixed internal cap of twice the source cap plus 1024 bytes bounds the concatenated canonical result. Each grant/deny key is unique, each effective scope field originates in one source, denies are a union, and consents are a subset. Thus retained source material cannot grow beyond the two inputs except for fixed structure/digest overhead. There is no relaxation of signed metadata admission.

Rows are encoded separately with the unchanged metadata encoder. A grant has at most 425,984 string characters across its four list fields, plus fixed keys and bounded scalar fields; even six-byte JSON escaping remains below 4 MiB per row. Consent rows have at most 106,496 list characters. Valid grant paths have the stronger 1024 UTF-8 byte semantic limit. No combined row can hit the source encoder cap. The final fixed keys are ASCII and use canonical order.

A real 4,194,303-byte source produces 4,194,409 effective bytes globally and 4,194,471 with a selected inheriting project.
