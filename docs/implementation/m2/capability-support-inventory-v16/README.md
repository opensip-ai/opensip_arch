# Native relation capability and Coverage prerequisites

Add capability_support.rs and capability-support-registry.json in the evaluator crate. These are siblings of body_identity.rs, which owns clone body frames and source dialect identity, and plan_native.rs, which owns Plan requests and selected contexts. Existing capabilities.rs continues to own release capability manifests. Names use the agreed Rust snake_case and closed metadata JSON kebab-case.

The new owner derives fact-time syntax support and Coverage prerequisites from committed grammar rows, source variants and Rust ownership. Inventory capabilities remain exempt from grammar gating; empty or mixed unsupported scopes cannot claim complete coverage. The interface must distinguish local prerequisites from the complete Coverage producer, graph admission and replay obligations. It cannot accept a caller ADMIT or a Plan count as a selected-pair token.

The closed registry is extracted from selected native/foundation sources, with a drift check against the language rows already embedded by the context owner. It is not a plugin registry or request capability vocabulary. No new crate, edge, runtime dependency or reverse identity dependency. Host tests can extend the existing owner tests and fixtures.

All 375 inherited rows and the 20-package DAG remain unchanged. Layout review cannot accept future source bytes. Current live selection is inventory15/runtimev4 (13 inventory and 17 contract successors); body15 is frozen and under separate source review. Project inherited description overrides by stable file path during activation.
