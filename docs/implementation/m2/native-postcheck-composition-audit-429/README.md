# Native reader/postcheck composition429 — unresolved adapter boundary

Existing directory_record_capture::read_one stores read_bounded_operational's result, performs after-read file/directory/name checks even when the read failed, and only then returns the read result. This is the native observation owner finishing its original-owner bracket. It must not be silently replaced with a helper whose error latches the work owner before those required checks execute.

Private reader428 intentionally guards each entire read: an I/O error or budget failure closes the original WorkScope/ReservedPostchecks before returning. This is correct standalone helper behavior, but blindly calling it inside the existing native read_one would leave the latter's mandatory rechecks running after closure (unaccounted) or refuse those checks. Reserved allowance cannot currently be spent after closure; a new ledger is forbidden. Account wrappers likewise remain raw observations, not creator bracket qualification.

Do not wire a borrowed-budget native adapter merely by replacing read_bounded_operational with read_bounded_accounted. The owner must derive and reserve the required bracket's work before starting, keep the original file/name observations, preserve original error precedence and effect visibility, and finalize the original operation only after its required checks. Ordinary I/O results may need to remain provisional data inside that one trusted owner's guarded bracket; that is different from swallowing an already-latched budget failure. Any public/provisional API must prevent callers mistaking pending bytes for admitted evidence and must not expose a resettable ledger.

Budget exhaustion still means failed/unavailable, not permission to do further work. For irreversible effects, the known required follow-up reservation must be sufficient before the effect; operational failure/unknown target visibility cannot license retries. The exact disposition of mandatory error-path rechecks versus already-latched budget failure needs an explicit owner-level analysis before native creator activation. Current raw read result codes/guards do not settle that composition on their own.

This audit is not a finding that source427 or the standalone reader algorithm violates its own narrow contract, and does not amend selected law. It identifies a concrete future native integration boundary to review with actual Claude. Preserve selected existing native brackets while improving helper accounting. No code mutation or new authority is justified by this note.
