## Diagnosis

**The failing assertions.** `apply-advisory-records.successor.v1.py` (captured lines 59–86) loaded `validation-summary.v1.json` from the accepted subject and required its counts to equal the subject's generated reports. In frozen39 these are two different evidence vintages:

| Field | Frozen39 summary (retained bytes) | Frozen39 generated report / bound execution |
|---|---|---|
| foundation.checksPassed / sourcePinsVerified | 2000 / 1224 (`foundation/validation-report.json`) | 2002 / 1247 (`final-reference.v39/foundation.json`) |
| native.casesPassed | 375 | 380 (`native-evidence-report.v2.json` is byte-identical to `native-report.json`) |
| workflows.checksPassed | 1803 (report `workflows-validation-report.json`) | 1816 (`workflows-report.v1.json` is byte-identical to `workflow-surface-report.json`) |
| evaluator3 suites / pins | 16 / 1228 (`final-reference.v25`) | 17 / 1251 |
| identity, security, sweeps, integration, matrix, qualified | 1596, 464, 11, 412, 66, 0 | the same |

The summary is a v25-vintage record (it names `identity-check-counts.v25.json` and `final-reference.v25`), retained byte-for-byte in source39. The native, workflows, integration and identity generated reports were regenerated by the source39 execution.

The original assertions, each evaluated over the same verbatim loads on actual frozen39:
- lines 79, 80, 81, 85 and 86 hold;
- **line 82** (`native.casesPassed` 375 ≠ 380) and **line 83** (`workflows.checksPassed` 1803 ≠ 1816) fail;
- the first failure raised is line 82, exactly as root observed.

The before-image `current_reference_summary` passes on the same inputs (2002 / 380 / 1816 / 17).

**The real boundary is wider than the first assertion.** Inspecting every later use of the loaded variables and records found:
1. **Carried workflow counts.** `current_reference_summary` copied `workflows.commands` and `workflows.goldens` from the historical summary (45/43). These equal the checker's v1 inventory only by coincidence and were never measured.
2. **No report custody.** Nothing bound the executed report copies to the frozen generated reports, the workflow surface report to its parent run (`workflows.json`), or the derived `report.json` to the original runner receipt. A consistent forgery of an executed report copy was accepted, and its count was presented as current: native 999, workflows 1817, integration 413, security 463 (controls below).
3. **Matrix pin and qualification.** The helper did not check the matrix pin, or the matrix's own `platformQualified`.
4. **Snapshot-report counts presented as current.** The apply script overwrote `current.native.matrixCells`/`qualifiedCells` from the snapshot report, and wrote the README native and workflow counts from snapshot reports rather than from the receipt-bound summary.
5. **Historical foundation count under a current name.** `assemble-records.successor.v1.py` records `referenceEvidenceSummary.foundationPassingCalls` from the frozen summary (2000). The apply script later repointed `validationSummary` to the current summary but left that count, so a historical value sat under a current-looking field.
6. **Security and foundation reports are not executed copies.** The frozen `security-lifecycle-report.v1.json` differs from the executed `security.json` only in `schemasValidated` (V1 versus V2 schema names), with the same counts. The frozen `foundation/validation-report.json` is historical (1224 pins).

## Correction

**`current_reference_summary.py`** (current guards added; historical meaning untouched):
- **Runner receipt:** `report.json.originalRunnerReceiptSha256` must equal `runner-original-reference-checks.json`, whose `passed` is true and whose commands equal the bound receipt's.
- **Workflow parent run:** `workflows.json` must be passed, pins valid and exit 0; its `check.reportSha256` must equal `workflow-surface-report.json`; and its stdout counts must equal the report.
- **Executed report integrity:**
  - native: failed 0 and passed = total;
  - workflow and integration: `failed` empty, and integration's `len(checks)` = passed;
  - security: passed true, fail 0, pass = total, and every sweep holds.
- **Matrix:** pinned by the subject manifest, cells = native report cells, `qualifiedCells` 0, and `platformQualified` false.
- **Generated-report custody** (`currentExecutedReference.generatedReportCustody`):
  - For native, workflows, integration and identity (the groups whose frozen report is presented as current), the frozen report must be the byte-identical executed copy.
  - For security and foundation, the relation is measured and recorded (`frozen-generated-report-differs; not current execution evidence`); no current claim is made from them.
- **Workflow inventory:** `workflows.commands`/`goldens` are measured from the pinned `workflows/command-inventory.v1.json`, which `check_workflows.v1.py` validates, and the inventory is referenced in the record.
- **New pure `accepted_summary_boundary(root, subject, snapshot_root, command_ref, count_ref)`:**
  - The accepted summary is checked only as itself: pinned bytes, `foundation.checksPassed = sum(components)`, and the already-corrected v13 matrix equality (summary = matrix = generated report).
  - It is never equated with current counts. Current counts come only from the receipts.
  - The frozen security report must agree in counts (verify-applied later compares these counts).
  - Returned count sources carry explicit roles, and both vintages' counts are returned side by side.

**`apply-advisory-records.successor.v1.py`:**
- Lines 59–86 are replaced by the boundary call. The old `accepted()` helper and the historical-versus-current equalities are removed.
- The historical v13 guard block is **byte-identical** (verified as a segment).
- `current = boundary['current']`, with an assertion that current matrix cells equal the measured cells and qualified cells are 0 (no overwrite from the snapshot report).
- `acceptedOriginalSummary` gains `meaning` and `recordedCountsVersusCurrent`. The historical summary bytes and path are unchanged.
- `referenceEvidenceSummary`:
  - a new guard checks that `foundationPassingCalls` equals the pinned frozen summary's value;
  - that value is kept as `acceptedFrozenFoundationPassingCalls`;
  - `foundationPassingCalls` becomes the receipt-bound current count.
- README counts come from the receipt-bound summary.
- The support corrections record adds `acceptedSummaryCountsVersusCurrent`.
- `countSources` keeps its rows (verify-applied still re-checks each), now with roles.

  - workflows 1816 / 45 commands / 43 goldens;

- **Recorded historical differences:**

## Limitations

- **Segment controls, not the whole script.** The controls execute extracted verbatim segments and the pure helpers. The application field values are those assembly would write for v39, supplied directly rather than read from an assembled record.
- **Constructed snapshot worlds.** Snapshot-mutation worlds re-derive the manifest, subject sha and receipt subject binding in runtime copies to reach deeper guards; they are not real subjects.
- **Required-copy design choice.** Native, workflows, integration and identity must be byte-identical executed copies. A future subject that retains a stale generated report in these groups will be refused until it is regenerated or explicitly rescoped. Security and foundation reports are only related and recorded, and security counts must still agree.
- **Custody basis for the native report.** The native checker has no `--report` argument. Its custody rests on byte identity with the pinned frozen39 report plus the derived `report.json` standing ("copied exactly from executed outputs"). The workflow copy is additionally bound by its parent run's `reportSha256`.
- **Inventory choice.** `workflows.commands`/`goldens` are measured from the v1 inventory that the 1816-check workflow checker validates. The v3 inventory (45 commands / 45 goldens) is not what this summary reports.
- **Assembly record not edited.** `assemble-records.successor.v1.py` still writes the frozen-summary foundation count as `foundationPassingCalls`. The apply script now relabels it, with a guard. Root may prefer to fix that name at assembly instead; the application reviewer should confirm the field semantics.
- **verify-applied compares counts, not bytes.** It still compares current counts with the applied tree's reports by count (the frozen security report is not an executed copy). Byte custody is enforced through its rebound helper call.
- **Identity counts.** 1596 passing calls, 1584 distinct ids and 12 extra instances are call counts, not coverage.
- **Not updated:** pins, planning, packages, grades and source acceptance. No readiness or acceptance is claimed.
