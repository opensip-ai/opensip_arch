# Reserved-path detector listing — closed join

**Standing.** Actual Grok security owner. Isolated `evaluator-successor.v1`. v11 pin verified in-tree `1c0b8868…`. W/core/schema unread-only. Not independent acceptance.

**Verdict.** The reserved-path plan is **consistent** with existing tree mapping. A receipt without a tree path was not an association owner. This is.

**Reserved path (exact).** `.opensip/detector-compatibility.json`

Not a `.` / `..` segment. Identity `LogicalPath` and `ordered()` admit it. v11 `pathRule` admits it (relative, NFC, no `.`/`..`). Selector is this exact string, not a case-fold alias. v11 uniqueness already forbids a case-fold duplicate of the same tree. Project-host `.opensip/project-id.v1` (`resolved-inputs.v2` reservedExclusion) is a different universe (snapshot custody, never component-tree).

## 1. Joining rules (owners, in order)

1. **Envelope + catalog (existing TCB).** Admit the DR-103 component-manifest body. `storedSha256` = identity `closure.manifestDigest`. Catalog `releases[]` may name `manifestDigest` and per-platform `archiveDigest`; those rows do **not** admit a `closure2`.

2. **Delivery tree (DR-103 v11).** Selected `platforms[]` entry for this os/arch. TreeCommitment entries `{path, type: file|dir|symlink, mode, length?, sha256?, target?}`. RJ-3 on path/NFC/case-fold/symlink-escape/entrypoint.

3. **Trust trio.** Admit **this** `closure2` from retained generation, installed signed release with the same `closure2`, or signed `closureBundle`. Protocol and platform are already `closure2` members.

4. **Identity file projection (no schema fork).** From the selected TreeCommitment, identity `closure.tree` is **regular files only**, ordered unique by path (`x-opensip-order: path`, `uniqueItems`, `BLOB_LENGTH`):

   | TreeCommitment | identity `Blob` |
   |---|---|
   | `type=file` | `{path, sha256: entry.sha256, bytes: entry.length}` plus retained `blobs[sha256]` of that exact length |
   | `type=dir` | not a Blob row |
   | `type=symlink` | not a Blob row; never followed; target inside tree (RJ-3) |
   | `mode` | stays on the TreeCommitment row; not an identity member; listing file is never executed (D-012 metadata-only / no-execution-during-admission) |

   Identity §3: “Closure tree hashing includes relative path, byte length and digest for every selected **file**.” Architecture 02 packaging: adapters emit that full-tree commitment plus an immutable archive. Archive recompress changes catalog `archiveDigest` only; identity tree is per-file.

5. **Listing select (this join).** Under already-admitted same `closure2`, look up the unique reserved path.

   | Present row | Result |
   |---|---|
   | no identity Blob and no TreeCommitment entry at the exact path | **no declaration** |
   | TreeCommitment `type` ≠ `file` (symlink or dir) | **refuse**, no downgrade |
   | file row whose Blob/sha256/bytes disagree with TreeCommitment sha256/length, or retained length disagrees | **refuse** (`BLOB_LENGTH` / delivery mismatch) |
   | file row, bytes parse as DetectorManifestV1 (`$id` `urn:opensip:product-v1:workflows:evaluator3:detector-manifest:1`), empty `compatibleClosures` | **complete declaration** (no peers) |
   | file row, valid body, non-empty listing | **complete declaration** of those `closure2` ids at `semanticsMajor` |
   | file row, unparseable / wrong family / extra properties / order fail | **refuse**, no downgrade to no-declaration |

6. **Never.** Catalog `manifestDigest` match as closure admission. Listing bytes as `closure.manifestDigest`. Second envelope domain. `signatureVerified`. Second listing `$id`. Following a symlink onto the reserved path.

## 2. Generated / repacked trees

Language build adapters (architecture 02; DR-G15 later qualification) must emit the **same** OpenSIP tree contract. The listing is one optional regular file in that contract.

- **Omit at pack:** path absent → no declaration. Lawful.
- **Generate at pack:** include the file in the signed TreeCommitment **before** the envelope. Generated bytes are ordinary `type=file` measurements.
- **Inject after signing:** TreeCommitment sha256/length will not match extracted bytes → refuse. Not a silent listing.
- **Recompress archive:** catalog `archiveDigest` may change; per-file identity tree does not. Listing still selected from the file row, not the archive digest.
- **Codesign rewrite of Mach-O** (`security-completion.v1` §3.2): inventory/TreeCommitment are over **final** executable bytes. Listing JSON is not a Mach-O; codesign does not rewrite it. Do not treat OS signature as the listing association.
- **Multi-platform:** each `platforms[]` tree is its own `closure2` (`platform` is in the hash). Each tree independently may omit or include the reserved file.

## 3. Closed receipt

Projected **after** steps 1–5. Not identity. Not a signature.

```
DetectorCompatibilityReceiptV1 = {
  closureId,            // admitted closure2
  manifestDigest,       // component-manifest raw-artifact; NOT the listing
  admissionOrigin,      // retained-generation | installed-signed-release | signed-closure-bundle
  listing:              // discriminated
    { "state": "absent" }
    | { "state": "declared",
        "path": ".opensip/detector-compatibility.json",
        "digest": "<64-hex Blob.sha256>",
        "bytes": <Blob.bytes> }
}
```

- `state=absent` → comparison must not take `declared-compatible`.
- `state=declared` → parse retained `blobs[digest]` of length `bytes` with the **existing** W DetectorManifestV1 schema; `compatibleClosures` is that body. Empty array is complete.
- Malformed present file **does not produce** this receipt (refuse before projection).
- No `tree`/`platform`/`protocolMajor` on the receipt: they are already `closure2`.
- No `compatibleClosures` copy required on the receipt if W parses from `blobs[listing.digest]` under `state=declared`; either is one body, not a second schema.
- No `signatureVerified`.
