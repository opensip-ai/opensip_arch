189: ## 2. Separate report custody, semantic correctness and qualification
190: 
191: The release gate has an authenticated invocation context before reading a
192: candidate report: exact host, provider/data closure, harness, matrix, corpus,
193: runner public key, runner identity, environment observation and platform profile.
194: The fresh qualificationRequestId (host RequestId grammar) also binds the
195: measurement campaign; an older report cannot satisfy a different campaign.
196: These come from the selected signed release closure and independently admitted
197: runner inventory. A report cannot supply or alter its own expected subject,
198: expected answers, trusted runner or performance baseline.
199: 
200: The producer signs the exact report bytes through the qualification signature
201: frame: ASCII `opensip.qualification.report.2`, NUL, raw 32-byte host digest,
202: provider-closure digest, harness digest, and SHA256(report bytes), concatenated
203: in that order. Ed25519 keys are provisioned by the authenticated gate outside
204: the report. The gate verifies signature before parsing bounded report bytes.
205: The report's embedded schemaMajor is covered by the signature. Reusing this
206: signature frame for report schema 3 does not make schema 2 bytes schema 3.
207: 
208: Authentication proves who supplied the observation; it does not prove the
209: machine executed correctly. The trusted first-party measurement harness,
210: runner observation path and gate are explicit TCB components. The harness must
211: execute the selected closure by verified handle, observe exit/EOF and normalized
212: actual results, and bind the exact measured environment. Product qualification
213: requires retained real measurements from every required lane; synthetic reports
214: are tagged reference-only and cannot be promoted. A producer cannot attest its
215: own unsupported hardware into the allowlist.
216: 
217: The original G13 schema/validator remain frozen historical evidence. The new
218: `g13-result-schema.v5.json` and `g13-validator.v5.py` close the reproduced defects
219: for the historical 24-cell shape: independently pinned corpus oracles determine
220: expected atoms and counters, all subject digests join to trusted context, and
221: actual observations plus signature are required. Consistently relabeling every
222: candidate subject digest or zeroing both expected and actual counts now fails.
223: This adapter does not qualify the added JavaScript/Rust cells.
