225: ## 3. Full-product matrix and report schema
226: 
227: The current native matrix is
228: `native/native-capability-matrix.v2.json`. Expand each declared capability/mode
229: cell over its four platform families and each selected signed platform profile
230: from the security contract. A release inventory explicitly selects the
231: advertised supported cells; unsupported typed cells also receive refusal
232: conformance cases. No cell disappears because no runner happened to produce a
233: report. Syntax-only capability is further parameterized by the exact grammar
234: inventory; one grammar's result does not qualify another grammar.
235: 
236: The full-product report schema is
237: `foundation/product-quality-report.schema.v3.json`; its gate reference is
238: `foundation/product-quality-validator.py`. A report covers exactly one trusted
239: runner/profile/environment and the required cell set for that lane. CellId is
240: `capability/mode/platform/profile/fixture`; each coordinate comes from the
241: reviewed matrix and corpus expansion, not from report labels. Every required
242: fixture names exact source/input bytes, selected capability/rung, expected
243: normalized observations, expected exit and independently chosen work/stress
244: bounds. Native reference scenarios supply semantic obligations; executable
245: native fixtures and their results must be admitted at implementation
246: qualification before a cell becomes QUALIFIED.
247: 
248: Qualification required cells are `capability/mode/platform/profile/fixture`
249: measurements of a trusted runner lane. They are not the evaluator's Plan-bound
250: required analysis cells. Completing a G13 or matrix lane does not mint a Run,
251: does not commit EnumerationPlanV1 or EvaluatorEmissionPlanV1, and does not
252: discharge execution-inputs required-cell accounting. Candidate locators and
253: syntax projections used as corpus answers remain candidate-only; they are not
254: native fact authority.
255: 
256: The gate's expectedCells is constructed from the verified matrix/corpus and
257: release selection by the first-party gate. It cannot be supplied as a CLI JSON
258: argument, copied out of report fields or recomputed from candidate answers.
259: Expected observation atoms have closed fields `kind`, `subject`, `value` (all
260: strings); `value` is the schema-defined normalized scalar or canonical JSON
261: text for structured payloads. The admitted fixture's normalizer and schema
262: are part of its pinned harness closure. Report atoms sort by canonical bytes,
263: are unique, and must equal the independent oracle exactly. Counts and
264: correctness are calculated by the gate; they are absent from the submitted
265: schema. Duplicate cells/observations, wrong cell sets, wrong exit or substituted
266: answers cannot be hidden by a reported PASS flag because no such flag is read.
267: 
268: Each benchmark records 3 warmups followed by 7 measured runs in that order,
269: with positive integer elapsed nanoseconds and peak RSS bytes. The gate calculates median
270: elapsed time and maximum RSS. For an existing baseline the limits are 1.20×
271: median time and 1.25× peak RSS, using checked wide-integer cross multiplication (never wrapping), plus the
272: fixture's independently reviewed absolute bounds. A new supported cell needs
273: an explicitly reviewed initial baseline and absolute budget; absence is not a
274: zero or automatic pass. The two baseline measurements must be both present
275: or both null. A null pair admits an initial-measurement report but never qualifies
276: a release-selected cell; reviewed initial baseline promotion is a separate gate act. Baseline host/provider/harness, fixture, environment and
277: platform profile must be compatible by the release gate's signed inventory;
278: changing the measuring subject cannot silently reuse an unrelated baseline.
279: Cold-start and retained-evidence workloads are separate fixtures, so warmup
280: cannot conceal startup or storage regressions. The old reference adapter
281: retains its historical hardware/performance baseline semantics unchanged.
282: 
283: A well-formed authenticated report may report a failing observation. Report
284: admission and release qualification are separate: admission verifies custody,
285: shape and joins; qualification requires every selected cell's correctness and
286: performance to pass on every required profile lane. Missing, unavailable or
287: failed lanes block promotion. The release gate also requires lifecycle,
288: security, output parity and recovery gates; G13 alone never authorizes release.
