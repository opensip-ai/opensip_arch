## Actual problems / tensions

1. **Cannot launch from this template as-is.** Placeholders are empty of successor freeze hashes by design. Filling them from mutable source would be a process error.
2. **Detector-compat listing wording.** Original called the listing optional and required that, if used, it is a reserved authenticated file rather than the component manifest body. The template makes reconstructing that **distinction** accept-blocking (`R-DETECTOR-COMPAT-FILE`) so it cannot vanish into a limitations list. That is slightly stronger than “optional artifact,” and is the only classification tension. It is not host implementation. Root may later mark the listing **artifact** optional while keeping the distinction mandatory; the current choice keeps the original sentence observable.
3. **Historical graph-query schemas vs successor.** Risk is a future consumer treating v10 filenames as a recipe. The charter forbids that. Not a present design gap.
4. **Root admission vs “do not import author implementation.”** These are different actors. Consumer implements from the kit and exports frames. Root admits those bytes afterward. The consumer charter never names an author model as an input.

No original reconstruction unit was found dropped. No extra host/product implementation was added.
