## Why this account exists

A prior independent origin returned `ACCEPT-RECONSTRUCTABLE` while required reconstruction remained unexecuted and while published cross-record laws were omitted from its own validator/joins. The original charter already forbade that (`Do not return an accepting verdict while required reconstruction remains unexecuted or its complete positive controls fail`). The successor charter does not add semantic recipes. It makes every original item **observable**, **classified**, and **stop-conditioned**, and it records that asserted complete positives are independently root-admitted from exact exported frames afterward.

That last clause is process observability of the original “independently implement retained closure” discipline. It is not a new design gate and not a licence for the consumer to import author models.

## Classification rule used

| Original verb | Kind assigned | Upgrade to complete Run? |
|---|---|---|
| complete Run / complete Run descriptor graphs / complete syntax-only Runs / complete file-fact Run | `completeRun` | n/a (already a Run) |
| Include / with / also attached to those graphs | `completeRunProperty` | no (must appear on the Run) |
| construct / exercise / derive / reconstruct / work through without “complete Run” | vector or envelope | **no** |
| public response / failure envelope / termination / pinned-purge refusal | `schemaEnvelope` | no |
| semantic proof replay after admission | `evaluatorReplay` | no |
| real OS/compiler/crypto/SQLite; synthetic TCB as proof; future auth/host | `futureQualification` | must not be demanded |
| focused-query successor not yet owned | `pendingSuccessorOwner` | not a current demand |

This is not a weakening: unexecuted vectors still forbid ACCEPT. It is also not an expansion: synthesized/custom/JS config and JS clone-body stay vectors because the original said “exercise”/“construct”, not “complete Run graphs” for each.
